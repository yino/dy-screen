### 1.1 一句话定位（背下来，每场都用同一句）

>
> 不是卖一个 AI 工具，而是交付**产能**。

| 客户真实困境 | 对应项目 | 交付结果 |

## 2. 行业判断：为什么是现在

> **演讲提示**：这一章每场讲 3–5 分钟，作用是建立"势"。不要讲太长，客户关心的是自己的问题。
> **注意**：以下为行业判断与逻辑推演，`[待填]` 处如需引用具体市场规模数据，请使用你核实过的权威来源，**不要凭印象报数字**。

### 2.1 三个正在同时发生的变化

**变化一：内容的生产成本结构被改写了。**

过去一部竖屏漫剧/短剧的成本大头是：写手、画师、分镜、配音、剪辑、合成。现在其中大部分环节可以被模型承担，但——**模型不能自动变成流水线**。

这正是机会所在：谁把"模型 → 可验收成片"的工程链路做扎实，谁就拿走这部分价值。漫剧平台做的就是这件事（结构化分镜 + 项目圣经 + 8 道质量门禁 + 版本可回溯），而不是"接一个大模型 API"。

**变化二：流量分配从"作品"转向"素材"。**

同一条直播/长视频，切成 20 条的曝光总和，通常远大于原片。切片不是内容创作的补充动作，而是**分发的主力动作**。但人工切片是体力活，成本随时间线性增长，无法规模化。

切片智能体把这件事变成软件动作：自动录 → 自动转写 → 自动找精彩 → 自动成片。

**变化三：获客从"广告投放"转向"人设矩阵"。**

口播是低成本建立信任的形态，但需要稳定的人设、稳定的产量、稳定的选题。这是口播项目的立足点。

### 2.2 我们判断的三个"不可逆"

1. **模型会持续变便宜、变多** → 所以架构上必须**模型无关**（漫剧平台的 Provider Adapter 架构就是为这个准备的）。
2. **平台风控会持续变严** → 所以**合规能力本身是竞争力**，不是成本（切片智能体主动放弃验证码绕过、Cookie 导出、代理池，走公开页面 + 本地优先）。
3. **人工验收节点在相当长时间内不可取消** → 所以产品设计必须**把 AI 放在"提议"位置、把"决定权"留给用户**（两个项目都坚持"不自动导出、不自动发布"）。

> **这一章的金句**（讲完停顿）：
> "这三条如果成立，那未来赚钱的不是模型公司，是**把模型变成产能的公司**。我们就是干这个的。"

## 3. 项目一：漫剧平台（LumenX，AIGC）

### 3.1 一句话定位

> **一个围绕"项目—剧集—分段—镜头—素材—生成版本—时间线—成片"的 AI 漫剧一体化生产系统。**
>
> 不是三个彼此孤立的工具页，而是一条把剧本推到成片的流水线。

### 3.2 客户痛点（**请让客户自己点头**）

> **演讲提示**：这四条一条一条问，客户点头再讲下一条。

| # | 痛点 | 客户的真实原话往往是 |
| --- | --- | --- |
| 1 | **画风和人设不稳定** | "上一集和这一集不像一个人。" |
| 2 | **返工是连锁的** | "一段废了，整集重做。" |
| 3 | **素材和提示词散落各处** | "上次那个提示词、那张母图，找不到了。" |
| 4 | **模型换一次，工作流崩一次** | "换了个模型，前面的模板全废。" |
| 5 | **成本和进度看不见** | "花了多少积分、哪一步慢，说不清。" |

### 3.3 解决方案：把"流程"变成"数据"

产品设计的七条核心原则（这七条就是差异化，请务必讲到）：

1. **剧情数据结构化** — 剧本、证据链、人物状态、镜头、台词、提示词、字幕不是散落文本，而是**可版本化、可校验、可回溯的数据对象**。
2. **人物与世界观资产化** — 脸、服装、伤势、道具、场景、光线、时间形成"**项目圣经**"与**连续状态表**，后续每集继承，不重复手工说明。
3. **模型接入适配器化** — 各模型统一走 **Provider Adapter**，前端与业务层不依赖任何一家接口字段。
4. **生成任务异步化** — 图片、视频、转码、抽帧、字幕、代理、导出全部进入**可观测任务队列**，支持重试、取消、超时、费用统计、失败段重做。
5. **剪辑非破坏化** — 时间线只保存引用、入出点、转场与效果参数，**不覆盖原素材**；任何生成版本可切换、对比、回滚。
6. **QA 前置且自动化** — 在花大钱调视频模型**之前**先做剧本、连续性、提示词、尺寸、时码、预算预检。
7. **先打通闭环，再扩展高级功能** — 第一版先实现"一集从剧情到可导出 MP4"的完整闭环。

#### D. Spec-Driven 短剧 Agent 工作流 🟡（灰度中）

已实现的 Agent 图（LangGraph），九个节点：

```
intake → storyboard_plan → continuity_check → asset_binding
       → prompt_compile → quality_gate → human_approval
       → submit_task → monitor_task
```

| 语义 | 价值 |
| --- | --- |
| `continuity_check` | 连续性检查：防止人设、服装、道具漂移 |
| `prompt_compile` | 提示词编译：把结构化分镜编译成可提交的模型提示 |
| `quality_gate` | 质量门禁：不达标不进昂贵的视频生成 |
| `human_approval` | 人工审批：**AI 提议，人决定** |
| `monitor_task` | 任务监控：同一 run/shot 幂等键可安全重试，不重复计费 |

**发布策略（这句话本身是信任状，值得讲）**：先以 `shadow_mode` 只做编译与质检、不创建计费任务；验证通过后灰度放开，**旧入口保留为回退**，能力由 feature flag 控制，可一键回滚。

> **对渠道讲**：这说明我们的 Agent 不是 demo，是**带灰度和回滚的生产系统**。

#### E. 交付形态

Web 平台（React + TypeScript）+ Go API + Go 异步 Worker + PostgreSQL + Redis/Asynq + S3 兼容对象存储 + FFmpeg 媒体处理，Docker 部署，API 与 Worker 分进程可独立扩容；同时提供 **macOS / Windows 桌面安装包**（`make build-mac` / `make build-windows`）。

### 3.5 真实生产流程（**演讲时可以照着屏幕指**）

```
创建项目
 → 导入故事 / 剧本
 → 建立项目圣经
 → AI 剧情推理与人工确认
 → 分集与四段规划
 → 分镜与逐秒提示
 → 生成 / 选择母图
 → 段级视频生成
 → 段级审核与尾帧接力
 → 时间线拼接
 → 配音 / 字幕 / 音效
 → QA 门禁
 → 服务端导出
 → 归档制作包
```

**创建项目向导的三层分流**（体现"懂创作"）：

1. **生产模式**：整剧规划 / 逐集推进
2. **输入成熟度**：故事想法 / 小说 / 故事稿 / 剧本 / 镜头稿 / 原样保留
3. **输出规格**：画幅、单集时长、集数、视觉风格、默认模型、预算

按输入成熟度**跳过不需要的阶段**：镜头稿直接进资产识别与分镜校验；原版剧本只做格式化与风险检查，**不进行未经授权的剧情改写**，并在开始前给出"处理策略预览"——明确 AI 将改写什么、保留什么。

> **这句话是打动专业创作者的关键**，请一定讲：**"我们不会偷偷改你的剧本。"**

### 3.6 八道质量门禁（Gate 0–8）

| Gate | 名称 | 卡什么 |
| --- | --- | --- |
| Gate 0 | 项目立项 | 规格、预算、模式 |
| Gate 1 | 剧情确认 | 剧情推理结果必须人工确认 |
| Gate 2 | 连续状态确认 | 人物 / 场景状态表一致性 |
| Gate 3 | 分镜锁定 | 分镜结构与逐秒提示 |
| Gate 4 | 母图锁定 | 视觉基准 |
| Gate 5 | 生成前检查 | 提示词、尺寸、时码、预算预检 |
| Gate 6 | 段级视频审核 | 单段产出验收 |
| Gate 7 | 时间线审核 | 拼接、接缝、字幕、音轨 |
| Gate 8 | 导出验收 | 导出与冻结快照一致 |

> **对客户讲**：**"我们在最贵的那一步之前设卡。"** 视频生成是成本大头，Gate 5 就是省钱的那道闸。

### 3.7 QA 规则：可信度证据（**这页最能建立专业信任**）

#### 确定性规则（可自动判定）✅

- 每集 4 个分段；每段目标时长 **15.000 秒**；第一段 0–1.5 秒为标题卡
- 分段提示覆盖 15 个一秒区间；单提示长度低于目标模型上限（历史模板默认 2500 字）
- 分段 SRT ≤ 15 秒，整集 SRT ≤ 60 秒
- PNG 必须 **1280×720**
- `identity_only` 资产**不得**出现在导出时间线
- 接缝检查窗口固定覆盖 14.8–15.2 / 29.8–30.2 / 44.8–45.2 秒
- 57.5–60 秒必须存在具体钩子；标题、定格、转场全部计入总时长
- 通用：媒体可解码无零字节；实际时长 / 分辨率 / 帧率 / 声道；黑帧、重复帧、长静音、削波；字幕重叠 / 倒序 / 超界 / 过长 / 安全区；缺失引用与孤儿素材；时间线片段冲突；导出与冻结快照一致

#### AI 辅助规则（给风险分，不替代人）✅

人物身份相似度异常；年龄 / 发型 / 服装 / 伤势漂移；手指、兵器、绳索、车辆结构异常；现代元素、公众人物相似风险、Logo 水印与乱码；镜头是否提前发生禁止内容；人数与关键道具数量是否明显不符；开头钩子和结尾钩子是否清楚。

> **我们对客户的承诺**：**AI 只给风险分和证据帧，不自动替代人工审片。**

#### 标准问题标签（15 个，可统计、可优化）

`FACE_DRIFT` `COSTUME_DRIFT` `EXTRA_PERSON` `HAND_ERROR` `WEAPON_DEFORM` `TEXT_GARBLED` `WATERMARK` `MOTION_OVERLOAD` `AXIS_JUMP` `LIGHT_MISMATCH` `BAD_END_FRAME` `AUDIO_CLIP` `SUBTITLE_OVERFLOW` `PLOT_LEAK` `COUNT_MISMATCH`

> **为什么这页值钱**：客户最怕"AI 出来的东西不可控"。这一页说明我们把"不可控"拆成了**15 个可统计的缺陷类型**。可统计 = 可改进 = 可验收。

### 3.8 项目模板：《一卒定山河》七条已验证创作约束 ✅

## 4. 项目二：切片智能体（dy-screen）

### 4.1 一句话定位

> **一个装在电脑上的切片工厂：自动监听主播开播并录制，本地转写，自动找出精彩，自动生成可审阅的成片草稿。**
>
> 本地优先、隐私可控、不依赖上传原始素材。

### 4.2 客户痛点

> **演讲提示**：讲这条时先问一句——"您团队里做切片的人，一天能出几条？"

| # | 痛点 |
| --- | --- |
| 1 | 主播什么时候开播不确定，人要守着 |
| 2 | 一场直播几小时，人工看完再挑精彩，纯体力活 |
| 3 | 切片团队人效低、成本随产量线性增长，扩不了规模 |
| 4 | 素材上传到云端有**版权与隐私顾虑** |
| 5 | 剪辑风格不统一，每条都要手工调字幕和转场 |
| 6 | 内容做出来了，但**什么时候能出第一条**说不准 |

### 4.3 解决方案：本地优先的切片流水线

```
多个主播主页 / 直播间入口
        ↓
   自动监听（开播即录）
        ↓
 FFmpeg 直播源直录（-c copy，不转码）→ MKV 分片
        ↓
   用户点击"开始分析"
        ↓
 FFprobe → FFmpeg → Silero VAD → ASR（本地 whisper.cpp 或云端百炼）
        ↓
 稳定句段 ID + 时间戳 + 文本
        ├→ 播放器联动、复制、TXT/JSON 导出
        └→ 用户授权 → 候选发现 Agent → 评分 Agent → 精彩候选
                              ↓
                     单轨剪辑工程（工程级字幕校对）
                              ↓
                     转场素材智能匹配（置信度 ≥ 0.75 才自动应用）
                              ↓
                     导出新的 H.264/AAC MP4
```

### 4.4 核心能力

#### A. 自动监听与录制 ✅

- 输入**公开**抖音个人主页或直播间链接；个人主页未开播时允许先保存，后台持续等待首次开播
- 用 `profile_sec_uid`、稳定 `web_rid`、当前 `room_id` 三层区分"主页身份 / 长期直播入口 / 本次场次"
- 直播间解析**优先原生 HTTP**，命中公开页访问限制后自动回退到全局持久化、串行共享的系统 WebView
- **多个主播共享同一浏览器会话**，浏览器解析期间不阻塞已运行的 FFmpeg 录制
- 检测到开播自动启动 FFmpeg，直播结束自动关闭会话；FFmpeg 退出后重确认房间状态，仍在直播时**同一逻辑会话内最多续录 3 次**
- 为主播持久保存**可调整录制优先级**；额度不足时按优先级选择，未入选者保持"直播中、等待录制资源"并继续监听
- 录制期间**增量监听完成清单**，MKV 分片一旦正确关闭立即登记，不等整场结束
- 关闭主窗口后**驻留系统托盘**，监听与录制继续运行；托盘支持打开窗口 / 暂停全部 / 恢复全部 / 退出

**"直播源直录"不是录屏**（这是一个技术卖点，值得单独讲）：

| 特性 | 说明 |
| --- | --- |
| 不需要浏览器窗口保持可见 | 后台运行 |
| 不会录入鼠标、桌面通知、其他窗口 | 无隐私泄漏 |
| `-c copy` 不转码 | CPU 占用低 |
| 保存直播源本身的视频和声音 | 画质无损 |
| 不含弹幕、礼物动画、网页控件 | 画面干净 |

> 若产品必须保留直播页面 UI 或弹幕，需另做系统级屏幕捕获方案 —— **如实告知，不夸大**。

#### B. 本地 ASR（语音转写）✅

- 流水线：`FFprobe → FFmpeg → Silero VAD → AsrEngine`，本地引擎为 `whisper.cpp small-q5_1`
- **macOS arm64 用 Metal 加速**；macOS Intel 与 Windows x64 用 CPU
- **只有用户点击"开始分析"才运行 ASR** —— 打开页面、应用启动、新录像完成都**不会**自动识别
- ASR **全局单并发**，默认允许已完成视频在录制期间识别、不占用录制并发许可；低配设备可在设置中关闭并行、恢复录制优先
- 相同源版本与识别配置**可跨项目复用**稳定转写产物
- 项目结果：播放器 + 点击句段跳转 + 当前句段高亮 + 跟随播放 + WebView 临时字幕 + 复制 + TXT/JSON 导出
- 弱项如实说明：VAD 用于排除静音、挂机和纯音乐，**不能保证**所有背景音乐场景被正确过滤；中文商品名、主播名、金额仍可能识别错误，可配置热词

#### C. 精彩候选分析 ✅

- ASR 完成后，按用户授权运行**候选发现 Agent** + **评分 Agent**
- 合格 / 优秀阈值默认 **70 / 80**；合格候选按页展示、**不设数量上限**；优秀候选首次分析完成时自动选中
- 使用**版本化 Skills**：通用、带货、搞笑、知识、故事；**未知标签只作为数据，不可改变 Agent 工具边界**（安全设计）
- 候选结果的时间与句段 ID **由 Rust 本地校验**，选择保存只写 SQLite，**不会自动触发 FFmpeg**

#### D. 单轨剪辑 + 工程级字幕校对 ✅

- 已选择精彩可进入单轨剪辑页，在**工程副本**中校对或隐藏字幕，导出带**逐字烧录字幕**的新 MP4
- 剪辑字幕**直接复用已发布的规范化 ASR 句段**，不重复识别；相交句段投影为工程独立副本，修正只影响本工程
- 字幕轨不可拖动调时；支持当前片段或全工程范围搜索、播放位置高亮、长列表独立滚动
- 逐字显示计划按 **Unicode 字素簇**处理中文、组合字符与 emoji；标点跟随相邻文字；**句段前 85% 时长逐字显示，后 15% 保持完整字幕**
- 长句按输出画幅稳定分页，每页最多两行；固定样式为底部居中白色半粗体 + 黑色描边 + 轻微阴影
- **导出期间字幕与片段结构锁定**；每个片段必须至少关联一条非空字幕副本，否则前后端**双重阻止导出**
- 原始录像、ASR 产物、预览缓存**始终只读**，导出只生成新 MP4

#### E. 转场素材智能匹配 ✅

- 授权心跳只发布**版本信号**；独立协调器串行检查、去重、退避。同步失败**不撤销授权**，也不停止监听 / 录制 / ASR / 剪辑
- 视频与缩略图只在**预览、人工应用或 Agent 高分选中**后按需下载，并校验大小与 SHA-256
- DeepSeek 只在 Rust 召回的本地候选中匹配；**置信度 ≥ 0.75 才自动应用**，低分只显示建议
- 人工应用或"保留无转场"会**锁定边界**，需显式解除后 Agent 才能再改
- 导出前所有已应用素材必须下载完成并通过大小、SHA-256 与媒体检查，否则**阻止导出**
- 桥接素材作为独立时间轴单元完整插入，**保留原声**并增加工程总时长

#### F. 智能成片（旗舰能力）✅

把 ASR、精彩提取、工程字幕纠错、转场素材匹配**编排成一个可恢复任务**：

- 支持 **"本地视频" / "直播回放" / "正在直播"** 三种模式
- 自动推进到**可审阅草稿**，但**不会自动选择输出路径、导出或发布**
- **一次授权只覆盖当前任务或当前直播场次**；来源、Provider、模型或发送范围变化后必须重新确认授权
- 失败阶段**只重试该阶段**；已成功且输入指纹未变化的前置阶段不重复调用 Provider
- **导出始终由用户显式触发**

### 4.5 关键指标：首稿时效 ⬜（产品目标，非实测）

> **定义（很重要，讲清楚才显得专业）**：
> 从**"构成精彩的最后一个来源分片完成登记"**到**"包含该精彩的草稿首次可审阅"**，产品目标 **10 分钟内**。
>
> 10 分钟覆盖"高光 + 基础字幕"组成的基础草稿可审阅；特效字幕与生成式动画等**增强结果异步补齐**，补齐后可再次审阅，**增强未完成不计入首稿超时**。

> **话术**："客户问的从来不是'你有没有 AI'，而是'我几点能拿到第一条'。我们把这个问题变成了一个可测量的指标。"

### 4.6 隐私与合规：**这节是我们的核心卖点，务必单独讲**

#### 数据边界（白纸黑字）✅

- 主播、设置、视频、ASR、精彩结果**全部保存在本机**
- 客户端只向授权运营服务上报**白名单**启动 / 功能 / 错误埋点
- **不向该服务上传**媒体、ASR 文本、本地路径、Cookie 或直播页面正文
- 用户内容出网**只有两条路径**，且都以当前任务或用户的明确授权为前提：
  1. 云端识别：直传 FFmpeg 生成的**标准 WAV** 到百炼
  2. 精彩分析：只发送**规范化文本 + 相对时间**

#### Agent 工具边界（讲给技术决策者）✅

转场 Agent 只能接收：相邻片段末尾 / 开头的**有界 ASR**、主播标签、素材键 / 版本 / 标题 / 描述 / 标签 / 分类。

**不会接收**：媒体、下载 URL、本地路径、Cookie、激活码、设备 ID。**没有网络或文件工具权限**。模型返回的素材键、版本、置信度与理由，**仍由 Rust 对本地目录二次校验**。

#### 合规红线（**主动讲，不要等客户问**）⚠️

- 只处理**普通公开页面**
- **不支持**：验证码自动识别、行为模拟、第三方打码、账号自动登录、Cookie 导出、代理池、DRM、付费或私有直播间绕过
- **不录制**弹幕、礼物动画或网页 UI
- 系统 WebView 仅执行标准页面脚本和用户主动完成的页面交互
- 仅应录制**你有权保存和处理**的内容，需遵守平台规则、版权、隐私与适用法律

> **话术（这是加分项，不是减分项）**：
> "我要先说我们不能做什么。我们不能帮您绕验证码、不能导出 Cookie、不能用代理池——**不做**。因为那些做法会让您的账号和生意有风险。我们走的是公开页面 + 本地优先这条路，慢一点，但您能一直用。"

### 6.2 三次变现，同一份资产

| 一次投入 | 第一次变现 | 第二次变现 | 第三次变现 |

> "单独买一个工具，您买的是**效率**。买这条链路，您买的是**产能**。效率是省 20% 时间，产能是原来做不了的事现在能做了。"

渠道最怕"只有一个产品、卖不动就没收入"。三个项目给了三段式销售路径：

1. **低门槛入口**：Playground 体验 / 切片单人版 → 建立认知
2. **主力产品**：漫剧平台或切片团队版 → 产生主要收入
3. **续费与增值**：口播矩阵 + 代运营 + 定制模板 → 提高客户 LTV
