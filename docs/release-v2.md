## 1. 三层边界

| 层 | 归属 | 本轮定位 |
| --- | --- | --- |
| 层 1 客户端 | Tauri 2.0 桌面端（`src/`、`src-tauri/`、`ui/`） | **本轮实现主体**：直连百炼完成 ASR、LLM、图片与视频生成，本地完成校验、渲染、合成与导出 |
| 层 2 我们的 admin-service | 独立仓库 | **本轮不新增任何接口**：只保留既有激活、心跳与 AI 临时密钥三个接口 |
| 层 3 阿里云百炼 DashScope | 阿里云 | **唯一的 AI 能力来源**：文件转写（ASR）、兼容 OpenAI 的 LLM 调用、万相文生图、万相图生视频 |

客户端现有的服务端 AI 相关接口只有三个，全部保留且不新增：

| 接口 | 作用 |
| --- | --- |
| `POST /api/client/activate` | 激活与设备鉴权 |
| `POST /api/client/heartbeat` | 心跳；提供激活态与额度**状态信号**。注意：实测该响应不含额度字段，未开通与额度耗尽实际由上游业务错误码 3001 / 3003 / 3004 判定 |
| `GET /api/client/ai/llm-ak` | 签发短期 token：`{ak, expireAt, provider}`，`provider=ALI`，`ak` 形如 `st-lt-v1.xxx` |

短期 token 由 Rust 侧只在内存中持有，按 `expireAt` 提前刷新，不写入 SQLite、设置、日志、诊断事件与前端状态。同一个短期 token 用于上述四类百炼调用；接口名沿用既有的 `ai/llm-ak`，不因用途扩大而改名，也不新增接口。

**记账边界**：客户端本地 SQLite 落盘 `requestId` 与输入指纹，重试只做同键复用；不做服务端分项账本，服务端不感知每次调用的实际用量。未开通与额度耗尽由上游业务错误码 3001 / 3003 / 3004 判定；heartbeat 响应不含额度字段。

## 2. 目标与范围

v2 从原视频提取音频，使用百炼 ASR 取得带时间戳的转写，再由客户端 DeepSeek Harness 提取高光并为**每条高光**选择一种增强方式：`effect_caption`（特效字幕）或 `video_animation`（视频动画）。两种方式互斥。客户端使用受限的声明式 HTML/CSS 组合渲染特效字幕，使用 FFmpeg 合成并导出 H.264/AAC MP4。

目标平台为 **macOS arm64、macOS Intel x86_64 与 Windows x64**，三者同等承诺：Harness sidecar、渲染运行时与渲染浏览器、FFmpeg 及运行资源清单都必须按架构随包，发布校验按架构逐项核对。原始视频与音频保存在客户端；只有用户授权的临时音频、转写文本、生成提示词以及生成任务所需数据会发往百炼。

**本轮非目标**：

- 不新增 admin-service 接口，不做服务端 AI 任务代理与分项账本（见已搁置的 `add-cloud-ai-job-backend`）。
- 不做本地 `whisper.cpp` 的云端自动回退；云端不可用即明确失败。
- 不让模型生成脚本、构建配置、依赖清单、任意滤镜或 FFmpeg 命令行参数。
- 不接入百炼之外的上游 AI Provider。
- 不实现登录、验证码、DRM、付费内容或私有直播间访问控制绕过。

第一版的视频动画默认在高光内做**替换并保留原声**：替换的目标源画面范围由生成资产的实际时长反向确定，因此动画覆盖高光的一部分，其余部分保持原画面与原声，工程总时长不变。高光之间的完整桥接动画可以采用 `insert` 模式，作为独立时间线单元增加时长，并归属左侧高光；没有有效右侧片段时不得选择 `insert`。普通渐入渐出由客户端的固定 FFmpeg 效果实现，不消耗图片或视频生成额度。

现有普通 ASR 字幕属于基础字幕，不计入上述二选一。`effect_caption` 命中某句时，该句普通字幕在同一时间范围内隐藏，避免重复显示；`video_animation` 不再生成特效字幕，但可保留普通字幕。

```text
原视频 --客户端 FFmpeg 提取音频--> 临时音频 --客户端直传--> 阿里云百炼
                                                              |
                                                              v
                                                    百炼文件转写任务 (task_id)
                                                              |
                                                              v
                                                 客户端保存统一转写结果
                                                              |
                                                              v
                                           客户端 DeepSeek Harness sidecar
                                                 |                    |
                                       特效字幕组合            动画分镜与提示词
                                                 |                    |

                                        （RGBA 帧序列）        文生图 → 图生视频
                                                 |                    |
                                        透明画面序列          已校验动画资产
                                                 +---------+----------+
                                                           |
                                                 客户端 FFmpeg 合成
                                                           |

```

## 4. 阿里云 ASR（客户端直连）

### 4.1 音频与云端任务

客户端冻结来源视频的路径、文件大小和修改时间，使用现有 FFmpeg 音频准备流程生成 16 kHz、单声道、16-bit PCM WAV。客户端用 `ai/llm-ak` 的短期 token 直连百炼，完成音频上传与异步文件转写任务的提交、轮询与结果下载；不经过我们的服务端，也不申请服务端上传凭证。

百炼的音频提交路径（文件上传接口、`oss://` 资源引用与所需的解析开关，或等价方式）**以 `validate-dashscope-direct-capabilities` 的探针结论为准**；本方案只固定契约：客户端必须在任务执行期间保证音频可被百炼读取，并在任务终止后清理本地临时音频。

上传成功但任务创建失败时，用同一 `requestId` 与同一输入指纹在本地落盘并安全重试；不因客户端超时重复提交付费转写。任务终止、取消或失败后清理本地临时音频。

当前客户端适配器默认模型为 `qwen3-asr-flash-filetrans`。v2 的模型、超时与分块上限由客户端版本化配置决定；接入前用真实中文样本验证其可用性、时长上限和结果格式。

### 4.2 时间、模型身份与失败语义

完整来源音频保留原始时间轴。若超过百炼单任务上限，客户端按有重叠的固定区间分块，每块独立直传并各自提交子任务，并按源音频偏移记录分块序号。客户端取得全部子结果后将块内时间还原为源视频时间，依据文本与时间交叠去重，再为合并后的句段分配稳定 ID。不能删除静音后直接拼接，否则返回时间无法准确定位原视频。

现有处理器在云端尝试前仍要求本地 VAD 运行，默认识别配置及云端结果的引擎身份也沿用本地 Whisper。v2 应分别诊断百炼直连转写、可选本地识别与音频准备能力；使用百炼时，缺少本地 `whisper.cpp` 模型不应阻止云端识别。转写产物保存实际 `provider`、模型、模型版本、分块策略和规范化版本，缓存键包含这些字段；旧产物保持原身份，不通过数据库迁移改写成云端结果。

**本轮不做本地回退**：百炼不可用、超时或返回错误时，云端路径**明确失败并报出可区分原因**，不自动改用本地 `whisper.cpp`，也不把失败伪装成成功。三条保留的显式语义是：

1. 用户取消 → 直接终止，不进入任何本地识别；
2. 授权、未开通、额度耗尽 → 显式报告可区分原因，不描述为云端故障；
3. 网络超时、限流、上游 5xx → 有界重试后按冻结策略失败并保留可重试状态，仍不自动回退本地。

本地 `whisper.cpp` 作为用户**显式选择**的独立识别路径保留，其既有行为不变，但云端路径不得自动降级进入它。云端转写成功但本地临时音频清理失败时，保留成功结果并重试清理，不重新付费转写。返回的句段还需通过既有时间范围、非空文本和排序校验，才能发布到项目。

## 5. 客户端 Harness sidecar

Rust 进程作为任务状态和工程数据的权威来源，启动受控的 DeepSeek Harness sidecar，通过其进程外 JSON-RPC 协议发送冻结 ASR 输入并接收结果。Harness 与渲染运行时使用独立子进程，便于分别限制资源、取消和回收。随应用打包固定版本的运行时、Profile 和 Skill；不依赖用户全局安装或用户目录的 Agent 配置。由于 DeepSeek Harness 当前仍处于开发者预览，升级需固定版本并通过 **macOS arm64、macOS Intel x86_64 与 Windows x64** 的协议和恢复测试。

应用专用 Profile 只注册模型路由、Skill 和明确授权的业务工具。高光分析不需要 shell、任意文件编辑、浏览器浏览或任意网络访问；这些通用工具不得进入生产 Profile。ASR 文本始终视为待分析数据，不能作为 Harness 的系统指令或工具配置。

### 5.1 模型调用的配置与冻结

模型调用只有一种形态：**客户端 Rust 侧持 `ai/llm-ak` 的短期 token 直连百炼**。不存在服务端模型网关、不存在网关短期令牌，也不存在“本机直连 / 经网关”两条路径的解析。

- 模型标识与调用参数在每次心跳周期边界重新解析（来源为构建期默认与本机设置），**配置切换接受最长一个心跳周期（90 秒）生效**。
- 一次运行开始前把生效配置冻结为不可变快照；**进行中的运行不受配置切换影响**。
- **重启后重新解析模型配置**；运行指纹与识别、分析、渲染的缓存键包含实际模型标识、模型版本与相关运行时版本。
- **已发布结果按产出它的运行指纹匹配**：指纹一致才能复用；指纹不一致时保留为历史建议、不自动应用，避免丢弃已付费资产。
- 正式构建不接受手输的 Base URL、代理地址或凭据；短期 token 只来自 `ai/llm-ak`，只在内存中使用，按 `expireAt` 刷新。

### 5.2 职责划分

Harness Skill 分为三个职责：

1. `highlight-and-treatment`：按窗口分析 ASR，提取候选，合并跨窗口重复结果，并为入选高光输出唯一的 `effect_caption` 或 `video_animation`。
2. `effect-caption-composition`：引用工程现有字幕文本、强调词和相对时间，输出受限的单个 HTML/CSS 组合与参数。
3. `animation-storyboard`：输出画面主体、构图、参考图提示词、镜头运动、图生视频提示词和目标时长。

图片和视频生成是受控业务工具：Harness 只能提交结构化请求并获取业务任务 ID，不能持有短期 token，也不能持有任意下载 URL；实际调用由 Rust 侧完成。Rust 侧负责校验时间、互斥类型、调用次数与本地冻结的额度上限。Skill 负责创作，Rust 负责提交与记账。

客户端 Harness 只服务所在设备。未来其他服务若需复用同一能力，可使用相同的 Skill 版本和结果协议部署服务端 runner；v2 不要求为桌面任务常驻服务端 Agent。

## 6. 高光与时间线协议

业务数据统一使用毫秒和半开区间 `[startMs, endMs)`。ASR 时间属于源视频；高光保存真实来源区间；字幕和动画内部时间属于高光；最终工程时间由客户端根据片段顺序、替换或插入方式计算。跨录制分片的高光以多个来源区间表示，不能只返回一个无法定位来源的全局时间戳。

下面是结果结构示例；字段名称是拟定协议，需要在客户端 Rust DTO 中固定版本：

```json
{
  "schemaVersion": 1,
  "runId": "run-123",
  "asrSnapshotHash": "sha256:...",
  "highlights": [
    {
      "highlightId": "h-1",
      "sourceRanges": [
        {
          "inputId": "input-7",
          "segmentIds": ["seg-18", "seg-19"],
          "startMs": 12800,
          "endMs": 19600
        }
      ],
      "score": 91,
      "enhancement": {
        "kind": "effect_caption",
        "captionPlanId": "caption-1"
      }
    }
  ]
}
```

`enhancement` 是互斥结构：字幕分支只包含组合定义与字幕参数引用；动画分支只包含分镜、生成任务及 `replace` 或 `insert` 合成方式。`replace` 还必须带有高光内的目标源时间范围。`insert` 必须带有 `leftClipSegmentId`、`rightClipSegmentId` 与 `boundaryId`；它归属左侧高光，但定位和有效性由这三个稳定边界字段决定。客户端拒绝未知类型、重叠且冲突的主画面范围、虚构句段、越界时间、失效的左右邻接关系，以及与冻结 ASR 哈希不符的响应。

高光分析按有界窗口发送 ASR，并在相邻窗口保留少量重叠上下文。只有最终入选的高光才进入组合或媒体生成。AI 可以建议范围、效果和强调词，但实际可用范围及文字必须由客户端从工程已发布的句段和用户修正文案中取得。人工修改工程后，旧代次生成结果保留审计，不自动覆盖新工程。

## 7. 特效字幕分支

默认优先选字幕：金句、数字、观点、反问，或视觉化收益不明确的内容均走此分支。Harness 生成受限的**纯声明式 HTML/CSS 组合**，引用随包样式与白名单 class。它只能生成单个组合文件，不生成脚本、事件处理器属性或构建配置，不安装依赖，不加载远程字体或媒体，也不接受远程地址或外部 CDN。

客户端使用白名单校验标签、属性、CSS 属性与取值、元素数量与嵌套深度、动画时长与帧数上限以及文本引用，再在限制网络、文件访问、内存与执行时间的进程中渲染。静态校验和进程隔离均不可省略：渲染器本身是真实执行的组件，且组合在用户设备上渲染。字体和渲染浏览器版本锁定，动画随机源固定，确保同一输入能重现预览与正式导出。

### 7.1 信任边界（HyperFrames）

渲染后端保留 **HyperFrames（Apache-2.0）**。信任边界必须按以下事实表述，不得简化为“生成物完全不可执行”：

- **模型侧**：MUST NOT 生成脚本、事件处理器属性、构建配置、依赖清单或任意滤镜与 FFmpeg 参数；生成物只是纯声明式的 HTML/CSS 组合。白名单校验显式拒绝生成物中的 `<script>`、内联脚本、`on*` 属性与任何指向随包资源之外的外部引用。
- **渲染器侧**：被渲染的页面中**确实存在可执行内容**——HyperFrames 自带的、随包钉版本的引擎脚本会随页面注入。这是已知事实，必须承认，不能被“生成物不可执行”掩盖。
- 因此新增两条硬要求：
  1. **渲染器运行时完整性校验**：渲染器二进制、渲染浏览器与引擎脚本按随包清单逐项校验哈希与版本，任一不符即拒绝渲染，冲突时明确失败而不是降级到未校验的运行时。
  2. **引擎脚本版本进入渲染缓存键**：缓存键包含组合版本、文本、字体、浏览器版本、渲染器版本与引擎脚本版本；任一变化即创建新的渲染尝试。

准确的边界表述是：“模型不得产出任何可执行内容；页面中可执行的内容仅限渲染器自带的、钉版本的引擎脚本，且该运行时必须通过完整性校验。”

预览只渲染高光范围的低规格透明帧；正式导出再按目标规格渲染。两者使用相同的组合版本、文本、字体、时间计划和相对布局，只允许分辨率不同。中间产物由渲染器直接输出**带 Alpha 的 RGBA PNG 帧序列**，由 FFmpeg `overlay` 覆盖原画面，不依赖色键抠图；普通 H.264 `yuv420p` 不作为透明中间格式。组合版本、文本、字体、浏览器版本、渲染器与引擎脚本版本、分辨率与帧率共同构成缓存键。逐字动画如仅有句级 ASR 时间，只能按字素分配视觉节奏，不能当作真实逐字语音对齐。

需要明确的一项代价：渲染后端需要捆绑固定版本的浏览器，安装包体积与峰值内存的代价来自“用浏览器渲染 DOM”这一技术路线本身，与选用哪个渲染后端无关。

## 8. 视频动画分支

动画适合可用具体画面说明的场景、过程或故事。Harness 先生成有目标时长的分镜，再由客户端 Rust 侧**直连万相**提交文生图与图生视频任务并轮询终态。每条高光只生成一段动画；参考图、视频各有独立的提交次数上限。成功结果返回资产 ID、哈希、尺寸、帧率、实际时长和受控下载地址。客户端校验下载文件和媒体属性后才能应用。

**能力可用性以 `validate-dashscope-direct-capabilities` 的探针结论为准**：临时 token 直接提交万相文生图与万相图生视频任务已实测确认（http=200，返回 `task_id`）；参数、时长档位、轮询与取消语义、结果资产下载方式仍以探针结论为准。

门禁在客户端：未开通与额度耗尽由上游业务错误码 3001 / 3003 / 3004 判定（heartbeat 不含额度字段），客户端另按本地冻结配置实施任务级动画数量、累计秒数与金额上限；同键（`requestId` + 输入指纹）复用，不为同一内容反复付费。

`replace` 使用生成画面替换高光内指定的源画面范围，保留连续的原视频音频和普通 ASR 字幕，工程总时长不变。目标源范围由 Rust 依据工程已发布句段与来源区间计算，必须落在该高光的一个来源区间内、不得跨来源片段，且不采用模型给出的时间戳。

生成模型只能产出有限档位的时长，因此目标范围由**生成资产的实际时长与冻结容差反向确定**，而不是先声明范围再要求生成恰好等长——否则会产生大量不可满足的付费请求并因此降级。未被目标范围覆盖的高光其余部分保持原画面与原声。生成时长与目标范围的差异不超过 5% 时，可裁剪多余帧或受限变速，并保证最终偏差不超过一个输出帧；差异超过 5% 时，该动画校验失败并进入字幕降级，不补黑帧或长时间冻结画面；所需变速超出冻结的受限范围时按超容差处理，不施加不受限变速。

`insert` 用于高光之间的桥接或章节转场，资产绑定稳定的左右片段 ID 与边界 ID，作为独立单元增加工程时长。生成音轨一律丢弃；客户端为插入段补齐 48 kHz 双声道静音，前后来源音频在边界作受控短淡出和淡入。桥接期间不显示来源 ASR 字幕，后续片段和字幕随之顺延。左右邻接关系改变后，该动画失效并需重新审阅。两种模式都不叠加特效字幕。

自动生成或媒体校验失败时，可以在预算允许的情况下把该高光改为字幕分支；字幕也失败时保留普通原视频与基础字幕。每次降级都记录最终唯一 `enhancement.kind`、原因和成本，避免两条分支同时进入导出。

## 9. 记账、幂等与恢复

客户端本地 SQLite 是唯一的业务状态与记账权威：

- 每次付费提交前，先在本地事务中持久化稳定的 `requestId`、任务类型、输入指纹与上游 `task_id`（若已取得）；提交后即使进程崩溃，也能按 `requestId` 找回本地记录。
- 幂等语义为同键复用：**同键同输入返回原结果，同键不同输入拒绝**。网络中断后先按 `requestId` 找回，不重复提交。
- 若本地记录显示已提交但缺少 `task_id`，**保持待对账状态**：先查询上游是否已创建任务；无法确认时不自动再次提交付费请求。
- 上游不支持取消时，停止后续步骤和结果应用，但已提交请求的费用仍按上游实际用量发生。
- 不做服务端分项账本；服务端不感知每次调用。客户端不得以本地设置替代上游返回的未开通与额度耗尽结论。
- 已经成功的 ASR、LLM、图片、视频与本地渲染结果按输入指纹复用，不为同一内容反复付费。

隐私方面：音频与转写文本均属于用户内容。短期 token、完整提示词、ASR 正文、本地路径与签名下载地址不进入普通日志、诊断事件与遥测；客户端仍可保存已下载并应用的生成结果。

## 10. 客户端状态、合成与恢复

客户端 SQLite 保存冻结输入指纹、ASR 产物、Harness 运行代次、高光结果、互斥表现形式、组合与运行时版本、远程资产 ID、媒体哈希、用户审阅状态和导出版本。Harness 的聊天记录不作为业务任务的唯一状态来源。

任务阶段为：`audio_preparing -> uploading -> transcribing -> highlight_planning -> asset_generating -> local_rendering -> review -> exporting -> completed`。各阶段另有 `failed`、`cancelled` 和可重试状态；每条高光的生成状态单独保存。录制中的分片只有在完整登记且来源指纹稳定后才进入 ASR。应用重启后重新解析模型配置，先核对已有本地 `requestId`、上游 `task_id`、已发布结果及工程代次，再继续未完成步骤；运行指纹不一致的已发布结果保留为历史建议，不自动应用。

FFmpeg 导出在同一冻结工程版本下进行：裁剪原视频与原音频；字幕分支覆盖透明帧；动画 `replace` 分支替换画面并保留原音频；动画 `insert` 分支增加独立时间线单元。所有视频单元统一输出尺寸、帧率、像素格式与时基，音频统一采样率和声道布局，最后编码 H.264/AAC MP4。FFmpeg 参数由 Rust 固定模板生成，前端和 Harness 均不能提交任意滤镜或命令行。

组合渲染与 FFmpeg 正式导出各自限制并发；录制期间按照资源策略排队。取消时终止受控子进程、清理未发布的本地临时文件，并保留可复用的成功产物。若用户在生成期间修改片段或字幕，迟到结果只能保存为历史建议，不自动覆盖人工编辑。

## 11. 交付顺序与验收

实施顺序、进入条件、写域归属与协作纪律以 [`v2-delivery-order.md`](v2-delivery-order.md) 为唯一来源：

0. **百炼能力探针**（`validate-dashscope-direct-capabilities`）：确认临时 token 可用于文件转写、流式 LLM、万相文生图与万相图生视频，并确认音频上传路径与取消语义。这是后续所有步骤的进入条件。
1. **ASR 直连改造**（`wire-cloud-asr-upload-and-jobs`）：完成音频直传、异步任务提交与轮询、结果发布、独立预检与显式失败语义。使用真实中文长短样本验证源时间映射、分块去重、取消、重启与配额。
2. **Harness sidecar**（`add-model-gateway-and-harness-sidecar`）：打包应用专用 Profile，完成 macOS arm64、macOS Intel x86_64 与 Windows x64 的启动、流式协议、临时 token 刷新、权限隔离、异常退出与恢复测试。
3. **特效字幕**（`add-effect-caption-renderer`）：先在仓库外的沙盒完成适用性验证（纯 CSS 组合的表现力上限、单条高光的渲染耗时与高光时长比值、全分辨率 RGBA 帧序列的体积）。**这是进入条件**：若表现力明显不足以优于现有逐字字幕、或渲染慢于实时、或体积不可接受，则改用 Rust 声明式模板路线，而不是继续本步。
4. **生成式动画**（`add-generative-video-animation`）：完成直连万相的文生图与图生视频提交、媒体校验、`replace` 和 `insert` 时间映射、客户端门禁与失败降级。
5. **整体发行**：验证 ASR 到导出全链路、历史工程兼容、用户编辑优先、取消与断点恢复，并记录 8 GB 目标设备上的 Harness、渲染运行时、渲染浏览器、FFmpeg 峰值内存、耗时和磁盘占用；三个目标架构各自完成一次端到端验收。

验收以实际输出的视频和本地任务记录为准：高光必须对应真实 ASR 句段；每条高光最终只有一种增强方式；云端失败不得重复提交未知状态的付费请求；成片的画面、字幕、音频和时长必须与冻结工程一致；缓存命中必须与运行指纹一致。
