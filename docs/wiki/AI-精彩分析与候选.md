# AI 精彩分析与候选

精彩分析是本地 ASR 之后的独立可选步骤。ASR 完成不会自动调用 LLM；只有用户配置 DeepSeek、
查看发送范围并确认“开始精彩分析”后，客户端才会发送文本。

## 前置条件

- AI 项目至少包含一个已经完成且有有效句段的输入。
- 设置页已经配置 DeepSeek 模型和 API Key，并通过或主动跳过连接诊断。
- 用户理解本次会把规范化转写发送到 DeepSeek，并在确认框中明确授权。
- 客户端激活和 Runtime Resource Pack 均处于可用状态。

API Key 只保存到操作系统凭据库。SQLite 和前端只保存 `keyConfigured`、模型 ID、超时等非敏感
配置，不会回填、显示或记录 Key 明文。

## 工作流

```text
本地时间戳转写
      ↓ 冻结模型、Prompt、标签、目标和 Skills
按源视频和稳定句段边界分块
      ↓
候选发现 Agent
      ↓
Rust 校验句段 ID、时间、时长和来源视频
      ↓
跨批次去重与候选压缩
      ↓
全局评分 Agent
      ↓
SQLite 原子发布候选、评分、理由、排名和选择状态
```

候选发现和全局评分使用同一个用户配置模型，但角色不同。Rust 决定分块、调用顺序、重试、
恢复和发布；模型不能写文件、执行命令、修改数据库、搜索网络或调用切片工具。

## 发送与不发送的数据

| 会发送 | 不会发送 |
| --- | --- |
| 稳定句段 ID | 视频或音频文件 |
| 输入 ID | 本地绝对路径 |
| 源视频内起止毫秒 | Cookie、签名流地址或页面正文 |
| 规范化文本 | SQLite 数据库内容 |
| 项目标签与主播标签快照 | DeepSeek API Key 和请求头 |
| 用户填写的分析目标 | Provider 原始响应正文和模型隐藏推理 |
| 选中的 Skill ID、版本和规则 | 原始 FFmpeg/Whisper 日志 |

未知标签只作为用户数据传入，不会被解释为系统指令。系统始终加载通用爆点 Skill，并根据标签
确定性选择最多三个专项 Skill；当前包含带货转化、搞笑包袱、知识密度和故事情绪。

## 分块、校验和重试

长直播不会一次性发送。当前实现按单个源视频分块，每块最多约 6,000 个字符，并带最多两个
相邻句段作为上下文；不会把一个候选跨到另一个源视频。每块最多保留 5 个发现候选，统一评分
前最多处理 60 个去重候选。

每个候选必须满足：

- 引用的稳定句段真实存在且属于同一个输入视频；
- 时间范围由真实句段约束，开始早于结束；
- 候选时长为 15–90 秒；
- 不能伪造句段、越过源视频边界或用模型返回的任意时间覆盖本地时间。

可重试的 Provider、临时网络和结构化响应错误，每批最多尝试两次。单批失败不会清空此前成功
批次；界面分别显示成功、失败、处理中和待处理批次数。统一评分失败时，系统可以使用候选发现
阶段的六维平均分生成备用排序，并把运行标为“部分完成”。

## 评分与候选状态

每个已发布候选包含：

| 字段 | 含义 |
| --- | --- |
| `totalScore` | 0–100 总分 |
| `hookScore` | 开场吸引力 |
| `informationScore` | 信息密度 |
| `emotionScore` | 情绪强度 |
| `tagRelevanceScore` | 与项目/主播标签的相关性 |
| `completenessScore` | 语义和片段完整性 |
| `shareabilityScore` | 传播潜力 |
| `reason` | 可展示的简短评分理由 |
| `matchedTags` | 命中的标签 |
| `rank` | 全局排序 |
| `selected` | 是否加入待切片 |

当前运行最多发布 10 个经过统一评分的候选。总分不低于 70 的候选在界面标记为精彩候选，
低于 70 的结果作为参考候选展示。这个阈值是辅助筛选，不代表内容事实或最终剪辑决定。

## 界面使用

1. 在设置页配置 DeepSeek API Key 和模型，点击“测试连接”只执行不含用户转写的最小诊断。
2. 回到已完成的 AI 项目，填写项目标签和可选分析目标。
3. 展开“分析详情”检查预计发送的视频数、句段数、字符数、批次、模型和 Skills。
4. 点击“开始精彩分析”并确认发送文本。
5. 运行期间查看批次进度、成功/失败数、候选草稿数和 Token 用量。
6. 完成后在“全文”“精彩候选”“已选择”之间切换，并按分数或源时间排序。
7. 点击候选会切换到来源视频、定位真实 ASR 句段并跳到开始时间。
8. 点击“播放片段”只播放候选起止范围，到结束时间暂停，不调用 FFmpeg。
9. 切换“加入待切片”会立即写入 SQLite，不需要额外保存。

预览不可用时，候选、评分、理由和 ASR 句段仍可查看；只有跳转、范围播放和字幕联动被禁用。

## 分析详情能看到什么

“分析详情”展示以下可审计信息：

- 本次运行冻结的模型、Prompt 版本、标签、分析目标和 Skills；
- 候选发现 Agent 和评分 Agent 的任务约束；
- 实际发送字段与本次使用的规范化句段；
- Rust 本地校验、去重和发布步骤；
- 本地保存的候选、六维评分、理由、排名和选择状态；
- 批次数、Token 用量和运行状态。

客户端不能展示模型没有返回的隐藏思考过程，也不会伪造“推理链”。Provider 原始响应正文、
请求头和隐藏推理不保存；可复核内容是请求约束、实际输入范围、稳定 ID 和最终结构化结果。

## 离开页面与应用重启

精彩运行、分块状态、候选草稿、评分、Token 和选择均保存在 SQLite。切换菜单不会取消任务；
回到项目后，界面主动查询最新运行和进度，并以约 1.2 秒周期刷新活动运行。

应用退出后再次打开时：

- 已完成批次不会重新发送；
- 排名未完成时复用已校验候选并继续评分；
- 部分失败或失败运行可通过“重试未完成批次”继续；
- 输入顺序、转写、标签、Skills、模型、Prompt 和参数都未变化时，可复用相同分析指纹的完整结果。

## 当前边界

- 不把 ASR 自动上传到云端，也不在本地 ASR 失败时自动回退 DeepSeek。
- 不编辑原始转写，不让 LLM 改写稳定句段或源时间。
- 不自动采用任何候选；必须由用户查看并选择。
- 不执行真实裁剪、拼接、字幕烧录或成品导出。
- 浏览器演示模式只使用本地示例，不保存真实 Key，也不发起 Provider 请求。
