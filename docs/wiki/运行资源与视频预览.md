# 运行资源与视频预览

Runtime Resource Pack 为录制、预览、缩略图和本地 ASR 提供受控 FFmpeg、FFprobe、Whisper、
VAD、模型、规范化字典和平台依赖。应用不接受前端传入的可执行文件或模型路径。

智能成片同样只使用资源管理器返回的已验证路径。资源门禁失败会阻止新批次执行，但不会停止
recorder，也不会删除已经登记的视频、转写、精彩或草稿。

视频预览是独立的可再生 MP4 缓存，只服务 WebView 播放；原始 MKV 始终是归档、ASR 和后续
剪辑的输入。预览失败不会清空转写或精彩结果。

## 资源来源与选择

应用只检查两个受控位置：

1. 应用数据目录中已经原子安装的资源版本；
2. 当前安装包内的随包资源。

如果随包资源版本比应用数据目录中的完整版本更新，优先使用随包版本。资源缺失或损坏时，用户
可以从发行构建注入的固定 HTTPS 地址下载；普通设置、WebView 和命令参数不能更换下载服务器。

资源 manifest 至少固定：

- schema、bundle 版本、最低应用版本、平台和架构；
- FFmpeg、FFprobe、Whisper、VAD sidecar、ASR/VAD 模型和规范化字典；
- 每个文件的相对路径、大小、SHA-256、可执行属性和许可证引用；
- 最低物理内存、可用内存和临时磁盘要求。

## 启动校验优化

每次进程启动仍会完整验证一次资源包，以避免直接信任上次保存的 `ready` 状态。完整校验包含
manifest、平台、必需组件、文件大小、SHA-256、权限和文件类型。

当前实现不会在 Tauri `setup` 的 macOS UI 线程同步扫描整个资源包：

1. 资源状态初始化为 `verifying`，主窗口先显示资源校验页。
2. 完整校验通过后台阻塞任务执行。
3. ASR runtime 先以轻量不可用状态创建，不加载 Whisper 模型或启动调度器。
4. 校验成功后在当前进程热激活受控资源根。
5. 客户端授权有效时，恢复待处理 ASR 和已启用主播监听。
6. 前端收到统一 `runtime-resource-event` 后自动进入监控中心。

完整校验成功后，解析结果缓存在进程内。录制、预览和 ASR 后续读取工具路径时只检查每个已验证
文件的大小、修改时间、普通文件类型和符号链接状态，不重复读取约 197 MB 的模型计算 SHA-256。
任一文件或 manifest 的大小、修改时间或类型变化会使缓存失效并触发完整重新校验。

手动“重新检测”也在后台执行，不阻塞 UI。前端先注册资源事件监听，再读取初始状态，避免校验
恰好完成时遗漏 `ready` 事件而永久停留在“校验中”。

## 资源状态

| 状态 | 含义 | 主功能 |
| --- | --- | --- |
| `verifying` | 正在校验随包或已安装资源 | 锁定，窗口可响应 |
| `downloading` | 正在下载、校验或安装 | 锁定，可取消 |
| `ready` | 当前平台全部必需资源已验证 | 解锁，按授权状态恢复任务 |
| `failed` | 没有可用资源或校验任务失败 | 锁定，允许重试/重新检测 |
| `cancelled` | 用户取消资源下载 | 锁定，允许重新下载 |
| `rollback` | 新候选资源失败，保留旧版本诊断 | 取决于是否仍有满足版本要求的完整资源 |

资源状态 DTO 不包含完整本地路径、下载授权头、签名私钥或命令行。

## 下载与热激活

下载流程使用取消 token、大小上限、临时目录和原子安装：

```text
固定 HTTPS manifest
       ↓ 签名、版本、平台与大小检查
逐组件下载 → 逐文件 SHA-256
       ↓
临时目录完整解析
       ↓
原子发布 current 版本
       ↓
进程内激活 FFmpeg/FFprobe 和 ASR scheduler
```

失败或取消不会把 `.part`、临时目录或半成品标记为 `ready`，也不会修改录像。下载成功后无需
重启应用，资源事件会解锁导航并恢复任务。

## 应用内视频预览

### 输入边界

预览只接受数据库中已登记、已经完成、文件存在且包含视频轨的单个分片。仍在写入的 partial、
任意前端路径、未登记文件和“整场自动合并”请求都会被拒绝。

AI 工作区、监控中心和视频库共享同一预览服务。AI 工作区针对竖屏视频读取真实宽高，使用有界
竖屏舞台和 `object-fit: contain` 展示完整画面，不裁掉上下半屏。

### 转换策略

```text
已兼容 MP4 ─────────────────────────→ 直接授权播放
MKV/其他容器 → 无损重封装 MP4 ─────→ FFprobe 验证 H.264 + 可选 AAC
                         验证失败 ──→ H.264 + AAC 回退转码
```

生成 MP4 时显式使用 MOV muxer、`mp42` brand 和 `+faststart`，避免临时输出名为 `.part.mp4`
或 WebView 对品牌判断不一致时出现“FFmpeg 无法生成兼容的 MP4 预览”。无音轨视频使用可选音轨
映射，仍可生成无声预览。

预览转换全局单并发。同一源路径、大小、修改时间和预览配置版本的并发请求共享任务；另一个视频
进入队列。进度来自 FFprobe 时长和 FFmpeg `out_time`，无法可靠计算时只显示阶段，不伪造百分比。

### 候选片段播放

精彩候选的“播放片段”不会生成新媒体。它复用当前视频预览，从候选开始时间播放，到结束时间
自动暂停。来源视频切换后，界面等待对应预览就绪再跳转；预览失败时仅禁用播放器联动，候选和
ASR 文本仍保留。

## 缓存与磁盘保护

- 缓存位于 Tauri 应用缓存目录，不写入视频业务表。
- 缓存键包含视频 ID、规范路径、大小、修改时间和预览配置版本。
- 转换先写临时文件，FFprobe 验证后再原子发布 MP4 和 JSON 清单。
- 默认清理超过 7 天未访问的预览，并按 LRU 把总容量限制为 10 GB。
- 正在生成或播放的缓存受保护；删除视频或会话时同步清理对应缓存。
- 转换前要求预计输出大小之外至少保留 2 GiB 安全余量。
- 缓存清理、转换失败和重试都不能修改原始录像。

## 常见问题

### 启动窗口长时间缓冲

确认已经重启到包含后台校验优化的新二进制。`make app-dev` 使用 `--no-watch`，Rust 修改不会
自动加载。控制台应先出现实例锁日志，窗口显示“正在校验本地运行资源”，随后进入监控中心。

### 一直停在“正在校验”

查看资源状态错误和日志中的 `runtime_resources` 事件。校验任务异常退出会返回
`resource_verification_failed`；文件缺失或哈希变化会返回对应完整性错误。不要用修改时间或
文件名伪装资源，应重新构建或重新下载完整包。

### “播放器联动不可用”

按以下顺序检查：

1. 原视频是否存在、已结束写入且包含视频轨；
2. Runtime Resource Pack 中 FFmpeg/FFprobe 是否通过校验；
3. 缓存卷是否有预计输出加 2 GiB 空间；
4. 重封装结果是否为 H.264 视频和可选 AAC 音频；
5. 点击“重试预览”是否能完成回退转码。

即使预览失败，也可以继续浏览、复制和导出 ASR，或查看精彩候选。不要删除 ASR 项目来修复
预览问题。

### FFmpeg 返回非零代码

非零退出只是结果，不是根因。应结合脱敏错误分类判断输入读取、muxer、编码器、磁盘或取消。
临时输出会被删除，已有有效缓存和原始录像保持不变。

### 智能成片停在资源或授权门禁

先在设置页重新检测运行资源，再检查客户端激活和 Provider Key。若任务提示授权失效，核对来源、
Provider、模型和发送范围后重新确认当前任务；不要通过修改 SQLite、传入系统 FFmpeg 路径或读取
仍在写入的直播文件绕过门禁。直播录制会继续，完成分片保留到任务可恢复。

## 验证命令

```bash
cargo test --manifest-path src-tauri/Cargo.toml --test runtime_resource_state
cargo test --manifest-path src-tauri/Cargo.toml --test preview
npm test -- --run ui/src/App.test.tsx ui/src/AiWorkspace.test.tsx
npm run typecheck
git diff --check
```

真实 FFmpeg 集成测试依赖本机可执行资源，应在发行候选资源环境额外执行对应 ignored 测试和
`make test-preview-integration`。自动化 mock 通过不能替代打包后 WebView 播放验收。
