# 客户端生命周期与访问恢复

客户端有两个相互独立的运行门禁：客户端授权和 Runtime Resource Pack。只有授权状态有效且运行
资源校验通过后，才会恢复主播监听、录制和 ASR 队列。抖音公开页访问会话是直播解析通道，
不是客户端激活服务，三者不要混为一类故障。

## 启动顺序

```text
获取应用数据目录进程锁
       ↓
打开 SQLite → migration → 异常状态对账
       ↓
读取本地激活摘要          初始化资源状态为 verifying
       ↓                         ↓
显示主窗口/必要门禁       后台校验 Runtime Resource Pack
       ↓                         ↓
AppStart + 心跳           激活 ASR runtime 和媒体工具
       └──────────┬──────────────┘
                  ↓ 两个门禁均通过
          恢复已启用监听与待处理 ASR
```

启动时完整资源哈希校验在后台阻塞线程执行，不再占用 macOS UI 主线程。资源校验期间只开放资源
准备界面，不启动业务任务；窗口本身可以响应，不会因为大模型和 FFmpeg 文件校验而长时间空白。

## 单实例保护

应用在打开 SQLite 和执行恢复前获取应用数据目录的独占锁，并持有到全部服务关闭。第二个进程
会记录 `instance_rejected` 后退出，不会：

- 把第一实例的录制会话标记为中断；
- 启动重复主播 worker 或 FFmpeg；
- 并发修改 AI 队列、资源安装状态或浏览器会话。

开发命令带有 `tauri dev --no-watch`。修改 Rust 后应先安全停止当前实例，再重新运行
`make app-dev`；不要通过启动第二实例验证新二进制。

## 客户端激活

### 服务端配置

`DY_SCREEN_API_BASE_URL` 在构建或开发命令中传入，由 Rust 的统一 API 客户端规范化。激活、
心跳、AppStart 和埋点不直接创建各自的 HTTP 客户端。开发示例：

```bash
make app-dev DY_SCREEN_API_BASE_URL="http://localhost/api/"
```

需要在开发构建中启用完整激活门禁时，变量必须使用赋值语法：

```bash
make app-dev DEV_REQUIRE_ACTIVATION=1
```

正式发行应使用固定 HTTPS 地址。当前协议使用明文 JSON，已保留统一 codec 替换点，但“已预留”
不代表当前请求已经加密。

### 状态

| 状态 | 含义 | 后台业务 |
| --- | --- | --- |
| `missing` | 本地没有完整激活记录 | 锁定 |
| `active` | 服务端已确认有效，存在可用 token | 允许，仍需资源门禁通过 |
| `retrying` | 临时网络错误，保留本地激活记录并重试 | 继续允许，显示重试状态 |
| `revoked` | 停用、过期、解绑或服务端明确拒绝 | 暂停并要求重新激活 |

前端只得到脱敏设备尾号、状态、消息和心跳时间，不得到激活码或 token。激活成功后，本地 SQLite
保存服务端交互和恢复所需记录；日志、事件和前端 DTO 不输出完整凭据。

### 心跳与强制下线

- 正常心跳周期为 90 秒。
- 临时网络失败后按 30 秒周期重试，并保持 `retrying`。
- 心跳可以更新 token、有效期、宽限时间、服务端时间偏移和可选录制额度 `max_screen_limit`。
- 收到 `disabled`、`expired`、`unbound` 或其他明确撤销后，客户端清理不可继续使用的 token，
  幂等暂停 Supervisor 和 ASR runtime，并重新显示激活入口。
- 再次激活成功后，只有运行资源仍然就绪才恢复监听和待处理 ASR。

AppStart 是免鉴权、best-effort 的启动登记，也可携带可选录制额度 `max_screen_limit`；失败只写脱敏诊断，不阻止使用本地有效授权。AppStart 或心跳最新返回的合法正整数立即成为当前进程唯一录制额度；字段缺失、非法或请求失败时保留最近合法值，从未收到合法字段时使用 4。本地旧设置只保留载荷和数据库兼容，不改变 Supervisor。埋点
队列只允许 `feature`、`action`、`result`、`duration`、`platform`、`count` 和 `source` 等白名单
属性，不上传媒体、ASR 文本、Cookie、本地路径或直播页面正文。

## 抖音公开页访问恢复

直播间解析优先使用原生 HTTP。当公开页被判定为 `access_restricted` 时，客户端回退到一个全局、
持久化、串行共享的系统 WebView。它与主窗口隔离，不为每个主播创建浏览器数据副本。

| 访问状态 | 含义 | 用户动作 |
| --- | --- | --- |
| `native` | 原生通道可读取受支持结构 | 无需操作 |
| `browser_resolving` | 共享 WebView 正在导航或探测 | 等待 |
| `verification_required` | 页面持续要求人工交互 | 点击“立即验证” |
| `session_ready` | 浏览器会话已能解析公开页 | 无需操作 |
| `session_expired` | 会话已清除或需要重建 | 重新检查或打开验证 |

### 自动恢复

1. WebView 在后台导航到规范化直播间地址并保持静音。
2. 页面无需人工处理即可出现匹配 `web_rid` 的受支持数据时，窗口继续隐藏并返回解析结果。
3. 有界探测后仍是验证页，才发布 `verification_required`，并在这一轮阻塞中只显示一次带“立即验证”和“稍后处理”的系统 warning 对话框；对话框不受普通通知开关影响，但不会在用户选择前导航页面。
4. 点击“立即验证”直接显示并聚焦持久验证 WebView；选择“稍后处理”或关闭弹窗只保留主界面横幅。普通系统通知仍遵循用户通知开关。
5. 用户在同一窗口完成验证后，客户端识别会话恢复、隐藏窗口并只发布一次恢复事件，同时重置下一轮系统弹窗去重门。
6. Supervisor 收到恢复事件后执行一次受控检查，唤醒等待 worker，不创建密集导航。

一个房间等待人工验证时，后续浏览器导航暂停，但其他主播仍可做受节流原生检查；已经运行的
FFmpeg 录制不会因此停止。

### 安全限制

- 顶层页面只允许 HTTPS 抖音官方域名；验证码 iframe 只允许受限字节官方路径。
- 拒绝任意新窗口、下载、非 HTTPS scheme 和非白名单 host。
- WebView 只读取规范化 URL、标题、加载状态、安全 marker 和有限初始化脚本。
- 旧请求代次、错误房间、未完成页面或不匹配的 `web_rid` 只返回 `pending`，不能启动 FFmpeg。
- 签名流 URL 只在本次解析内存中使用，不写日志、错误、事件或数据库。
- 验证窗口不具备主窗口 capability，也不开放任意本地文件或通用 Tauri command。

### 重新检查与清除会话

“重新检查”先执行一次受节流原生检查。原生已经恢复时会清除旧验证目标并唤醒 worker；仍受限
时才创建新的浏览器请求代次。

“清除抖音会话”会取消当前和排队中的浏览器解析，清理平台 WebView browsing data，并进入
`session_expired`。该操作不会删除主播、设置、录像或 ASR 数据，也不会强制停止正在使用已获
流地址的 FFmpeg；后续页面检查和流地址刷新需要重新建立会话。

## 关闭与异常恢复

主窗口关闭只隐藏窗口，托盘服务继续运行。只有托盘退出、前端确认退出、Tauri 退出请求或系统
信号会进入全局关闭流程。关闭流程是幂等的：第一个来源领取关闭权，重复事件不会重复结束会话。

正常关闭会取消心跳和埋点、Supervisor、录制、浏览器解析、预览、缩略图和 AI runtime，并在
全局期限内等待 FFmpeg 安全封装 MKV。异常重启时，SQLite 对账把未完成状态恢复到可重试形态，
资源和授权门禁通过后再恢复任务。

## 故障定位

| 现象 | 优先检查 |
| --- | --- |
| 一直显示激活弹窗 | 激活服务地址、业务 `code`、激活码状态和本地时间 |
| 显示“正在重试”但监听仍在 | 心跳临时网络错误；这是预期宽限行为 |
| 突然要求重新激活 | 心跳是否返回停用、过期或解绑；查看脱敏原因 |
| 主界面停在资源校验 | Runtime Resource Pack，而不是激活服务；参见运行资源专题 |
| 多个主播都等待验证 | 共享 WebView 正处于人工验证门，完成一次验证即可唤醒队列 |
| 已在浏览器验证但仍未恢复 | 点击“重新检查”，确认目标直播间仍可访问且页面结构受支持 |
| 第二个开发窗口打不开 | 单实例锁生效；先安全停止旧进程 |
