# Runtime Resource Pack 发行清单

本文用于每次发布前记录应用和运行资源是否来自同一组受控输入。macOS arm64 与 Intel
x86_64 必须分别复制并填写一份清单，不能用一个架构的证据批准另一个架构。

## 版本与平台

| 字段 | 值 |
| --- | --- |
| 应用版本 | `0.3.0` |
| 资源 bundleVersion | `2026.07.4` |
| channel | `stable` |
| 平台/架构 | `macos/aarch64` 或 `macos/x86_64`，每份只选一个 |
| 固定 HTTPS 基础地址 | `https://.../stable/0.3.0/macos/{aarch64|x86_64}/2026.07.4/` |
| manifest SHA-256 | 候选 staging 完成后填写 |
| manifest 公钥 keyId/指纹 | `release-key-placeholder / 待正式签名` |

## 组件

- [x] `media.ffmpeg` / `media.ffprobe`
- [x] `asr.whisper` / `asr.vad-sidecar`
- [x] `asr.model` / `asr.vad-model`
- [x] `asr.normalization`
- [x] macOS 动态库（Windows VC++ 运行库待补充）
- [x] 全部第三方许可证与来源
- [x] 逐文件大小和 SHA-256 已记录在 `runtime-manifest.json`

## macOS 架构一致性

- [ ] `MACOS_ARCH`、Rust target、manifest 平台、资源 URL 和 DMG 文件名属于同一架构。
- [ ] `.app` 主程序、Whisper/VAD、FFmpeg/FFprobe 和全部 dylib 均为目标单切片 Mach-O。
- [ ] 全部原生文件最低系统版本不高于 macOS 12.0，且没有临时目录或未声明动态依赖。
- [ ] arm64 Whisper 使用 Metal；Intel Whisper 关闭 Metal/BLAS/原生 CPU 优化并使用 SSE4.2 基线。
- [ ] arm64 与 Intel 使用独立 staging、Tauri target 目录、资源发布目录和 DMG。
- [ ] 架构索引分别位于 `macos/aarch64/index.json` 与 `macos/x86_64/index.json`，基础地址通过 HTTPS 和目标架构后缀门禁。

## 启动与热激活检查

- [x] 每次进程启动把资源状态初始化为 `verifying`，不直接信任 SQLite 中上次的 `ready`。
- [x] 完整 SHA-256 校验在后台阻塞任务执行，不占用 Tauri UI 主线程。
- [x] 单次启动完整校验成功后缓存解析结果，业务读取只检查大小、修改时间和文件类型。
- [x] manifest 或组件元数据变化会使缓存失效，并触发完整重新校验。
- [x] 资源就绪后热激活 ASR scheduler，并在客户端授权有效时恢复监听和待处理 ASR。
- [x] 前端先订阅 `runtime-resource-event` 再读取初始状态，不遗漏启动完成事件。
- [x] 手动“重新检测”在后台执行，校验期间禁用重复下载和检测操作。

上述缓存只在当前进程内有效，不会跨进程跳过完整性校验。窗口可以在校验期间显示资源准备页，
但监控、录制、预览和 AI 业务仍保持门禁。

## 视频预览兼容检查

- [x] MKV 优先无损重封装，输出不满足 H.264 + 可选 AAC 时回退转码。
- [x] 临时及最终 MP4 显式使用 MOV muxer、`mp42` brand 和 `+faststart`。
- [x] 无音轨输入使用可选音轨映射，不因缺少音频失败。
- [x] FFprobe 验证通过后才原子发布缓存，WebView 不读取 `.part` 半成品。
- [x] 竖屏 AI 预览使用 `object-fit: contain`，播放器展示完整画面。
- [x] 预览失败不影响原始录像、ASR 产物和高光候选。

## 智能成片平台验收

macOS arm64、macOS Intel x86_64 和 Windows x64 必须分别保存以下证据，任一平台不得复用其他
平台或 mock 测试的结论：

- [ ] FFmpeg、FFprobe、Whisper、VAD sidecar 与全部动态依赖架构匹配，逐文件 SHA-256 通过。
- [ ] 随包 ASR/VAD 模型可加载，并用授权的含音轨媒体完成一次中文识别。
- [ ] 本地智能成片从系统文件选择器推进到可审阅草稿，普通项目仍等待手动高光授权。
- [ ] 直播智能任务只消费完成登记分片；AI 失败、取消和重启均不停止 recorder。
- [ ] 应用重启后恢复任务快照，失败阶段可局部重试，成功前置阶段不重复调用 Provider。
- [ ] 预览显示真实完整画面，最终显式导出为 H.264 视频和 AAC 音频的 MP4。
- [ ] 人工编辑或导出冻结后，新直播高光进入下一版草稿，不修改旧工程或已导出文件。
- [ ] 日志、事件和遥测抽检不含媒体、字幕、主播/直播间、本地路径、Prompt、凭据或原始响应。

Intel 必须在真实 Intel Mac 验收，Windows 必须在真实 Windows x64 目标机验收。当前开发机只可为
自身平台项提供证据，三平台未全部归档前不得把智能成片跨平台发行门禁标记为通过。

## 验收命令

```bash
make fmt-check
make runtime-resource-verify MACOS_ARCH=aarch64 ASR_STAGE=resources/asr-stage
make runtime-resource-verify MACOS_ARCH=x86_64 ASR_STAGE=resources/asr-stage-x86_64
make frontend-build
cargo test --all-targets
cargo test --manifest-path src-tauri/Cargo.toml --all-targets
npm test
openspec validate --all --strict
git diff --check
```

Intel 发布候选还需执行：

```bash
make macos-build-doctor MACOS_ARCH=x86_64
make build-mac-intel-release \
  MACOS_ASR_SOURCE=resources/asr-source-macos-x86_64 \
  DY_SCREEN_API_BASE_URL=https://api.example.com/api/ \
  RESOURCE_BASE_URL=https://resources.example/stable/0.3.0/macos/x86_64/2026.07.4/
hdiutil verify src-tauri/target/x86_64-apple-darwin/release/bundle/dmg/切片智能体_0.3.0_x86_64.dmg
```

## Intel 正式发行门禁

- [ ] 在真实 Intel Mac 上安装并运行；Rosetta 或 Apple Silicon 交叉编译不能替代。
- [ ] Developer ID 签名、hardened runtime、notarization、stapling 和 Gatekeeper 全部通过。
- [ ] 断网启动并完成公开直播录制、视频预览、首帧封面、本地 ASR 和字幕 MP4 导出。
- [ ] 退出后无遗留 FFmpeg、Whisper 或 VAD 子进程，脱敏验收证据已归档。
- [ ] 以上门禁通过前，不更新 stable Intel index，不把 x86_64 DMG 标记为正式可发布。

## 服务器验收

使用静态 HTTPS 服务验证：

- `runtime-manifest.json` 返回 200，签名能由应用内嵌公钥验证；
- 单文件请求支持 `Range`，断点响应为 206；
- 错误或篡改文件无法通过 SHA-256，且不会出现在 `current` 目录；
- 下载取消、进程重启和网络中断不会留下可执行半成品；
- 服务端访问日志中不包含视频、音频、转写、主播数据或用户数据库内容。

本次已使用 OSS 静态文件服务完成 `index.json`、`runtime-manifest.json` 和模型文件的 `200` 验证，以及模型文件 `Range` 的 `206` 验证；响应包含 `ETag`、`Last-Modified` 和 `Accept-Ranges`。正式签名完成后仍需重新构建应用，使基础地址成为构建期常量；不能通过设置页或 WebView 动态替换。

## 用户错误提示对照

| 错误码 | 用户处理 |
| --- | --- |
| `resource_not_checked` | 旧版本或迁移状态；点击“重新检测”或重新启动应用 |
| `resource_verification_failed` | 后台校验任务异常退出；查看日志后重新检测 |
| `invalid_manifest` / `invalid_signature` | 停止使用当前下载地址，重新发布签名清单 |
| `unsupported_platform` | 下载匹配当前系统和架构的发行包 |
| `download_failed` | 检查网络、HTTPS、Range 和磁盘空间后重试 |
| `integrity_failed` | 删除未完成下载并重新下载，原子安装不会覆盖旧版本 |
| `cancelled` | 点击下载继续；取消不会删除已完成录像 |
| `rollback` | 新资源安装失败，应用会保留并尝试使用上一份完整资源 |
| `smart_resources_unavailable` | 重新检测 Runtime Resource Pack；不会停止录制或删除已有草稿 |
| `smart_authorization_stale` | 核对来源、Provider、模型和文本范围后重新确认当前任务授权 |
| `smart_live_batch_failed` | 打开任务详情并重试失败批次；后续完整分片和 recorder 保持独立 |

启动、校验和预览故障处理见 [运行资源与视频预览](运行资源与视频预览.md)。最近相关提交和回归
范围见 [最近变更](最近变更.md)。
