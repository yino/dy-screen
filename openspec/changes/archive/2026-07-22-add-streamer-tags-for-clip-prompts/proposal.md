## Why

当前主播只有名称和直播来源，无法表达“带货”“搞笑”“知识科普”等内容特征。后续切片 LLM 如果缺少稳定的主播语义上下文，只能对所有主播使用同一套判断标准，难以优先提取与主播类型匹配的重点句子。

## What Changes

- 为每个主播增加可排序的多个本地标签，例如“带货”“搞笑”，并允许为标签补充可选的 Prompt 指导说明。
- 在添加和编辑主播时维护标签，在主播表格和详情区域以标签徽章展示；浏览器演示模式同步模拟该行为。
- 使用独立 SQLite 关系表持久化标签，限制每个主播最多 10 个标签，标签名称为 1–24 个字符，Prompt 指导最多 500 个字符，并对同一主播的标签名称进行规范化去重。
- 扩展 Rust 领域模型、Tauri DTO、command 和前端类型，使主播查询结果稳定携带按优先级排序的标签。
- 定义只读的结构化 `StreamerPromptContext` 契约，供未来切片功能读取主播名称、标签名称、可选指导和优先级。
- 主播归档和恢复时保留标签；永久删除时级联删除；无历史临时主播合并到已有主播时对标签取并集并确定性处理同名标签。
- 现有数据库迁移后，已有主播默认拥有空标签集合，不影响监听、录制、视频库和预览逻辑。
- 非目标：本变更不生成 Prompt、不调用 LLM、不执行 ASR、高光评分、句子提取、自动标签推断、自动切片或视频导出，也不创建独立标签管理页面、标签筛选、颜色、图标或导入导出功能。

## Capabilities

### New Capabilities
- `streamer-tagging`: 定义主播多标签的校验、排序、持久化、合并、生命周期和未来结构化 Prompt 上下文输出。

### Modified Capabilities
- `streamer-monitoring`: 主播创建、编辑、查询、归档、恢复、重复身份合并和数据库迁移需要保留并返回标签集合。
- `desktop-client-shell`: 添加/编辑主播表单、主播表格、详情区域和浏览器演示模式需要支持标签维护与展示。

## Impact

- SQLite 增加 `streamer_tags` 表、唯一索引、排序字段和级联外键；repository 查询需要稳定加载标签，迁移必须保持已有主播及历史关系。
- `src-tauri/src/domain.rs`、`database.rs`、`streamer_service.rs`、Tauri command 和事件刷新路径需要扩展标签 DTO 与事务更新逻辑。
- `ui/src/types.ts`、`api.ts`、`App.tsx` 和组件测试需要增加标签输入、排序、校验错误和标签徽章。
- 后续 AI 分析或切片变更可以读取 `StreamerPromptContext`，并在创建分析项目时自行保存标签快照；本变更不修改当前 ASR 活动变更，也不实现任何 Prompt 或模型调用。
