## 背景

根 Rust crate 已经提供抖音直播页解析、FFmpeg 分片录制、多房间任务隔离、取消和脱敏事件模型，但当前只有 CLI。新客户端需要在不复制核心逻辑的前提下，增加长期运行的主播监听、SQLite 持久化、桌面生命周期和可视化管理界面。

用户选择参考 `examples/test.webp` 的方案 A：左侧导航、顶部状态摘要、主播表格和右侧当前会话详情。客户端第一版优先支持 macOS，继续依赖本机 FFmpeg/FFprobe；所有主播、设置和视频元数据只保存在本地。

## 目标/非目标

**目标：**

- 创建可运行的 Tauri 2.0 + React/TypeScript 桌面客户端。
- 管理主播、自动检查开播状态、自动开始/停止/重试录制。
- 应用重启后恢复监听，关闭窗口后驻留托盘继续工作。
- 使用 SQLite 保存主播、设置、录制会话和视频分片。
- 展示直播状态、监听状态、本次视频和历史视频。
- 提供磁盘保护、系统通知、文件打开/定位/删除和错误恢复。
- 复用根 crate 的 resolver 和 recorder，保持签名 URL 脱敏。

**非目标：**

- 登录、验证码、Cookie 自动化、DRM 或权限绕过。
- 第一版生产级 FFmpeg sidecar 打包。
- 应用内视频播放、分片合并、转码、ASR、NLP 或 AI 剪辑。
- 云端同步、账号体系或遥测。

## 技术决策

### 使用 React + TypeScript + Vite 构建 Tauri 前端

前端负责导航、表单、表格、详情、设置和空状态，通过 Tauri command 获取快照并通过 Tauri event 接收状态变更。组件按页面和领域拆分，避免让单一页面同时承担数据库或录制逻辑。

替代方案是使用原生 HTML 或其他框架。React 在表格、弹窗和状态驱动界面上更成熟，也符合 Tauri 官方常见组合。

### 新增独立的 `src-tauri` crate 并复用根 crate

`src-tauri` 依赖根目录的 `dy-screen` library。Tauri 层只实现数据库 repository、监听 supervisor、command、事件桥接和桌面生命周期；直播流解析和 FFmpeg 参数仍由根 crate 负责。

### 使用 SQLite repository 作为唯一持久化入口

SQLite 文件位于 Tauri app data 目录。第一版使用 `rusqlite` 和版本化迁移，repository 对前端暴露类型化 command，不允许前端直接执行 SQL。

主要表：

- `streamers`：名称、URL、room ID、监听开关、归档状态、直播/监听状态、检查时间和错误。
- `recording_sessions`：主播、开始/结束时间、状态、重试次数、输出位置和错误。
- `videos`：会话、文件路径、时间、时长、大小、音频和文件状态。
- `settings`：输出目录、轮询间隔、并发上限、分片时长、质量、协议、FFmpeg 路径、通知和开机启动。
- `schema_migrations`：迁移版本。

### 每个主播对应一个长期监听 worker

supervisor 在应用启动时读取所有已启用监听的主播，并确保每个主播最多只有一个 worker。worker 状态机为：

`paused → checking → waiting → recording → retrying/error`

未开播时每 30 秒检查一次。解析失败时按 30、60、120、300 秒退避，成功后恢复 30 秒。系统唤醒或网络恢复后触发一次去重后的立即检查。

### 开播自动创建逻辑会话并开始录制

检测到开播时创建一个逻辑 `recording_session`。FFmpeg 录制过程中产生的完成分片持续登记到该会话。主播下播、用户关闭监听或显式退出时，系统优雅停止并关闭会话。

录制异常时重新解析签名地址并在同一逻辑会话内最多重试 3 次；每次底层 recorder 可以创建独立输出子目录，但视频记录统一归属该会话。连续失败后保留完成分片、标记异常，并继续等待后续监听周期恢复。

### 用信号量限制全局并发录制

默认最大并发数为 4，可在设置页调整。直播中的主播超过上限时进入“等待录制资源”，获得 permit 后再次解析地址并启动录制，避免使用过期 URL。

### 将录制目录和数据库目录分离

数据库由应用管理；录像默认写入 `~/Downloads/dy-screen/`。修改输出根目录只影响新会话，不自动搬迁已有文件。视频路径使用绝对路径持久化。

### 以完成清单为视频可用性依据

录制期间增量监听 FFmpeg 的 `segments.csv`，发现新完成分片后立即去重、执行有界 FFprobe，并发送包含开始时间、结束时间、时长和音频状态的完成事件。FFmpeg 退出时执行最终扫描，保证最后一个已关闭分片不会遗漏。`partial_segments` 只记录为异常候选，不作为可播放视频。启动恢复时把遗留活动会话标记为异常中断，扫描完成清单；如果主播仍在线则创建新续录会话。

数据库事件桥只在视频幂等写入成功后确认完成事件并发布 `video_changed`；写入失败时 recorder 保留该分片为未确认状态并继续增量重试。逻辑会话结束和应用启动时还会对全部相关完成清单执行幂等对账，SQLite 连接设置忙等待时间，避免短时写锁竞争产生虚假的界面刷新或永久漏记。

### 以再次解析结果判定直播周期边界

FFmpeg 每次退出后都重新解析直播页。只有明确返回“房间未开播”才结束当前逻辑会话；房间仍在线或发生瞬时网络/页面解析错误时，均在同一会话内消耗最多 3 次续录预算。每次续录先执行可取消退避，再重新解析最新签名地址并立即启动 FFmpeg，不复用退避前的 URL。重新解析、等待重试和获取录制资源都监听同一个取消令牌，暂停监听、磁盘保护或应用退出可以立即打断流程。

### 使用全局期限执行应用退出

显式退出时先统一取消所有监听 worker、活动 recorder 和磁盘监控任务，再用一个全局截止时间并发等待全部任务结束。超过期限后终止剩余任务，并通过数据库对账关闭遗留活动会话，退出耗时不随主播数量线性增长。

### 添加主播前执行真实访问校验

表单提交后先规范化公开抖音直播间 URL，再调用 resolver 访问页面并提取页面中的 canonical room ID。成功解析表示房间有效且直播中；明确未开播时也从离线页面提取 canonical room ID 并视为有效房间；404、网络错误和不支持的页面结构均拒绝写入 SQLite，并只向前端返回脱敏中文错误。去重使用 canonical room ID，重新添加已归档的同一房间时恢复原主播记录和历史关联，而不是创建重复数据。

### 主窗口关闭与应用退出分离

关闭主窗口只隐藏窗口，托盘继续显示活动录制数。托盘提供打开窗口、暂停全部、恢复全部和退出。显式退出时若存在活动录制，前端或托盘流程请求确认；确认后触发共享取消并等待有界清理。

### 使用双状态模型驱动界面

直播状态独立为检查中、未开播、直播中、检查失败；监听状态独立为已暂停、等待开播、等待资源、录制中、正在重试、录制异常。SQLite 保存最近稳定状态，前端通过事件刷新，避免把“未开播”和“未监听”混淆。

### 使用渐进式资源保护

开始录制前检查输出磁盘可用空间：低于 10 GB 发出警告，低于 2 GB 不启动新录制，低于 1 GB 请求现有录制优雅停止。第一版阈值固定，后续再决定是否开放配置。

### 文件操作由 Rust command 执行

打开视频、在文件管理器中显示、删除视频或会话均通过类型化 command。删除整个会话时先把会话内视频标记为待清理，再把全部文件原子移动为同目录隔离名称；数据库事务提交失败时全部移回原路径并恢复状态，提交成功后再清理隔离文件。外部删除的文件在读取时标记为“文件缺失”。

### UI 采用方案 A 信息架构

左侧导航包含监控中心、视频库、AI 剪辑和设置；监控中心包含顶部摘要、主播表格和右侧本次会话详情；添加主播使用弹窗。AI 剪辑页面只显示规划说明。

## 风险/权衡

- [Tauri 2.0 插件或系统 API 在不同平台存在差异] → 第一版以 macOS 编译和运行验证为准，平台相关行为封装在 Tauri 层。
- [频繁检查触发限流] → 固定 30 秒基础周期、错误退避并加入少量调度抖动。
- [签名地址过期或网络抖动中断录制] → 每次启动/重试前重新解析，最多连续重试 3 次。
- [多个主播同时开播耗尽资源] → 全局信号量、明确等待状态和磁盘阈值。
- [SQLite 同步调用阻塞 Tokio] → repository 操作保持短事务，必要时使用 blocking task；不在数据库锁内执行网络或 FFmpeg。
- [应用崩溃导致状态与文件不一致] → 启动对账、完成清单、缺失状态和幂等迁移。
- [关闭窗口被误认为退出] → 首次关闭时提示已转入托盘，托盘始终提供显式退出。
- [本机缺少 FFmpeg] → 设置页和启动诊断显示可操作错误，录制任务不启动。

## 迁移计划

1. 将现有根 crate 保持为可独立测试的录制核心。
2. 创建 React/Vite 前端和 `src-tauri` crate。
3. 初始化 SQLite 迁移及 repository。
4. 实现监听 supervisor、录制事件落库和 Tauri command/event。
5. 实现监控中心、视频库、设置、托盘和 AI 占位页。
6. 在 macOS 上验证应用启动、窗口隐藏、托盘、自动恢复和真实直播录制。

回滚时删除前端、`src-tauri` 和对应 SQLite 文件即可；根录制 crate 和已有 CLI 不受影响。
