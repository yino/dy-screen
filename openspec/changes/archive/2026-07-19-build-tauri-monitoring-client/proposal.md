## 为什么

现有 Rust Demo 已验证公开抖音直播流解析和多房间音视频录制，但用户仍需通过命令行手动启动任务，无法长期管理主播、自动发现开播、在后台续录或浏览历史视频。本变更把已验证的录制核心升级为可日常使用的 Tauri 2.0 本地桌面客户端。

## 变更内容

- 创建 Tauri 2.0 + React/TypeScript 客户端，视觉参考 `examples/test.webp`，采用浅色背景、绿色主色、左侧导航、顶部摘要和主播监控表格。
- 提供“添加监控主播”表单，输入主播名称和公开抖音直播间链接；保存前校验 URL、解析 room ID 并阻止重复房间。
- 使用 SQLite 持久化主播、监听开关、状态、录制会话、视频分片、应用设置和数据库迁移版本。
- 为已开启监听的主播每 30 秒检查一次开播状态；检查失败使用 30/60/120/300 秒退避。
- 检测到开播后自动启动录制，下播后关闭本次会话；录制中断时重新解析直播地址并最多连续续录 3 次。
- 应用启动时自动恢复此前启用的监听；关闭主窗口后驻留系统托盘继续运行，显式退出时优雅停止录制。
- 主播表格分别展示直播状态和监听状态，并提供立即检查、暂停/恢复监听、停止录制、查看详情和归档操作。
- 提供本次监听视频列表和历史视频库，按“主播 → 录制会话 → MKV 分片”组织，并支持系统播放器打开、文件管理器定位和确认后删除。
- 录像默认保存到 `~/Downloads/dy-screen/`，设置页允许修改后续录像目录；SQLite 保存在 Tauri 应用数据目录。
- 提供系统通知、磁盘空间保护、托盘菜单、日志目录入口和可选开机启动设置。
- 预留可点击的 AI 剪辑页面，只展示规划说明，不创建任务或处理视频。
- 明确不实现登录自动化、验证码、DRM、付费/私有直播间绕过、应用内视频播放器、视频合并转码或 AI 剪辑。

## 能力

### 新增能力

- `streamer-monitoring`：管理主播监听记录、周期检查开播状态、自动开始/停止/重试录制，并在应用重启后恢复监听。
- `recording-library`：持久化录制会话和视频分片，展示本次与历史视频，并安全处理打开、定位、缺失和删除。
- `desktop-client-shell`：提供 Tauri 桌面界面、托盘后台运行、设置、通知、磁盘保护和 AI 剪辑占位入口。

### 修改能力

- 无。

## 影响

- 新增 React、TypeScript、Vite 和 Tauri 2.0 前端/桌面应用结构。
- 新增 Tauri Rust backend，并复用根 crate 中的 resolver、recorder、manager 和可序列化事件模型。
- 新增 SQLite 依赖和迁移，所有业务数据保持本地，不引入云服务或遥测。
- 新增托盘、系统通知、打开文件/目录和可选开机启动相关 Tauri 插件。
- 第一版优先支持 macOS；路径、SQLite 和进程接口保持 Windows/Linux 可迁移。
- 第一版继续使用本机 FFmpeg/FFprobe，并提供依赖诊断和路径设置；生产 sidecar 打包另行立项。
