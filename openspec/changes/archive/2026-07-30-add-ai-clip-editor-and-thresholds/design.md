## Context

AI 高光 Agent 已经能生成、评分和选择候选，但推荐规则固定为“前 10 条且 70 分以上”，不支持用户按内容目标调节密度。已选择候选仅停留在数据库选择集合，尚不能形成可编辑、可恢复和可导出的短视频。

项目已有 SQLite migration、受信 AI 项目输入、MP4 预览服务和受控 FFmpeg 进程调用。新设计必须复用这些安全边界：前端不能提交任意本地路径或 FFmpeg 参数，原始录像、预览缓存、ASR 产物和高光记录不可被编辑器覆盖。

## Goals / Non-Goals

**Goals:**

- 让用户在设置中定义 0–100 的合格与优秀阈值，默认 70/80；优秀候选自动进入已选择。
- 保留完整评分结果，不设推荐数量上限，并用合格阈值决定默认候选导航。
- 将已选择候选转换为可恢复的单轨剪辑工程；候选按来源时间排序首尾相接，并可重排、删除、调节音量和应用有限的内置动画/转场。
- 提供与主应用一致主题的独立编辑页面、时间轨道、播放器、素材库、属性面板、取消和进度明确的 MP4 导出。
- 用固定 FFmpeg 参数数组、安全滤镜模板和临时文件原子发布导出结果。

**Non-Goals:**

- 不支持任意本地素材、第三方插件、任意滤镜表达式、云端渲染或用户自定义 FFmpeg 参数。
- 不提供波形、多轨混音、关键帧、字幕烧录、文字编辑、任意裁剪、协作或无损拼接承诺。
- 不自动重试导出失败，不替换原始录像，也不把导出视频自动加入录制库。

## Decisions

### 1. 阈值属于非敏感 LLM 设置，并在运行创建时冻结

`LlmProviderSettings` 增加 `qualified_score`、`excellent_score`，均为整数 0–100，默认 70/80，并要求 `qualified_score <= excellent_score`。SQLite 的单行设置表保存当前默认值；`ai_highlight_runs` 同时保存这两个快照，并把它们纳入分析指纹。

这样同一运行的候选筛选、自动选择和缓存语义稳定；之后修改设置只影响新运行。替代方案是按当前全局设置实时重算旧运行的展示和选择，但会让历史项目在未执行任何动作时改变“已选择”结果，且使缓存指纹失真，因此不采用。

### 2. 所有评分候选均持久化，筛选发生在查询视图

全局评分阶段保存全部通过本地校验和去重的候选，不再按照分数或数量删除数据。默认高光导航仅返回总分大于等于运行快照 `qualified_score` 的候选；运行统计保留总候选数。初次最终评分发布时，总分大于等于 `excellent_score` 的候选自动标记 `selected=1`；已有运行重试时保留用户已确认的选择，避免覆盖人工调整。

替代方案是只持久化合格候选或限制查询前 10 条。前者会丢失审计和复评数据，后者再次造成用户要求移除的上限，因此不采用。

### 3. 一个高光运行对应一个可恢复的默认剪辑工程

新增 `ai_clip_projects` 和 `ai_clip_segments`。用户从“已选择”打开编辑器时，后端为该运行创建或返回唯一的默认工程；首次创建按候选源视频输入顺序、候选开始时间和稳定 ID 排序，将每个候选快照为一个时间轴片段。片段保留候选 ID、输入 ID、源内开始/结束时间、标题、音量、入出动画和转场值，工程保存输出尺寸与版本。

候选选择随后改变不会修改已经创建的工程；用户可明确重建工程。这样编辑项目不会因为返回高光页而丢失人工排序和属性。替代方案是每次进入编辑器从当前选择集合即时构建，无法保存编辑且会产生不可预期的导出内容，因此不采用。

### 4. 第一版采用可控单轨与内置效果白名单

编辑器使用一个顺序视频轨道，片段宽度按源内时长表示，播放头由工程时间映射到当前来源片段。左侧素材库只提供受支持的“无动画、淡入、淡出、淡入淡出、闪白转场、淡黑转场”；把素材应用到当前片段或两个片段边界。右侧属性面板编辑当前片段标题、音量 0–200%、入出动画和相邻转场。所有值由后端枚举校验。

这保留了参考页面的工作流与布局，同时避免让 UI 生成任意 FFmpeg 滤镜。多轨和外部素材需要另一套资产授权、时间重叠与渲染模型，留给后续变更。

编辑器以 `video_cut.html` 的桌面工作台为布局基准，但使用当前应用的绿色主题与 Lucide 图标。进入编辑器后由其覆盖主应用侧栏和顶栏；左侧效果以两列素材缩略块展示并支持分类、点击应用和拖放到片段，播放器使用受控播放栏，底部时间轴支持缩放、点击定位、插入位置拖拽重排与删除，右侧展示完整的片段时间和音量属性。参考页中的任意外部导入、虚构素材和未进入安全模型的按钮不得以不可用占位形式出现。

素材库同时提供“待切片视频”分类。它只读取当前高光运行已选择且尚未进入工程的候选；点击素材会追加到时间轴末尾，拖放到间隙会插入指定位置。后端必须重新校验候选所属运行、选择状态和工程内唯一性，前端不能提交来源路径或自行构造视频区间。动画与转场继续保存为视频片段的白名单效果；拖到间隙时明确应用到该间隙之后的视频片段，拖到末尾时应用到最后一个视频片段，从而保持导出模型可控且不伪造独立媒体。

### 5. 导出规范化为 H.264/AAC 并以临时文件发布

`ClipExportService` 从工程快照加载受信 AI 输入，重新检查文件、时长与来源指纹，在输出尺寸上把每段以 `trim`/`atrim`、`setpts`/`asetpts`、音量、白名单淡入淡出与转场滤镜规范化，再使用 `concat` 生成 H.264/AAC MP4。FFmpeg 通过参数数组启动；保存对话框仅决定 `.mp4` 目标文件，服务先写入同目录受控 `.part.mp4`，成功后原子重命名。进度、完成、失败和取消使用专用事件；取消或失败清理临时文件。

直接使用 concat demuxer 虽然更快，但要求编解码、时间基和参数完全一致，无法可靠支持 MKV、MP4、横竖视频、音量和动画，故不采用。导出过程不会自动重试，避免在用户取消、磁盘不足或目标文件被占用时生成意外文件；界面提供显式重试。

## Risks / Trade-offs

- [重新编码速度和磁盘占用高于无损拼接] → 导出显示阶段与百分比、允许取消、导出前检查目标目录可写与最小可用空间，保留源文件不受影响。
- [混合横竖视频可能产生黑边] → 输出尺寸以第一个工程片段探测的方向确定，其余片段等比缩放并居中填充；界面清晰显示输出规格。
- [候选数量很多会使导航缓慢] → 后端按阈值、分数和时间排序并分页，前端使用分页导航和单一候选详情，不一次展开全部文本。
- [高光候选或输入在工程后被删除] → 工程保存来源快照，导出前重新校验；缺失源片段显示稳定错误，允许用户移除后继续导出。
- [FFmpeg 或应用在导出中退出] → 任务带 cancellation token、临时输出和启动清理，不将未完成文件标记为成功。

## Migration Plan

1. 新 migration 为现有 LLM 设置补充默认 70/80 阈值，为历史高光运行补充同样的阈值快照，并创建剪辑工程表及索引。
2. 旧运行保留原候选和用户选择；其默认导航使用迁移后的 70 分快照，不自动改写已选择项。
3. 新代码发布后验证 migration 幂等、外键、旧项目读取和缺失源处理；失败时应用可安全回退到只读高光页，数据库中新表不影响既有 ASR、录制或预览功能。

## Open Questions

- 无。输出尺寸、素材范围、自动选择策略和失败处理已按推荐默认值固定；未来若要增加外部素材或多轨，将另起变更。
