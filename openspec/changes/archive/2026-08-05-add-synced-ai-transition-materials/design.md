## Context

当前客户端已经具备授权心跳、SQLite、DeepSeek 精彩分析、可恢复剪辑工程、原始片段预览和受控 FFmpeg 导出，但剪辑素材仍是本地固定枚举。服务端现已在心跳中发布 `transitionMaterials.catalogVersion` 与 `minimumAppVersion`，并通过 `GET /api/v1/transition-materials?clientVersion=<catalogVersion>` 返回带版本、描述、媒体元数据和 SHA-256 的全量素材目录。

首批目录包含 33 个 `renderMode=bridge` 的 MP4，其中既有 H.264 也有 HEVC，且均带原声。客户端既要让 LLM 根据相邻精彩的 ASR 语义匹配这些素材，也要允许用户在剪辑工作台搜索、预览和人工覆盖。目录更新、媒体下载、WebView 预览和最终 FFmpeg 导出具有不同失败边界，不能耦合到授权心跳或一次性执行。

该变更横跨授权生命周期、网络 API、本地存储、AI Provider、剪辑工程时间模型、前端工作台和 macOS/Windows 发行资源。激活码、设备 ID、下载 URL 和本地绝对路径必须留在 Rust 侧；发送给 LLM 的内容只包含必要的 ASR 上下文、主播标签和素材语义元数据。

## Goals / Non-Goals

**Goals:**

- 将桌面客户端版本统一升级到 `0.3.0`，并兼容服务端发布的最低客户端版本。
- 通过心跳发现目录变化，以独立任务事务化同步全量素材元数据，同时保持授权状态不受素材故障影响。
- 在 SQLite 中维护可离线查询的版本化素材目录，在应用数据目录按需下载、校验和缓存媒体。
- 使用当前 DeepSeek Provider 对相邻精彩片段与本地素材描述进行受限匹配，并支持置信度门槛、人工锁定和显式重新匹配。
- 在剪辑工作台把 `bridge` 素材作为独立时间轴单元插入片段边界，统一预览、字幕映射和 H.264/AAC MP4 导出结果。
- 在 macOS 和 Windows 上检查 FFmpeg 对 H.264、HEVC、AAC 和最终桥接导出的实际能力。

**Non-Goals:**

- 不支持用户导入本地素材、素材上传、素材商店或账号云同步。
- 不支持透明叠加、遮罩、画中画、`xfade` 或让 LLM 生成任意 FFmpeg 参数。
- 不在目录同步时下载全部视频，也不把二进制媒体保存到 SQLite。
- 不让 LLM 访问网络、文件系统、下载 URL、本地路径、Cookie、激活码、设备 ID、视频或音频。
- 不自动清理历史工程仍引用的素材版本，不在片段重排后自动产生额外 LLM 费用。

## Decisions

### 1. 心跳只发布版本信号，素材同步使用独立状态机

`HeartbeatResponse` 增加可选的 camelCase `transitionMaterials` DTO。成功心跳把 `catalogVersion` 和 `minimumAppVersion` 发布给单实例素材目录协调器；协调器自行去重、串行同步和退避。字段缺失继续使用本地目录，目录请求失败只更新素材同步状态，不得撤销激活、停止监听或改变心跳重试。

`minimumAppVersion` 使用语义版本比较。客户端版本低于要求时停止应用更新目录并展示升级提示，但保留已有本地目录和授权能力；版本满足后再同步。当前发行的 npm、Cargo、Tauri 配置及锁文件统一升级到 `0.3.0`。

替代方案是直接在 90 秒心跳任务中下载目录。该方案会让慢 CDN、SQLite 锁和目录解析拖慢续约，并混淆授权故障与素材故障，因此不采用。

### 2. 把 `clientVersion` 解释为本地目录版本

目录请求中的 `clientVersion` 传本地已提交的 `catalogVersion`，首次同步使用 `0`。`changed=false` 时保留本地事务快照，响应可以不携带 `materials`；`changed=true` 时必须携带完整目录，客户端校验完整响应后才在一个 SQLite 事务中发布新版本。响应版本倒退时不自动降级；版本相同的完整响应允许幂等重放。

该解释与服务端示例 `clientVersion=1 -> catalogVersion=2` 一致，也避免另增增量协议。替代方案是把应用版本传给该字段，但这无法表达目录缓存状态，并与心跳中的 `minimumAppVersion` 重复。

### 3. 元数据版本化保存，媒体文件按需缓存

SQLite 新增以下逻辑实体：

- `transition_catalog_state`：已提交目录版本、最后检查/成功时间、远端版本、同步状态和脱敏错误码。
- `transition_materials`：以 `(asset_key, asset_version)` 为稳定键，保存标题、描述、标签 JSON、分类、渲染模式、受信媒体引用、校验值、媒体属性、排序和当前目录可见状态。
- `transition_material_downloads`：保存源文件与预览缓存的 `missing/downloading/ready/failed` 状态、相对缓存路径、已校验大小、错误码和重试时间。
- `ai_clip_transition_boundaries`：以工程中相邻片段稳定 ID 定位边界，保存素材键与版本、选择来源、置信度、理由、人工锁和失效状态。
- `ai_transition_match_runs`：保存一次批量匹配的状态、Provider、输入摘要指纹和脱敏错误，便于恢复和诊断，不保存密钥或完整 Prompt。

全量同步先把响应解析到内存并校验唯一键、字段范围和 URL，再在事务中 upsert 新目录并把未出现版本标记为非当前。旧行和已下载文件继续保留，以保证历史工程固定引用 `(assetKey, assetVersion)` 后可复现。二进制保存到应用数据目录下的稳定相对路径，数据库和前端 DTO 不暴露任意绝对路径。

替代方案是覆盖单行最新版本或清空重建。前者会让历史工程静默变化，后者会破坏外键和离线导出，因此不采用。

### 4. 所有远程地址在 Rust 中建立信任边界

正式构建只允许 HTTPS。相对 `videoPath`、`previewPath` 和 `coverPath` 相对 `cdnBaseUrl` 解析；绝对 URL 的 scheme、host 和有效端口必须与 `cdnBaseUrl` 同源。开发构建仅允许显式配置的 localhost HTTP。拒绝凭据 URL、非 HTTP(S) scheme、路径穿越、缺少必要媒体字段、未知 `renderMode`、重复键和非法 SHA-256。

请求复用现有 `ApiClient` 的业务信封解析、超时、`device_id` 和 `activate_code` 请求头。激活信息只由 Rust 凭据存储读取，不传给 WebView。前端通过受限 Tauri command 获取目录 DTO 和预览句柄，不能提交任意下载 URL。

替代方案是信任服务端返回的所有绝对 URL或由前端直接下载。两者都会扩大 SSRF、凭据泄露和本地协议访问面，因此不采用。

### 5. 下载采用校验后原子发布，并对同一资源合并并发请求

LLM 高置信度选中、用户预览或手动应用素材时触发下载。下载器按 `(assetKey, assetVersion)` 合并并发请求，写入同目录临时文件，限制响应大小，完成后核对 `sizeBytes` 和 SHA-256，再原子改名为就绪文件。失败删除临时文件并保存稳定错误码，用户可显式重试；目录同步本身不等待媒体下载。

预览图缺失时使用文字占位；图片也走受信下载或受控协议。源视频是 HEVC 或 WebView 实际探测不兼容时，复用受控 FFmpeg 生成 H.264/AAC MP4 预览缓存。最终导出仍以已校验源文件为输入，不以降码率预览缓存为输入。

替代方案是启动时全库下载。当前目录虽小，但该行为会随素材增长放大启动延迟、磁盘占用和失败面，因此不采用。

### 6. Agent 只在本地目录候选中做结构化选择

匹配由用户显式启动，可按全部未锁边界批量执行，也可对单个边界重新执行。Rust 为每个边界截取前一片段尾部和后一片段头部的有界 ASR 文本，加入主播标签，并从当前本地目录选择有界数量的素材标题、描述、标签和分类发送给现有 DeepSeek Provider。素材候选可先用标签/文本相关性做确定性收窄；LLM 不拥有工具调用、网络或文件访问权限。

响应 schema 仅接受边界 ID、`assetKey`、`assetVersion`、`none`、`confidence` 和简短理由。Rust 再验证素材存在、版本当前且 `renderMode=bridge`。`confidence >= 0.75` 的合法结果写入自动选择并触发按需下载；低分结果保存为建议但不改变工程；`none` 明确保留无素材边界。解析或 Provider 失败不清除已有人工选择。

替代方案是给模型完整目录和任意渲染指令。该方案 Prompt 会持续膨胀，而且模型可能虚构资产或参数，因此不采用。

### 7. 人工选择优先，结构变化只做局部失效

用户手动应用或替换素材后设置 `manually_locked=true`；后续批量匹配不得覆盖。用户可主动移除并选择保留人工空值锁，也可解除锁后重新匹配。片段重排、插入或删除时，以相邻稳定片段 ID 重算边界：仍存在且邻接关系未变的选择保留，受影响的自动选择标记失效，人工选择若不再对应有效边界则保留审计记录但不参与工程。

系统不因结构变化自动调用 LLM；界面展示“需要重新匹配”并由用户确认，从而控制费用和避免编辑过程中的异步跳动。

替代方案是按数组位置保存转场或每次拖拽自动重跑。前者会把素材绑定到错误边界，后者不可预测且成本更高，因此不采用。

### 8. `bridge` 是独立时间轴单元，不复用片段效果字段

已就绪的 `renderMode=bridge` 素材完整插入左、右精彩片段之间，保留素材原声，默认音量 100%，并增加工程总时长。播放器时间映射由“来源片段区间”和“桥接素材区间”组成；进入桥接区间时播放素材本身，时间轴显示可选择的桥接块，右侧展示素材信息、替换和移除操作。

桥接区间不映射来源 ASR，也不显示或烧录来源字幕；后续片段的工程字幕时间整体顺延。现有单片段 `effect` 枚举继续独立存在。第一版不裁剪桥接素材、不修改其音量、不叠加字幕。

替代方案是把素材键塞进 `ai_clip_segments.effect`。现有字段是有限单片段效果，无法表达左右边界、版本固定和额外时长，因此采用独立边界表。

### 9. 预览和导出共享同一冻结工程计划

Rust 从工程版本生成有序计划：裁取原始精彩片段、插入已就绪桥接素材、规范化尺寸/帧率/像素格式/采样率、应用片段效果与音量、连接音视频并烧录保存版本的字幕。桥接素材保持宽高比，以工程画布进行 scale/pad；没有音轨的未来素材补静音，有音轨则保留。最终输出仍为 H.264/AAC MP4。

开始导出前冻结工程版本和边界素材版本，缺失、校验失败或仍在下载的素材会阻止导出并给出重试入口，而不是静默跳过。导出取消或失败沿用临时文件清理和原子发布语义。macOS/Windows 的 FFmpeg 资源审计增加 H.264、HEVC、AAC 解码以及 filter/concat/编码能力检查。

替代方案是预览与导出分别拼接。两套时间模型容易造成字幕漂移和最终成品不一致，因此共享 Rust 计划模型。

## Risks / Trade-offs

- [服务端目录错误会影响全部客户端] -> 完整响应先校验后事务发布，保留上一可用目录并记录脱敏错误。
- [绝对 CDN URL 将来跨域迁移] -> 当前按 `cdnBaseUrl` 同源校验；若需多 CDN，服务端应先扩展显式受信 origin 契约，再更新客户端规格。
- [HEVC 转码增加 CPU 和等待时间] -> 只在首次预览按需生成缓存，展示明确进度，最终导出复用原始已校验文件。
- [桥接素材原声造成响度突变] -> 第一版保留原声并规范化技术格式；响度归一化和素材音量编辑留给后续独立变更。
- [目录增长导致 LLM Prompt 过大] -> 本地确定性召回后只发送有界候选；模型输出仍由 Rust 对完整目录校验。
- [缓存长期增长] -> 当前优先保证历史工程可复现；后续可增加基于引用计数和磁盘预算的显式清理功能。
- [片段结构变化使 Agent 结果过期] -> 用稳定左右片段 ID 定位并局部失效，只有用户显式操作才重新调用 LLM。
- [服务端最低版本配置错误] -> 只门禁新目录同步，不撤销授权或删除现有目录，并在诊断中展示服务端要求与当前版本。

## Migration Plan

1. 新增向前迁移的 SQLite 表、索引和约束；既有工程默认没有边界素材，行为保持不变。
2. 扩展 API DTO 与心跳事件，先接入只读目录同步和诊断状态，不改变授权判定。
3. 将 npm、Cargo、Tauri 配置和锁文件版本统一升级为 `0.3.0`。
4. 接入按需下载、SHA-256 校验和 H.264 预览缓存，并在 macOS/Windows 发行检查中验证 FFmpeg 能力。
5. 接入受限 Agent、边界持久化和人工锁定，再扩展剪辑工作台、统一时间映射与导出计划。
6. 通过单元、repository、API 契约、前端交互和 FFmpeg 小样集成测试后发布。

回滚到旧客户端时，新表会被忽略，既有原始片段工程仍可读取；已经包含桥接边界的新工程不保证由旧版本正确表达，因此发布前必须备份 SQLite。新版本回滚功能时不得删除目录、下载缓存或边界表，恢复后可继续使用固定版本素材。

## Open Questions

无。跨 CDN 受信列表、桥接素材音量编辑、本地自定义素材、缓存配额和服务端增量同步均明确留待后续变更。
