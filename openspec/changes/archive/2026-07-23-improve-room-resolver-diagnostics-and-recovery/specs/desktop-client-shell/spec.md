## MODIFIED Requirements

### Requirement: 展示可操作主播表格
系统 SHALL 在表格中分别展示主播、来源类型、直播状态、监听/发现状态、最近检查时间、本次/历史视频数量和操作，并 SHALL 对已发现主页展示标准化直播入口；检查失败时 SHALL 直接展示脱敏中文错误摘要、连续失败次数和预计重试时间。

#### Scenario: 等待首次开播
- **WHEN** 个人主页主播尚未发现稳定直播入口
- **THEN** 表格显示“个人主页”和“等待首次开播”，直播间入口显示为尚未发现

#### Scenario: 已发现直播入口
- **WHEN** 个人主页主播已经保存稳定 `web_rid`
- **THEN** 表格或详情显示“已发现直播间”以及可打开的标准化 `live.douyin.com/{web_rid}` 地址

#### Scenario: 正在重新发现
- **WHEN** 已知直播入口连续明确失效并触发主页回查
- **THEN** 表格显示“重新发现直播间”，且不得错误显示为录制中

#### Scenario: 访问受限
- **WHEN** backend 返回 `access_restricted` 监听状态
- **THEN** 表格显示“访问受限”、脱敏中文错误、连续失败次数和预计重试时间，不显示“直播入口失效”

#### Scenario: 页面结构变化
- **WHEN** backend 返回 `layout_changed` 监听状态
- **THEN** 表格显示“页面结构变化”、脱敏中文错误、连续失败次数和预计重试时间，不显示“直播入口失效”

#### Scenario: 用户处理检查失败
- **WHEN** 主播存在直播间检查错误
- **THEN** 操作菜单提供立即检查、打开标准化直播间和打开日志目录；没有稳定直播入口时禁用打开直播间

#### Scenario: 状态发生变化
- **WHEN** backend 发送主播发现、合并、直播、检查或录制状态事件
- **THEN** 前端更新对应行和顶部摘要，合并事件定位到目标主播，而不重载整个应用

#### Scenario: 默认排序
- **WHEN** 表格展示多个状态的主播
- **THEN** 顺序为录制中、直播等待资源、正在发现、检查失败、等待首次开播、等待开播、已暂停，同状态按名称排序

### Requirement: 管理本地日志
系统 SHALL 让用户从设置页和主播错误操作菜单打开日志目录，并 SHALL 默认只保留最近 14 天按日期命名的应用日志。

#### Scenario: 清理过期日志
- **WHEN** 应用启动或跨过日期边界
- **THEN** 系统删除超过 14 天的应用日志，不删除录像或数据库

#### Scenario: 从错误主播打开日志
- **WHEN** 用户在检查失败主播的操作菜单选择“打开日志目录”
- **THEN** 系统打开与设置页相同的本地日志目录，不向外部服务上传日志

### Requirement: 保持数据本地和输出脱敏
系统 MUST NOT 上传主播、视频、设置、页面诊断或使用数据，并 MUST NOT 在日志、事件、界面错误或 CLI 诊断中暴露签名 URL 查询字符串、Cookie、页面正文或 React Flight 原始载荷。

#### Scenario: backend 返回直播流错误
- **WHEN** 错误与签名 CDN 地址有关
- **THEN** 前端只接收脱敏后的中文错误

#### Scenario: 用户运行直播间诊断
- **WHEN** CLI 完成公开直播间诊断
- **THEN** 输出仅包含允许的 HTTP 元信息、安全 marker、分类和脱敏错误
