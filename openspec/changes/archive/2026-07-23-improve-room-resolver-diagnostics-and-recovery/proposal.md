## Why

多个已有历史录像的直播间在同一时间被标记为“直播入口失效”，但实际错误只是当前页面无法按已有结构解析。现有实现把页面布局变化、平台访问限制、网络异常和真实入口失效合并成同一状态，既会误导用户，也可能错误清除可复用的稳定 `web_rid`，需要先恢复准确分类和可诊断性。

## What Changes

- 将直播间解析结果明确分类为正常直播、正常离线、访问受限、页面结构变化、暂时网络错误和明确入口失效。
- 仅在非法 URL、HTTP 404 或 410 等明确证据下标记入口失效；访问受限、布局变化和网络错误保留稳定 `web_rid` 并按可重试策略继续检查。
- 直播间解析复用个人主页已有的访问限制特征识别，避免验证码或风控页面被当成页面布局变化。
- 增加安全的直播间诊断命令，只输出 HTTP 状态、Content-Type、响应大小、脱敏特征和分类，不输出 HTML、Cookie 或签名流地址。
- 为后台检查增加结构化终端与滚动文件日志，记录主播、稳定入口、分类、连续失败次数和下次重试时间；普通日志保留 14 天。
- 在主播列表中直接展示中文错误摘要、连续失败次数和预计重试时间，并提供立即检查、打开直播间和打开日志操作。
- 只为具有脱敏 fixture 和自动化测试的页面格式增加解析支持，不根据未知线上载荷猜测字段。
- 不使用 Cookie、登录态、验证码绕过、WebView 抓包或其他访问控制规避方式。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `douyin-stream-discovery`：细化直播间页面获取和解析的安全分类，并增加脱敏诊断输出要求。
- `streamer-monitoring`：调整入口失效判定、稳定入口保留、失败计数和重试状态行为。
- `desktop-client-shell`：增加可操作的中文诊断展示、结构化日志和日志目录入口。

## Impact

- Rust 核心：`src/resolver.rs`、错误模型、CLI 诊断入口及相关 fixture/测试。
- Tauri 后端：监听 supervisor 状态机、DTO、日志初始化和诊断 command。
- React 客户端：主播状态类型、错误详情和快捷操作。
- SQLite：可能增加连续失败次数和下次重试时间字段，需要兼容现有数据库的幂等 migration。
- Makefile 与 README：补充安全诊断命令和日志排查说明。
- 非目标：本变更不绕过平台访问控制，不保证解析平台尚未提供脱敏 fixture 的新页面格式，也不修改录制、预览、ASR 或 AI 切片流程。
