## 为什么

计划中的 Tauri 2.0 桌面客户端需要先证明多个抖音直播间可以被可靠录制，之后才值得继续设计 ASR、基于 NLP 的高光识别和自动切片。本变更优先验证风险最高的基础能力：解析短期有效的公开直播流地址，并在保留视频和声音的情况下并发录制多个直播间。

## 变更内容

- 新增可由 Tauri 2.0 后端直接调用的 Rust 录制核心。
- 新增可在一次运行中接收多个抖音直播间 URL 的 CLI Demo。
- 从公开直播页初始化数据中解析每个房间的签名 FLV/HLS 地址，并暴露可用清晰度。
- 每个房间启动并监督一个独立 FFmpeg 进程，以不转码方式保存包含原始视频和声音的可恢复 MKV 分片。
- 隔离单房间故障，使下播、签名过期或页面异常的房间不会停止其他录制任务。
- 输出适合未来 Tauri event 桥接和下游 ASR 队列使用的结构化任务及分片信息。
- 记录本地依赖、Demo 使用方式、输出结构和已知平台限制。
- 明确推迟 ASR、NLP 分析、高光评分、语义切片和桌面 UI，直到录制可行性得到验证。

## 能力

### 新增能力

- `douyin-stream-discovery`：将公开抖音直播页解析为当前有效的签名 FLV/HLS 直播流和清晰度元数据。
- `multi-room-recording`：并发管理多个 FFmpeg 录制任务，持久化可恢复的音视频分片，并输出结构化状态。

### 修改能力

- 无。

## 影响

- 新增包含可复用 library 模块和 CLI 适配层的 Rust crate；library 边界面向后续 `src-tauri` 集成设计。
- 新增异步 HTTP、JSON 解析、CLI 参数、错误处理、序列化以及任务/进程监督相关 Rust 依赖。
- 构建需要 Rust/Cargo，录制需要 FFmpeg；生产版 Tauri 打包还需要针对各平台设计 FFmpeg sidecar。
- 仅向用户提供的公开抖音直播页及页面返回的 CDN 直播流地址发起网络请求。
- 不绕过登录、验证码、DRM、付费墙、私有房间权限、地域限制或其他访问控制。
