## 背景

本仓库在变更开始时还没有应用代码。目标产品是一个 Tauri 2.0 桌面客户端，最终需要同时录制多个直播间、保留回放、提取音频进行 ASR、分析转写文本寻找高光，并自动生成视频切片。早期页面检查确认，抖音浏览器播放器使用 Media Source Extensions；但 React Flight 初始化载荷仍包含 `FULL_HD1`、`HD1`、`SD1` 和 `SD2` 对应的签名 FLV/HLS 地址。这些地址会过期，因此必须在开始录制前即时解析。

第一阶段需要回答：能否在不进行高成本屏幕捕获的情况下，同时录制多个公开直播间并保留其原始视频和声音。因此实现需要一个兼容 Tauri 的 Rust 核心、一个简单 CLI 验证入口，以及可靠的 FFmpeg 进程监督。桌面 UI 和内容分析管线明确延后。

## 目标/非目标

**目标：**

- 从公开抖音直播间 URL 解析当前有效的签名直播流。
- 并发录制多个直播间，并隔离逐房间故障。
- 不转码地保留源视频和声音。
- 生成可恢复、有时间边界、适合后续 ASR 和切片的 MKV 分片。
- 让领域逻辑独立于 CLI，以便用最小改动迁入 Tauri `src-tauri` crate。
- 暴露可序列化的任务结果和状态事件，供未来 Tauri event 桥接层转发给前端。

**非目标：**

- 浏览器窗口捕获、弹幕、礼物和其他渲染后的页面 UI。
- 登录自动化、验证码处理、DRM 或访问控制绕过。
- ASR、NLP 分析、高光评分、切片生成或持久化任务数据库。
- 生产级断点恢复、调度器或跨平台 FFmpeg 打包。
- 在本次验证变更中创建 Tauri 前端。

## 技术决策

### 使用可复用 Rust library 加 CLI 适配层

crate 对外提供 resolver、recorder、manager、model 和 error 模块。`main.rs` 只解析 CLI 参数，并把 library 事件转换为人类可读输出或 JSON-lines。这样，主要逻辑可以直接复用于 Tauri command 和 managed state。

替代方案：先编写 Python 原型。Python 更容易快速验证，但会引入第二运行时；构建 Tauri 应用时仍需重写录制核心或把 Python 作为额外 sidecar 管理。

### 从公开页面初始化载荷解析直播流

resolver 使用普通桌面 User-Agent 请求用户提供的 `live.douyin.com` 地址，检查包含 `self.__pace_f.push(...)` 的内联脚本，对其中的 React Flight 字符串进行 JSON 解码，递归定位包含 `stream_url` 的房间对象，再把 FLV/HLS 清晰度映射规范化为类型模型。resolver 在发起录制请求前拒绝非抖音直播域名；找不到可用流时返回明确的下播错误或页面结构变更错误。

替代方案：录制 `<video>` 元素或依赖其 `src`。页面检查发现活动元素没有可用 `src`，因为播放由 Media Source Extensions 驱动。

替代方案：调用私有或逆向的房间 API。公开页面载荷已经足以完成可行性验证，也避免 Demo 依赖未公开的签名请求流程。

### 优先 FLV，并允许回退到 HLS

对于选定清晰度，selector 默认优先 FLV，因为它是可由 FFmpeg 直接复制的连续低延迟直播流。HLS 作为回退。清晰度选择保持确定性：先选择用户请求的清晰度，其次选择页面默认清晰度，最后选择已知最高的可用清晰度。

### 将媒体处理委托给 FFmpeg

Rust 只监督 FFmpeg，不自行解码媒体。FFmpeg 通过独立参数接收选定 URL，并携带抖音 Referer 和 User-Agent 请求头；它映射第一路视频和可选的第一路音频，使用 `-c copy`，输出带时间戳的 MKV 分片。命令不通过 shell 构造，避免参数注入。

替代方案：使用 Rust 媒体 crate。该方案会显著扩大编解码器和容器处理范围，在本次可行性验证中也不如 FFmpeg 成熟。

### 每个直播间使用独立异步任务

manager 为每个房间创建一个 Tokio 任务和一个 FFmpeg 子进程。单个任务失败只写入自己的结果，不取消其他任务。任一任务失败时 CLI 最终返回非零退出码，但仍输出所有房间的结果。共享取消信号先请求 FFmpeg 优雅退出，经过有界等待后才强制终止。

### 使用分片 MKV 作为录制产物契约

Demo 默认输出有界 MKV 分片，而不是单个 MP4。MKV 对异常中断更有恢复能力；分片能限制崩溃时的损失，每个正确关闭的分片也天然成为未来的 ASR 工作项。输出层级为 `<output>/<room-id>/<session-id>/<timestamp>.mkv`。

`segments.csv` 作为完成分片清单。只有进入清单的文件才放入 `segments`；异常退出时未完成的 MKV 放入 `partial_segments`。FFprobe 对完成分片进行有超时限制的音频轨道检查。

### 保持事件和结果模型可序列化

任务状态、选定清晰度/协议、输出目录、完成分片路径、音频状态和错误使用兼容 Serde 的模型。未来 Tauri command 可以把 manager 放入应用状态，并使用 `AppHandle::emit` 转发相同事件，无需修改 resolver 或 recorder 内部逻辑。

### 对签名地址执行端到端脱敏

签名 CDN URL 的查询字符串不能出现在普通日志、类型化错误、生命周期事件、JSON 结果或 Debug 输出中。FFmpeg 子进程仍接收完整 URL，但对外模型只暴露移除查询参数后的 endpoint。

## 风险/权衡

- [抖音修改 React Flight 载荷] → 将解析逻辑隔离在 `StreamResolver` 后，维护脱敏 fixture；无法识别时返回页面结构变更错误，不静默选择错误数据。
- [签名 URL 在 FFmpeg 启动前或录制中失效] → 在 spawn 前即时解析；自动重新解析和重启延后到初始录制验证通过之后。
- [直播流要求 Cookie 或地域权限] → 报告访问失败；Demo 不自动登录或绕过限制。
- [FFmpeg 缺失或不支持所需协议] → 在开始任务前检查可执行文件，并输出可操作的前置依赖错误。
- [并发直播间过多导致带宽、文件描述符或磁盘耗尽] → 保持任务隔离并暴露分片时长和输出路径；并发限制与磁盘配额延后到产品阶段。
- [直接复制直播流时出现编解码器/容器边界问题] → 录制阶段使用 MKV，将重封装和转码留给后处理管线。
- [FFmpeg sidecar 增加 Tauri 包体积和许可证义务] → Demo 允许配置可执行文件路径；在生产打包前确定分发来源和许可证策略。
- [人工取消返回非零退出码] → 保留“未自然完成”的准确语义，同时保证已完成分片优雅收尾并在结果中清晰列出。

## 迁移计划

1. 在 macOS 上通过 CLI 验证直播流解析和多房间录制。
2. 将 library crate 移入未来 Tauri workspace，或作为 workspace member 引用。
3. 使用 Tauri command 包装 `RecordingManager`，并把可序列化状态事件转发到前端。
4. 只有在录制可靠性验收后才添加持久化任务和 session 元数据。
5. 将完成的 MKV 分片投入单独定义的 ASR 管线。

回滚时删除新增 Rust crate 和本 OpenSpec change 即可；本 Demo 不迁移现有 API 或用户数据。
