## Context

视频库当前按 50 条分页读取 SQLite 元数据，卡片封面区域只展示统一图标。应用已有 `PreviewService`，它按用户点击为单个 MKV/MP4 准备可播放 MP4，并管理 10 GB 预览缓存；该服务可能执行完整重封装或转码，不适合在列表加载时为整页视频调用。

本变更需要跨越视频库查询、FFmpeg 子进程、Tauri 缓存与 asset scope、删除生命周期和 React 卡片状态。缩略图是可再生展示资源，不属于录像、预览媒体或 ASR 输入，必须保持独立，且不能让 50 条分页查询被媒体处理阻塞。

## Goals / Non-Goals

**Goals:**

- 为视频库当前分页中的已完成视频异步生成并展示真实首帧封面。
- 缓存可复用的 JPEG，并在源版本变化、视频删除、会话删除和容量清理时正确失效。
- 限制 FFmpeg 并发、去重同源任务、取消已翻页批次中尚未开始的任务。
- 只向 WebView 暴露后端验证过的精确缩略图文件。
- 失败或文件缺失时保持列表布局稳定，并允许一次显式重试。

**Non-Goals:**

- 不修改本次监听视频的紧凑列表。
- 不生成动态封面、智能选帧、黑帧检测、会话合成封面或用户自定义封面。
- 不因生成封面创建完整 MP4 预览缓存，也不修改原始录像。
- 不在应用启动时批量处理全部历史视频，不把图片二进制或缓存绝对路径写入 SQLite。
- 浏览器演示模式不读取本地媒体，只展示占位状态。

## Decisions

### 1. 使用独立的 `ThumbnailService`

在 Tauri 后端建立独立缩略图服务，负责批次兴趣、任务去重、FFmpeg 执行、状态事件、缓存和退出清理。纯数据模型、缓存键和 FFmpeg 参数构造保持为可单测的 Rust 逻辑，Tauri command 只负责数据库授权和 WebView 资源授权。

不直接复用 `PreviewService` 的任务，因为预览可能对完整视频执行重封装或转码，成本和状态模型都远高于单帧提取；也不把封面生成放进 `list_videos`，避免只读列表查询产生长时间副作用。

### 2. 当前分页通过批次接口表达兴趣

前端取得视频库当前页后调用批量请求接口，后端返回批次 ID 和每个视频的 `queued`、`ready`、`failed` 或 `unavailable` 状态。缓存命中同步进入 `ready`；未命中任务由事件更新。翻页、筛选变化或离开视频库时，前端释放旧批次；没有其他批次引用的排队任务被取消，已经运行的轻量提取允许完成并缓存。

同一视频源版本的请求共享缓存键和任务。缩略图服务使用独立 semaphore，把 FFmpeg 提取并发限制为 2；该限制不改变录制和完整视频预览的并发配置。

### 3. 从受信媒体提取第一个可解码帧

后端只接受数据库中已登记、状态为完成或外部缺失的 MKV/MP4 视频 ID。原文件是常规文件时优先使用原文件；原文件缺失时，只允许使用 `PreviewService` 已有且仍有效的 MP4 缓存，禁止为了封面触发预览生成。

FFmpeg 首次从视频起点解码第一帧；命令成功但没有发布有效 JPEG，或起点解码失败时，只在第 1 秒重试一次。输出自动应用媒体旋转信息，保留画面比例，把最长边限制为 480px，并编码为 JPEG。该策略忠于“第一帧”要求，同时为起点时间戳异常提供有限恢复，不扩展为智能选帧。

所有 FFmpeg 参数使用参数数组传递。输出先写入 `.part.jpg`，完成后验证为非空、尺寸有效且最长边不超过配置，再原子重命名；日志不得包含完整用户路径或 FFmpeg 原始 stderr。

### 4. 使用独立、可再生的缩略图缓存

缓存位于 `app_cache_dir()/video-thumbnails/`。缓存键包含视频 ID、规范源路径、文件大小、修改时间、来源类型和缩略图配置版本；JPEG 配套 JSON sidecar，记录源指纹、生成时间、最后访问时间和尺寸。源文件变化或由原文件切换到预览缓存时会生成新键。

缓存启动时及新批次准备前清理 `.part`、损坏清单和孤立 JPEG；超过 30 天未访问的条目被删除，并按最久未使用顺序把总量限制在 512 MB。清理和发布共享同步边界，不删除正在生成或当前批次正在展示的文件。

不使用数据库 migration。旧视频按分页访问懒生成；回滚代码时遗留缓存可由后续版本或用户缓存清理安全删除。

### 5. 精确授权图片而不是扩大文件系统范围

缩略图 command 根据视频 ID 查库并由服务返回已验证缓存路径，随后只把该精确 JPEG 加入 Tauri asset scope。前端不能提交源路径或缓存路径。批次释放后无需立即撤销已授权路径，但文件删除、缓存淘汰或应用退出后资源必须不可再读取。

### 6. 封面状态独立于视频可用性

React 以视频 ID 维护当前页缩略图状态。固定 16:9 封面区始终占位；JPEG 保留原始比例，使用 `object-fit: cover` 居中裁切。`ready` 时封面是调用既有预览动作的按钮；`queued` 显示加载占位；`failed` 显示占位和图标重试；`unavailable` 仅显示缺失占位。

缩略图失败不得改变视频 `status`，不得禁用已有预览、系统打开、定位或删除操作。浏览器演示 API 返回 `unavailable` 占位，不伪造本地首帧。

### 7. 删除与退出采用取消后清理

删除单个视频或整个会话前，先为相关视频设置驱逐标记、释放批次兴趣并取消任务；持有缓存发布锁完成删除后再解除。任务在发布 JPEG 前必须再次确认未被驱逐，防止删除后重新生成缓存。

如果原始文件或数据库删除失败并回滚业务状态，已有缩略图缓存保持可用；只有业务删除提交成功后才最终清理缩略图。应用显式退出时取消所有缩略图 FFmpeg、等待子进程回收，并由下次启动清理未发布临时文件。

## Risks / Trade-offs

- [首帧可能是黑画面或转场] → 按已确认范围不做内容分析；只在解码失败时回退第 1 秒，并保留未来增加智能选帧的配置版本边界。
- [首次打开包含 50 个旧视频的页面时出现渐进加载] → 列表先渲染占位，任务并发限制为 2，缓存后再次打开立即命中。
- [缩略图与完整预览同时使用 FFmpeg] → 缩略图只解码单帧并限制独立并发；错误和退出路径必须及时终止子进程。
- [预览缓存被清理导致缺失原文件无法重新生成封面] → 已生成的缩略图独立保留；只有缩略图也失效时回到不可用占位，不主动重建预览。
- [本地路径通过图片资源泄露] → 前端只提交视频 ID，后端验证精确缓存文件并使用受限 asset scope，错误和事件仅返回脱敏信息。
- [删除与异步发布竞态] → 使用驱逐标记、任务取消和统一发布锁，发布前二次校验视频仍存在。

## Migration Plan

1. 引入缩略图模型、缓存和执行器，但暂不从 UI 请求。
2. 接入 Tauri 批次 command、事件、精确 asset 授权、退出与删除生命周期。
3. 更新前端类型和视频库卡片，按当前页请求并在卸载时释放批次。
4. 通过真实 MKV/MP4 样本验证横屏、竖屏、起点失败回退、缺失源文件和缓存淘汰。
5. 发布后不做历史数据迁移；用户浏览视频库时逐步生成。回滚时删除或忽略 `video-thumbnails` 缓存目录即可，数据库和录像不受影响。
