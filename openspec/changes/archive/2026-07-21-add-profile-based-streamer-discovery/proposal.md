## Why

当前客户端只能添加已经知道 `live.douyin.com/{web_rid}` 的直播间链接，无法仅凭主播个人主页建立长期监听。用户往往更容易获得稳定的个人主页地址，而且主播未开播时主页不会提供可直接使用的直播入口，因此需要支持“先保存主页、等待首次开播、发现并持久化直播入口”的流程。

## What Changes

- 添加主播和编辑主播时同时接受公开抖音个人主页 URL 与现有公开直播间 URL，保持直播间直连方式向后兼容。
- 对个人主页解析 React Flight/内嵌结构化数据，识别 `profile_sec_uid`、主页昵称、当前 `roomIdStr`、稳定 `web_rid` 和直播入口；“直播中”或“正在直播”文本仅作为辅助信号。
- 允许未开播个人主页在没有直播间 ID 时先写入 SQLite，进入“等待首次开播”状态，并按独立周期和退避策略持续发现直播入口。
- 首次发现直播后持久化稳定 `web_rid` 和标准化直播间 URL，立即复用现有直播流解析、并发录制和续录逻辑；后续正常检查直接访问直播间。
- 当已发现的直播入口连续出现结构不支持、404 或入口失效时，回退个人主页重新发现；正常未开播不触发主页回查。
- 引入个人主页、稳定直播入口和当前直播场次三层身份，调整唯一性与重复记录处理，兼容迁移现有直播间来源主播。
- 增加等待发现、正在发现、已发现和重新发现等监听状态与中文错误反馈。
- 非目标：不引入浏览器自动化、Cookie 导入、账号登录、验证码处理、私密/付费直播访问或任何风控绕过。

## Capabilities

### New Capabilities
- `profile-live-discovery`: 定义公开抖音个人主页校验、结构化直播入口发现、身份提取、等待轮询、入口失效回退和安全错误处理。

### Modified Capabilities
- `streamer-monitoring`: 允许尚未发现直播间的个人主页主播持久化和恢复监听，并更新身份去重、状态机、轮询、迁移及冲突处理要求。
- `douyin-stream-discovery`: 扩展支持的公开 URL 和发现流程，使个人主页发现结果能够规范化为现有直播间解析输入，同时保持直播流解析边界不变。
- `desktop-client-shell`: 将添加/编辑表单扩展为个人主页或直播间链接，并展示个人主页发现阶段和已绑定直播入口。

## Impact

- Rust 核心 resolver 将增加独立的个人主页 URL 校验、React Flight 载荷解析与直播身份模型，同时复用现有 HTTP 客户端、错误脱敏和直播间解析器。
- Tauri domain、SQLite migration、repository、create/update command 和 supervisor worker 状态机需要支持尚未发现直播入口的主播记录。
- `streamers` 身份模型将新增来源类型、来源 URL、`profile_sec_uid`、稳定 `web_rid` 与可更新的当前 `room_id`；现有数据迁移为直播间来源且不重新联网校验。
- React 表单、类型、浏览器演示 API、主播表格状态标签和测试样例需要同步更新。
- 未发现主页按 60 秒加随机抖动轮询，网络/风控错误按 60、120、300 秒退避；发现直播入口后继续使用现有 30 秒直播间检查周期。
- 不改变 FFmpeg 录制、分片登记、视频预览、ASR/NLP 规划和原始录像目录结构。
