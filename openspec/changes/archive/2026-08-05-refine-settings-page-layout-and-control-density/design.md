## Context

设置页当前由 `SettingsPage` 在一个 `<form>` 内顺序渲染六张卡片，`.settings-layout` 使用两列 CSS Grid。Grid 的隐式行会由同行最高卡片决定高度，因此“桌面行为”等高卡片会在另一列下方制造大片空白。页面同时混用 8-11px 说明文字、10px 标签、39-42px 表单控件和多套按钮规则，英文栏目提示还使用 1.6px 字间距；这些数值在截图对应的 1703-1904px 桌面窗口中仍显得过密且难读。

普通设置由外层表单统一保存，高光分析 Provider 则使用独立 API、Key 凭据和操作按钮。布局调整必须保持这两套提交语义隔离。项目中另有活动变更 `add-synced-ai-transition-materials`，实现时不得修改或覆盖其 OpenSpec 产物，并应在触碰共享 `App.tsx`、`styles.css` 时基于当时工作区合并。

## Goals / Non-Goals

**Goals:**

- 提高设置页文字、表单和操作的可读性与尺寸一致性。
- 消除两列卡片因共享网格行产生的垂直空白，并限制超宽窗口中的内容行长。
- 在 1920x1080、1440x900、1280x800 和 1024x768 下提供稳定的双列或单列布局。
- 为普通设置增加可靠的脏状态、保存中和结果反馈，同时保持 Provider 独立操作。
- 让长说明、错误、深色主题和系统字体放大都能自然重排而不重叠。

**Non-Goals:**

- 不改变设置字段、后端 API、SQLite、授权协议、录制调度或 Provider 数据模型。
- 不重构监控中心、视频库和 AI 剪辑工作区的信息架构。
- 不引入新 UI 框架、字体包、布局依赖或新的主题体系。
- 不用本次变更统一专业高密度编辑器中的全部专用控件。

## Decisions

### 1. 使用两个显式列容器，而不是单个行网格

`SettingsPage` 将渲染一个有界的 `.settings-layout`，内部包含 `.settings-column` 左右两个垂直栈。左列依次放置录像设置、桌面行为、抖音访问会话；右列依次放置运行环境、客户端授权、高光分析 Provider。每列使用自身的 `display: grid` 或纵向 flex 和统一间距，卡片高度只影响本列。

选择显式列容器，是因为它能直接消除 Grid 同行高度耦合，并提供确定的 DOM、键盘和屏幕阅读器顺序。未采用 CSS multi-column 或 masonry：前者会产生不稳定的阅读/焦点顺序，后者兼容性和可测试性不足。窄屏时两列容器变为单列，顺序为完整左列后完整右列，与用户确认的逻辑分组一致。

### 2. 内容宽度受限并以可用内容宽度触发单列

设置页主体使用约 1440px 的 `max-width` 并居中，保留现有页面外边距。双列使用接近等宽的 `minmax(0, 1fr)`，间距保持 16-20px；在窗口约 1180px 以下或等效可用内容宽度不足时变为单列。最终断点以 1024x768 无横向页面滚动、1280x800 可读为验收依据，而不是通过视口宽度缩放字体。

未选择始终单列，因为宽屏会形成过长页面并降低跨组扫描效率；未允许内容无限拉伸，因为长输入和说明行会损害可读性。

### 3. 用少量共享尺寸变量统一基础控件

在现有 CSS 变量中增加语义化文字和控件尺寸，例如正文 13px、辅助文字 11-12px、标签 12px、卡片标题 17px、输入/选择器 44px、普通按钮 40px、紧凑按钮 36px、图标按钮 36px。设置页和共享 `.primary-button`、`.secondary-button`、`.ghost-button` 使用这些变量；专业编辑器和数据表格的专用密度规则不做机械覆盖。

所有 `letter-spacing` 统一为 0，包括品牌文字、页面标题、栏目提示和表头。层级改由字重、色彩、行高和间距表达。字体大小不随视口宽度缩放，长文字允许换行，固定格式控件通过 `min-height`、网格轨道和响应式约束保持稳定。

未采用全局百分比放大，因为它会同时放大高密度表格和编辑器，造成不可控回归；本次先校正共享命令控件及设置页文字体系。

### 4. 保持命令语义并统一操作外观

主操作、次操作和危险操作复用稳定的高度、内边距和图标尺寸。`重新激活`、`清除抖音会话` 在宽屏作为内容宽度命令放入可换行操作组，不再通过 grid-column 强制铺满；在窄屏操作组切为单列并全宽。已有图标继续使用 Lucide，熟悉的纯图标命令保留可访问名称和提示。

Provider 的保存、测试连接、清除 Key 仍为 `type="button"` 并使用自身反馈，不加入普通设置提交。这样避免视觉重构改变安全敏感的 Key 生命周期。

### 5. 普通设置保存栏由表单脏状态驱动

`SettingsPage` 比较当前 `form` 与最近一次 `settings` 快照来计算 dirty；外部设置刷新时同步基线，但不得在用户保存失败时丢弃本地输入。`onSave` 调整为可等待的 Promise 或等价结果通道，使页面能表示 `pristine`、`dirty`、`saving`、`saved` 和 `error`。保存中禁用重复提交，成功后更新基线并短暂显示成功状态，失败保留 dirty 和输入。

保存栏保持吸附但降低高度、圆角和阴影，设置页增加足够底部滚动留白，使最后一张卡片能完整滚动到保存栏上方。未选择彻底隐藏保存栏，因为固定位置能让长页面始终有明确提交入口；pristine 状态只降低强调并禁用按钮。

### 6. 用行为测试和多视口截图共同验收

React 测试覆盖卡片分组、所有既有字段、普通设置脏状态与保存状态、Provider 操作隔离、危险命令类型和窄屏可访问结构。浏览器演示模式使用 Playwright 或等效截图验证四个目标视口、浅色/深色、长错误文本与字体放大；同时检查正文和控件计算样式、页面横向溢出、卡片/保存栏重叠以及主要操作可见性。

单靠快照测试不能证明真实布局，因此视觉验收必须读取元素边界和截图；单靠截图也不能证明提交语义，因此保留组件行为测试。

## Risks / Trade-offs

- [共享按钮尺寸变化可能影响其他页面] → 只调整公共命令按钮族，逐页运行现有测试并在主要页面做桌面/窄屏截图；专用编辑器控件继续使用局部规则。
- [两个列容器在单列时形成左列全部在前、右列全部在后] → 该顺序与确认的业务分组一致，并通过标题和稳定 DOM 顺序保证键盘导航可预测。
- [字体增大使卡片变高、页面滚动增加] → 通过内容宽度、独立列栈、合理行高和紧凑标题区换取可读性，不以缩小文字压缩高度。
- [外部 settings 刷新可能覆盖未保存输入] → 只有在表单 pristine 或成功保存后更新本地基线；dirty 时保留用户输入并提示状态。
- [当前活动变更同时修改共享前端文件] → 实施前检查 `git status` 和相关差异，只合并本变更需要的结构与样式，不回退或重写其他变更。

## Migration Plan

1. 先补充设置页行为测试与视觉验收脚本，记录当前失败基线。
2. 引入尺寸变量和零字间距规则，限制作用域并验证其他主要页面。
3. 将设置卡片重组为左右列容器，加入内容宽度、断点和长内容约束。
4. 增加普通设置脏状态和异步保存反馈，保持 Provider 独立操作。
5. 完成四档视口、浅色/深色、长错误和字体放大验收后提交。

回滚时可恢复原单个 `.settings-layout` 子级结构和保存栏状态逻辑；本变更没有数据库、接口或持久化迁移，回滚不会损失用户设置。
