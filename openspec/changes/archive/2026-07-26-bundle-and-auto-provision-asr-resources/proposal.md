## Why

当前普通 Tauri 构建不会携带 FFmpeg、FFprobe、Whisper、VAD 和模型资源，完整 ASR 构建又依赖开发机上未纳入 Git 的本地资源目录；用户拿到应用后无法判断缺少哪些组件，也没有统一的下载、校验和修复入口。需要把运行资源整理为可版本化、可验证的资源包，并由用户提供的 HTTPS 地址托管，使安装包和首次启动流程都能可靠准备运行环境。

## What Changes

- 新增版本化运行资源包清单，统一描述平台、架构、组件、版本、大小、SHA-256、许可证和下载地址。
- 将录制/预览/封面所需的 FFmpeg、FFprobe，与 Whisper sidecar、VAD sidecar、ASR 模型、VAD 模型、规范化字典和 Windows 运行库纳入资源包管理，避免开发机路径成为发行依赖。
- 构建正式 macOS arm64 和 Windows x64 安装包时，支持把当前平台资源完整打入安装包；资源缺失或损坏时不能生成可用发行包。
- 应用启动时先检查本机资源状态；资源未安装、版本过期或完整性校验失败时，阻止进入主功能界面和任务执行。
- 增加用户确认后的 HTTPS 下载、断点续传、取消、重试、进度展示、临时文件隔离和原子安装流程，下载完成后自动重新诊断。
- 下载资源保存到应用数据目录，不修改安装目录，不允许前端配置任意可执行文件路径；资源包通过固定 manifest 和哈希校验防止篡改。
- 将资源服务器地址、发行频道和资源版本作为可配置发行参数，支持用户后续提供自有 CDN/对象存储地址，不把临时地址写死在业务代码中。
- **BREAKING** 启动资源未准备完成前，直播监听、录制、视频库和 AI 剪辑均不可使用；资源准备失败时只能进入资源修复界面。
- 明确非目标：本次不实现通用动态插件扫描、第三方插件市场、任意模型导入、多模型切换或绕过资源校验的开发者开关。

## Capabilities

### New Capabilities

- `runtime-resource-provisioning`: 负责资源清单、下载、断点续传、完整性校验、安装、升级、回滚、启动门禁和资源诊断。
- `release-resource-bundling`: 负责 macOS arm64、Windows x64 发行包中的平台资源收集、许可证封存、安装器映射和离线验收。

### Modified Capabilities

- `desktop-client-shell`: 启动流程增加强制资源准备门禁、下载进度和修复界面；资源未就绪时不开放主功能。
- `local-speech-transcription`: ASR 资源从“仅随包提供”扩展为“随包优先、缺失时从受信地址下载后安装”，识别前仍必须执行版本、大小、哈希和平台校验。
- `multi-room-recording`: 录制链路使用经过资源管理器验证的 FFmpeg/FFprobe，不再依赖用户机器上的任意可执行路径。

## Impact

- Rust/Tauri：新增资源清单模型、下载器、校验器、安装事务、版本状态、启动门禁和 Tauri commands/events；调整媒体与 ASR runtime 的可执行文件解析。
- SQLite/本地文件：新增资源安装状态、当前版本、失败原因和下载进度快照；资源文件放在应用数据目录并保留临时 `.part` 文件清理规则。
- React：新增首次启动资源准备页、下载确认、进度、暂停/取消、失败重试、重新检测和版本信息展示；主导航在资源未就绪时锁定。
- 构建与发行：更新 Makefile、Tauri 平台配置、资源 staging 工具和 macOS/Windows 离线验收脚本；发行构建需要平台资源包或明确的资源服务器版本。
- 外部服务：需要一个由用户提供的 HTTPS 资源托管地址，至少提供版本 manifest、资源压缩包或分片、SHA-256 和许可证文件；运行时只下载资源，不上传视频、音频、转写或用户数据。
- 安全边界：下载地址必须使用 HTTPS，资源包必须与 manifest 的哈希和版本匹配，安装过程采用临时目录加原子替换，日志和错误不得暴露本地完整路径或密钥。
