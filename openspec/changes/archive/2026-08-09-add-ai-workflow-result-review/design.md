## Context

剪辑工作台当前使用固定三栏结构：左侧素材库、中间播放器与时间线、右侧 230px 属性区。一键 Agent 返回的 `TransitionMatchSummary.boundaries` 已包含逐边界总分、四项维度、理由和建议素材，但完成处理只写入一条汇总消息；用户必须先发现并点击时间线边界才能在属性区看到明细。一键文本纠错返回包含不可变 `originalText` 与当前 `text` 的完整工程详情，但前端没有保存运行前快照，因此只展示修改计数。

这是一项桌面剪辑审阅交互，审阅时必须保留播放器和时间线上下文。文本差异只服务当前打开的剪辑会话；Agent 评分已经存在于运行审计和边界记录中，可安全恢复最近一次结果。既有 Rust 原子提交、工程版本和隐私边界保持不变。

## Goals / Non-Goals

**Goals:**

- 让用户在工作流完成后立即看到本次逐项结果，而不是只收到计数消息。
- 让 Agent 评分和文本差异可筛选、可解释、可定位并能复用既有应用建议与恢复原文操作。
- 在宽桌面保持播放器和时间线可见，在窄窗口提供不溢出的覆盖式审阅栏。
- 不增加数据库迁移和前端依赖。

**Non-Goals:**

- 不保存多次工作流结果历史，也不跨重启恢复文本纠错正文差异。
- 不把一键文本纠错改为提交前审批，也不改变其全有或全无事务。
- 不保存新的字幕正文副本，不展示 Provider 原始响应或隐藏推理。
- 不展示评分阶段所有候选的完整排行榜，也不批量强制应用低分建议。

## Decisions

### 1. 使用扩展右侧审阅栏而非居中弹窗

工作流完成后，右侧属性区切换为 `AI 审阅` 模式并扩展到约 420px；播放器与时间线继续可见。大于 1100px 时审阅栏占据网格列，小窗口改为覆盖中间画布右侧的抽屉，极窄窗口使用全宽面板。关闭后顶栏出现带结果数量的“查看结果”入口，时间线结果标记也能重新打开。

居中弹窗会遮挡播放器和时间线，无法完成“边看结果边验证画面”的主要任务，因此只保留现有轻量完成消息，不作为结果主体。独立结果页面会中断剪辑上下文，首版也不采用。

### 2. 结果栏使用统一外壳和工作流专用内容

审阅栏顶部提供 `Agent` 与 `文本纠错` 分段控件，仅在当前会话存在对应结果时可用。每种结果使用计数筛选和分隔列表，不嵌套装饰卡片。Agent 默认筛选待确认建议；若没有待确认项则显示全部。文本纠错默认只显示已修改项。

选中结果行是整个交互的核心：Agent 行选择边界并定位边界时间，文本行选择字幕、切换字幕属性并定位字幕开始时间。当前结果行、视频轨边界和字幕轨使用同一状态强调，形成同步审阅游标。

### 3. Agent 审阅直接使用现有摘要和目录数据

前端保存本次 `TransitionMatchSummary`，以其 `boundaries` 作为本次结果集合；使用工程片段解析左右片段标题，使用本地 `transitionMaterials` 解析建议或已应用素材。每行展示分类、总分和边界，选中行展开四项分数、理由和操作。

达到阈值且自动应用的结果标为“已应用”，有 `suggestionNone` 的结果标为“无需转场”，带建议分数但未应用的结果标为“待确认”。低分建议复用现有素材预览、应用建议和时间线定位路径，不新增 API。

重新打开工程时，前端通过只读 command 查询最近一次已完成运行的冻结阈值、统计与 token 用量，并与当前持久化边界评分组合为同一 `TransitionMatchSummary`。这不会保存新的模型输出或字幕正文。人工应用会锁定边界；当全部边界锁定时，Agent 命令保持不可执行，但审阅项提供解除指定边界锁定的操作。

### 4. 文本差异由运行前后工程快照计算

启动文本纠错前，前端按字幕 ID 保存当前 `text` 快照。后端成功返回后，只把前后文本不同的字幕记为本次修改，因此既有人工编辑与跳过字幕不会混入结果。审阅项从返回 `detail` 读取片段、时间和纠错后文本，从快照读取纠错前文本。

字符差异使用本地、确定性的 Unicode code point LCS 算法生成 unchanged/removed/added 片段；单条字幕已有 500 字素限制，不引入第三方依赖。删除和新增分别使用柔红与青绿语义色，并同时保留“ASR 原文/纠错结果”文本标签，不能只依赖颜色表达。

### 5. 文本差异仍只存在于当前会话

当前会话审阅结果保存在 `ClipEditor` 组件状态中，关闭面板只改变可见性，不清空结果；离开编辑器后释放文本差异。Agent 边界评分继续使用现有工程数据和运行审计恢复最近一次结果，文本本次差异不写入新的审计表。若后续要求跨重启恢复文本差异，应新增只保存 `runId + subtitleId` 的关联，而不是复制字幕正文。

### 6. 视觉使用现有剪辑台语汇并把强调留给状态

审阅栏沿用画布 `#0D1713`、面板 `#12221B` 和分隔线 `#29473B`；已应用使用 `#28C49A`，待确认使用 `#E6B44A`，删除差异使用 `#E07A78`。正文继续使用系统中文字体，时间码与分数使用系统等宽字体。列表尺寸稳定，展开内容只影响内部滚动，不改变播放器或时间轴高度；动画限制为栏位进入和同步高亮，并尊重 reduced motion。

## Risks / Trade-offs

- [关闭编辑器后无法恢复本次文本差异] -> 属性栏和时间线提供当前会话再次进入入口；跨重启文本差异明确留作后续能力。
- [420px 审阅栏压缩窄窗口播放器] -> 通过容器查询在窄窗口切换为覆盖式抽屉，不继续缩小原有三栏到不可用尺寸。
- [大量字幕差异导致渲染成本] -> 默认只渲染修改项，差异结果按本次数据计算并复用，列表内部独立滚动。
- [颜色表达对部分用户不可靠] -> 所有状态均同时提供文字标签、图标或分数，不只依赖颜色。
- [应用建议后结果分类变化] -> 使用后端返回的最新工程刷新边界，并同步更新当前审阅项，不保留已失真的分类标签。

## Migration Plan

1. 增加审阅结果类型、运行前字幕快照和字符差异工具，并提供最近一次 Agent 运行的只读查询。
2. 增加统一审阅栏、筛选、自动打开、再次进入、定位与既有操作连接。
3. 增加时间线状态标记和响应式样式，不改变数据库或 Tauri command。
4. 通过组件测试、生产构建和桌面尺寸截图后重新打包客户端。

回滚只需移除只读查询、前端审阅状态与样式，既有工作流、工程数据和审计不受影响。

## Open Questions

无。Agent 恢复最近一次已完成结果；文本纠错采用当前会话差异、纠错后审阅与逐条恢复，不包含多次历史和提交前审批。
