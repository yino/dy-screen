## Context

AI 工作区当前把高光候选完整卡片放在播放器和 ASR 结果之前。每张卡片同时展开六项评分和理由，候选数量或文本长度增加后会显著拉长页面，并使候选选择与来源句段、视频预览分离。

后端已经为每个候选返回 `inputId`、稳定 `segmentIds`、源视频 `startMs`/`endMs`、评分、理由、标签和 `selected`。转写投影也按输入保存同一组稳定句段 ID，因此前端能够确定性建立映射，无需修改数据库或 Agent 工作流数据模型。

当前转写列表每页最多渲染 200 个句段，切换视频会异步准备预览并重置分页。候选跳转必须显式协调输入切换、分页渲染、列表滚动和媒体就绪，不能假设目标 DOM 或 `<video>` 已经存在。

## Goals / Non-Goals

**Goals:**

- 将高光运行控制与候选浏览分离：上方保持紧凑运行摘要，候选比较和选择进入 ASR 工作区。
- 为全文、高光候选和已选择结果提供长度有界、可排序且可恢复的浏览方式。
- 让一个当前候选同时驱动来源视频、转写范围、评分详情和选择状态。
- 复用现有 command 即时持久化选择，并明确展示保存中、成功和失败状态。
- 在桌面宽窄窗口、无可靠预览、跨视频和候选重叠情况下保持文本可访问。

**Non-Goals:**

- 不修改候选生成、评分阈值、Prompt、Skills 或 DeepSeek 调用策略。
- 不编辑 ASR 文本，不生成字幕文件，不执行 FFmpeg 切片、拼接或成品导出。
- 不新增 SQLite 表、字段、Tauri command 或前后端 DTO。
- 不把高光分析与本地 ASR 合并为同一个自动阶段；高光分析仍需用户显式启动。

## Decisions

### 1. 使用“运行摘要 + ASR 主从浏览”替代完整候选卡片列表

高光面板只保留 Provider、运行状态、候选统计、分析进度和开始/重新分析操作。ASR 面板新增“全文”“高光候选”“已选择”分段模式；候选模式使用固定最大高度的紧凑导航选择一个当前候选，并仅展开该候选的理由和评分明细。

这样可以保留分数排序和候选对比入口，同时避免把每个候选的原文、六项评分和理由全部展开。替代方案是在每个 ASR 句段后重复候选卡片，但候选跨越多句且可能重叠，会重复内容并让片段总分被误解为单句评分，因此不采用。

### 2. 以现有稳定句段 ID 派生视图，不复制结果数据

前端从 `highlightCandidates` 和当前 `transcript` 派生候选排序、当前输入候选、已选候选、`segmentId -> candidates` 映射及当前候选句段。候选总分和详情只在候选头部展示一次；全文模式在相关句段使用色带和紧凑标记，高光模式只展示当前候选引用的句段并可附带有限上下文。

不把候选副本写入新的 React 状态或 SQLite 结构，避免历史运行恢复后出现两套选择状态。候选重叠时，句段显示命中数量并允许切换当前候选，不使用互相嵌套的 DOM 区间。

### 3. 使用显式待处理跳转协调跨视频定位

点击候选后立即设置当前候选和目标 `inputId`，根据目标输入中第一个匹配 `segmentId` 计算转写页码。输入切换后的 effect 等目标句段渲染完成再滚动；预览达到 `ready` 后再把播放器定位到 `startMs`。预览失败时仍展示和高亮转写范围，只禁用播放片段。

替代方案是在点击事件中同步查找 DOM 和修改 `video.currentTime`，但跨视频时组件会先重置分页和预览，这会产生丢失定位的竞态，因此不采用。

### 4. 片段预览由前端时间边界控制

“播放片段”复用当前本地预览媒体：定位到 `startMs` 后播放，并保存当前候选 `endMs` 作为临时停止边界。`timeupdate` 到达边界时暂停并清除边界；用户切换视频、候选或手动拖动到范围外时也清除旧边界。该行为不生成新媒体，也不修改原视频。

### 5. 选择开关即时调用现有批量持久化 command

“加入待切片”开关使用现有 `selectAiHighlightCandidates(runId, candidateIds)`，每次切换都根据当前完整候选集合生成下一组 ID。保存期间禁用候选选择并展示状态；成功后以后端返回列表替换本地状态，失败时保持原状态并显示错误。

选择采用后端确认后更新的方式，而不是先更新后回滚，避免快速连续操作导致较旧请求覆盖较新选择。界面不再要求用户滚动到底部点击额外保存按钮。

### 6. 浏览模式和排序仅属于本地界面状态

默认打开“全文”模式，分析完成或用户点击候选统计后可进入“高光候选”模式。候选默认按 `rank`、总分和 ID 稳定排序，并提供按源视频及开始时间排序；“已选择”模式只过滤已保存候选。模式、当前候选和排序不写入数据库，重新打开项目时从已保存候选状态安全恢复。

## Risks / Trade-offs

- [跨视频切换时预览异步完成，跳转可能过早执行] → 使用包含候选 ID、输入 ID 和开始时间的待处理跳转，只在目标预览和句段均就绪后消费。
- [候选引用的句段因历史数据异常而缺失] → 仍展示候选概要和时间范围，禁用精确句段定位并给出可操作提示，不猜测或构造文本。
- [候选重叠导致多重颜色难以理解] → 只强化当前候选，其他候选显示紧凑数量或分数标记，不绘制嵌套区间。
- [每次开关都提交完整 ID 集合] → 当前发布结果最多为有限候选，数据量很小；保存期间串行化交互以避免覆盖。
- [浏览器演示 API 与桌面端返回顺序不同] → 测试以 ID 和 `selected` 语义断言，不依赖 mock 的对象引用或未约定顺序。

## Migration Plan

1. 先以 React 测试固定候选视图、跨视频定位、区间播放和即时保存行为。
2. 替换完整候选列表并增加 ASR 候选浏览状态，不修改现有后端查询和持久化接口。
3. 运行前端全量测试、构建和相关 Rust 回归，确认历史运行恢复仍能加载候选。
4. 发布无需数据库迁移；回滚时恢复旧前端组件即可，候选及选择数据保持兼容。
