## Context

剪辑工程由高光候选快照组成，每个片段引用一个已经完成 ASR 的 `ai_project_inputs` 输入和源内毫秒范围。`transcript_segments` 已保存稳定句段 ID、规范化文本及源内开始/结束时间，但当前 `AiClipProjectDetail` 和 FFmpeg 导出计划都没有读取这些数据。

应用分发的是 `--disable-everything` 的精简 LGPL FFmpeg。当前资源没有 `libass/subtitles/drawtext`，引入 libass 会额外带来 FreeType、FriBidi、HarfBuzz、字体发现和多平台动态库分发复杂度。因此不能假设开发机的完整 FFmpeg 能力，也不能让前端传入 SRT/ASS 路径或滤镜表达式。

## Goals / Non-Goals

**Goals:**

- 复用已发布 ASR 稳定句段，将源内时间可靠映射到剪辑工程时间。
- 在编辑器播放器内默认显示与当前播放位置同步的字幕。
- 用后端生成的受控字幕画面序列，把中文字幕直接烧录到 MP4。
- 保证字幕临时文件在成功、失败、取消和应用退出路径中清理。
- 让随包 FFmpeg 和发行校验明确覆盖剪辑导出所需的全部解码器、demuxer、滤镜和编码器。

**Non-Goals:**

- 不重新执行 ASR，不修改稳定句段、候选、原始视频或预览缓存。
- 不支持字幕人工编辑、翻译、逐字时间轴、卡拉 OK、任意字体、样式、位置或外部字幕导入。
- 不把字幕作为可关闭的 MP4 软字幕轨道；第一版输出为直接可见的烧录字幕。
- 不接受前端提供本地路径、图片、字幕文件、滤镜或 FFmpeg 参数。

## Decisions

### 1. 在 repository 边界生成只读剪辑字幕投影

`AiClipProjectDetail` 增加扁平的 `subtitles` 集合和 `subtitlesComplete`。每条字幕携带稳定句段 ID、所属剪辑片段/输入 ID、规范化文本、源内范围和工程范围。对每个剪辑片段，只读取其输入已绑定的已发布 ASR 产物中与 `[source_start_ms, source_end_ms)` 相交的句段：先裁剪到片段边界，再减去片段源起点并加上此前片段累计时长。

字幕投影每次从稳定 ASR 和当前剪辑顺序计算，不另建可漂移的字幕表。片段重排、追加或移除后，工程时间会随返回的新详情立即重算；源内字幕和文本保持不变。

替代方案是在创建剪辑工程时复制字幕。复制会产生版本、同步和删除一致性问题，也违背 ASR 结果只读和单一事实来源，因此不采用。

### 2. 编辑器以工程时间选择当前字幕

前端播放器已有来源时间与工程时间双向映射。字幕层直接用 `timelinePositionMs` 查询满足 `projectStartMs <= t < projectEndMs` 的字幕；跨片段播放和用户定位都通过同一个工程播放头更新。字幕默认开启，无命中句段时不显示空背景；界面展示字幕完整性状态，但不允许修改文本。

重叠句段按工程开始时间和稳定 ID 排序；同一时刻多条命中时选择开始时间最晚的一条，保证预览与导出确定一致。

### 3. Rust 栅格化透明 PNG，FFmpeg 读取 concat 序列并 overlay

导出前，Rust 使用纯 Rust 字体栅格化和 PNG 编码库生成固定宽度、透明背景的字幕画面。字体只从后端内置的受支持平台系统字体候选中选择；macOS 优先 Hiragino/STHeiti，Windows 优先 Microsoft YaHei/SimHei。字体路径不进入前端、数据库或日志。字幕使用白字、半透明黑色背景、固定安全边距和按画幅约束的自动换行。

每个字幕和字幕间空白生成一张编号 PNG，后端用简单相对文件名写入 `ffconcat` 清单。FFmpeg 只增加一个由后端创建的 concat 输入，经 `format=rgba` 后叠加到已经拼接的视频。这样参数数量不随句段数量线性增长，中文路径只出现在受控参数数组中，字幕文本也不会进入 FFmpeg 滤镜字符串。

替代方案是 libass/SRT。它需要额外 C 依赖、字体配置和跨平台动态库，并扩大资源包和许可证边界。MP4 `mov_text` 软字幕不能保证应用播放器和外部播放器默认可见，也不满足直接可见的成品要求，因此均不采用。

### 4. 字幕作为导出的完整性门禁

由高光候选建立的每个片段理论上都应有 ASR 句段。若任一片段没有相交的规范化文本，编辑器仍允许预览和调整，但 `subtitlesComplete=false`，导出命令在保存对话框前拒绝启动，并提示返回 ASR 补全或移除无字幕片段。这样不会静默生成一部分有字幕、一部分无字幕的成品。

仅有片段边缘短暂无字幕属于正常情况，透明空白区间会保留原画面。这里的完整性按“每个剪辑片段至少有一条有效字幕”判断，而不是要求全时段连续覆盖。

### 5. 扩展并验证精简 FFmpeg 能力

macOS 构建脚本启用 PNG decoder、concat/image2 demuxer、overlay/concat/pad/setpts/asetpts/volume/fade 等导出滤镜，并继续保持 LGPL 和系统 VideoToolbox H.264。导出编码器按受控运行时选择平台白名单，不再只假设 `libx264`。Windows staging 和发行校验要求提供等价的 H.264/AAC、PNG、concat 和 overlay 能力。

发行测试直接查询 `-decoders`、`-demuxers`、`-filters` 和 `-encoders`；缺少任一能力时拒绝生成资源包或安装包。

## Risks / Trade-offs

- [系统字体在未来操作系统版本中移动] → 使用按平台排序的多个固定候选，启动导出前探测字形；全部不可用时返回可操作错误且不启动 FFmpeg。
- [长项目产生较多 PNG 临时文件] → 一个可见区间只生成一张高度受限的压缩 PNG，使用单独任务目录并在所有终止路径递归清理。
- [ASR 句段重叠导致字幕竞争] → 预览与导出共用确定性规则，后开始的句段覆盖先开始的句段，避免双层文字。
- [PNG 时间基与最终帧边界存在一帧误差] → 时间统一保留毫秒，concat 时长保留三位小数，并通过真实 FFmpeg 小样验证首尾和跨片段切换。
- [旧 Runtime Resource Pack 缺少新能力] → 提升资源能力要求和 bundle 版本，资源门禁要求下载新包；数据库无需迁移，可回滚到不带字幕的旧应用版本。

## Migration Plan

1. 先发布代码与资源能力校验，旧资源会被标记为版本或能力不兼容，不执行剪辑导出。
2. 为 macOS arm64 和 Windows x64 重新构建、签名并上传 Runtime Resource Pack。
3. 新应用完成资源更新后解锁剪辑导出；已有 ASR 项目和剪辑工程无需迁移，打开时动态获得字幕投影。
4. 回滚应用时忽略新增 DTO 字段即可，原始录像、ASR 表和剪辑工程表均保持兼容。
