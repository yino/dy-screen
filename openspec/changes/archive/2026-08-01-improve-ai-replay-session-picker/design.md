## Context

当前 `AiWorkspace` 在首次挂载时调用一次 `listAiCompletedSessions()`，把最近最多 100 场会话保存在组件状态中。AI 页面首次打开后即使收到录制结束，目录也不会更新；由于工作区之后只切换 `active` 而不卸载，切走再回来仍然使用旧数组。实际数据库中当天已结束会话存在，说明缺失发生在前端缓存刷新边界。

后端查询按全局时间倒序截断，随后逐场读取主播和分片，既不能先筛主播，也会形成 N+1 查询。前端原生 `<select>` 不支持搜索、分页、加载状态或项目级“已导入”反馈。现有 `session_changed` 监控事件在 `finish_session` 和 manifest 对账完成后发布，可以作为安全刷新信号。

## Goals / Non-Goals

**Goals:**

- 让用户先搜索并选择主播，再搜索和选择该主播的已结束回放。
- 让任意历史场次可通过服务端搜索和游标分页发现，不受全局条数上限影响。
- 在当天直播结束后自动刷新目录，无需重启应用或重建 AI 工作区。
- 在选择前显示会话分片、不可用和当前项目已导入数量，并阻止重复执行没有新增内容的导入。
- 保持查询 DTO 无本地路径，保持导入 command 对进行中会话和陈旧选择的后端校验。
- 提供与现有主题一致、可键盘操作且在 Tauri WebView 中稳定的搜索组合框。

**Non-Goals:**

- 不导入正在录制的直播，不提供边录边识别入口。
- 不实现跨主播或跨场次批量多选。
- 不修改、移动或删除录像、会话、视频库记录及已有 AI 输入。
- 不引入前端组件库、云端索引或网络搜索。

## Decisions

### 1. 使用两个有界查询契约替代全局会话数组

新增主播目录和回放目录查询 DTO。主播项包含稳定主播 ID、名称、标签摘要、`webRid` 提示、归档/监听/直播状态、可选回放数和最近结束时间；回放项包含会话 ID、开始/结束时间、状态、总分片数、总时长、不可用数、当前项目已导入数和是否全部导入。分页响应返回 `items` 与可选的稳定游标，默认 20 条、后端上限 50 条。

主播目录只聚合至少存在一个 `ended_at IS NOT NULL` 且至少有一个登记视频的会话。回放目录必须接收 `streamer_id` 和 `project_id`，只查询该主播已结束且非空的会话。当前正在直播、暂停或归档不改变历史回放资格，仅作为展示状态。

替代方案是继续一次返回全部会话并在前端分组。它仍受内存、加载时间和陈旧缓存影响，无法保证超过 200 场的回放可发现，因此不采用。

### 2. SQLite 负责绑定参数搜索、聚合和稳定游标分页

主播搜索匹配去空白后的名称、标签名称和 `web_rid`；回放搜索匹配会话 ID及按系统本地时区格式化的开始/结束日期时间。所有搜索词有长度上限、使用绑定参数并转义 `LIKE` 通配符。空搜索按最近回放时间排序，主播游标使用 `(latest_ended_at, streamer_id)`，回放游标使用 `(started_at, session_id)`，避免新会话插入时重复或跳过已经加载的行。

数据库查询聚合视频数量、时长、状态和当前项目 `video_id` 命中数，避免为每场回放读取一次主播。文件存在性只在当前一页的有界分片集合上检查，并与已持久化视频状态合并；路径不进入返回 DTO、日志或前端。为已结束会话扫描补充合适的复合索引迁移，迁移幂等且不改现有数据。

替代方案是 offset 分页。新直播结束会把数据插入第一页，用户加载更多时可能重复或遗漏，因此采用稳定游标。

### 3. 目录刷新由页面激活、选择器打开和 `session_changed` 共同驱动

AI 工作区从非活动变为活动时刷新主播目录；主播组合框打开时再次刷新。选定主播后打开回放组合框会重新查询第一页。收到 `session_changed` 时，仅在 AI 工作区已挂载时使目录版本失效；若页面可见则立即刷新，否则在下次激活时刷新。导入完成后刷新所选主播的回放页，以更新已导入数量。

每次异步查询携带前端 generation，主播、搜索词、项目或页游标变化后忽略旧响应，防止快速输入导致结果倒退。失败只影响对应组合框并提供显式重试，不清空已选主播或项目输入。

替代方案是固定间隔轮询。它会在用户不使用 AI 页面时持续查询，并仍可能让刚结束回放等待一个周期，因此复用现有事件并在打开时兜底。

### 4. 使用项目内可复用的无依赖搜索组合框

实现受控 `SearchableCombobox`，由按钮、弹层搜索输入和 `listbox` 组成。它支持上下方向键、回车、`Esc`、点击外部关闭、焦点恢复、滚动加载更多、加载/空结果/失败重试状态，并通过 `aria-expanded`、`aria-controls`、`aria-activedescendant` 和 option 禁用状态表达语义。弹层尺寸受容器约束，长文本省略，窄窗口改为纵向排列。

主播未选择时回放组合框禁用。默认不自动选择主播；添加成功后保留主播、清空回放。完全导入项继续可见但禁用并标记“已全部添加”；部分导入项显示“已添加 N/M”并允许补充。一次仍只添加一场回放。

替代方案是引入 Radix 或其他组件库。项目当前没有对应依赖，这个控件需求边界有限，引入整套依赖会扩大安装包和样式整合范围，因此不采用。

### 5. 保留导入 command 作为最终一致性边界

目录状态只用于交互提示。`ai_add_completed_session` 仍重新读取会话，拒绝 `ended_at IS NULL`，按 `started_at ASC, id ASC` 展开并在事务边界跳过重复项。即使列表陈旧、会话被删除或前端绕过禁用状态，后端也不会导入进行中会话或不受信路径。

## Risks / Trade-offs

- [本地时间搜索与 UTC 存储不一致] → 查询统一按操作系统本地时区生成可搜索日期时间，并增加跨日和时区测试。
- [高频 `session_changed` 或快速输入产生并发响应] → 只在会话完成事件刷新目录，搜索使用短防抖和 generation 丢弃旧响应。
- [归档主播名称或标签后来变化] → 目录展示当前主播元数据，但回放身份始终使用稳定 `streamer_id` 和 `session_id`。
- [文件在列表查询后被删除] → 列表状态只作提示，导入阶段继续执行现有文件与音轨检查并返回不可用项。
- [搜索中的 `%`、`_` 或超长输入扩大扫描] → 后端限制长度、转义通配符、绑定参数并限制每页数量。

## Migration Plan

1. 增加幂等索引迁移和分页 repository 查询，不修改现有会话、视频或 AI 输入。
2. 增加新 Tauri 查询 command 与 TypeScript DTO，保留旧导入 command；旧全局列表 command 可暂时保留给兼容测试但新界面不再使用。
3. 切换 AI 工作区到二级组合框并接入 `session_changed`、页面激活和打开刷新。
4. 用超过 200 场、当天新结束、归档主播、当前直播主播、部分/全部导入和不可用分片数据验收。
5. 回滚应用时忽略新增索引即可，数据库数据和旧列表 command 仍兼容。
