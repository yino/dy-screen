## Context

当前本地 ASR 由媒体准备、VAD、`AsrEngine` 契约和 `WhisperCppEngine` 组成，产物通过现有 SQLite transcript/artifact 管道发布。客户端 API 层已有鉴权请求头、响应 envelope 和业务错误处理，但尚无 `/api/client/ai/llm-ak` 方法。百炼文件转写接口是异步 API，要求可访问的 HTTPS `file_url`；本地临时 WAV 不能直接提交。详见 proposal.md 和规格 delta。

## Goals / Non-Goals

**Goals:**

- 在不破坏现有本地 ASR、缓存、时间轴和资源门禁的前提下增加云端优先策略。
- 将项目临时 AI 授权、百炼异步任务和统一 ASR 结果封装在中立边界内。
- 明确临时音频上传/对象存储的安全生命周期，并在能力不可用时安全回退本地。
- 提供可解释但不泄露密钥、路径和完整 URL 的状态与错误。

**Non-Goals:**

- 不下发或在客户端保存长期 `DASHSCOPE_API_KEY`。
- 不实现任意模型路径、任意云厂商或绕过项目授权/配额的逻辑。
- 不把百炼专属 JSON、任务 ID 或认证字段暴露到通用业务契约。
- 不上传原始视频、热词或转写正文；仅为文件转写建立必要的短期音频引用。

## Decisions

### 1. 在现有中立 AsrEngine 边界增加 provider 路由

由 processor 使用一个云端优先的路由器，先尝试获取临时授权并选择云端 engine，失败后调用现有 `WhisperCppEngine`。云端适配器只负责百炼请求/轮询/结果解析，向上返回现有统一结果；这样不需要让业务层理解百炼字段，也保留本地引擎作为明确的 fallback。

替代方案：直接在 processor 内拼接 HTTP 请求会把供应商协议和回退逻辑扩散到业务层，难以测试和替换，因此不采用。

### 2. 复用客户端鉴权与 envelope 解码获取临时密钥

在 API 层新增 `llm-ak` 方法，复用现有 `client_headers` 和响应解码；只在内存中缓存未过期的密钥，并以 `provider` 与 `expireAt` 校验是否可用。所有项目后端错误码（尤其 `3001`~`3004`）在本地映射为可读提示，不把它们当作百炼上游错误码。

替代方案：客户端自行调用百炼 Token API 需要长期密钥，违反密钥边界，因此不采用。

### 3. 先实现临时音频发布器抽象，不绑定部署方案

新增抽象的临时音频发布器：输入为任务生命周期内的标准 WAV，输出为短时 HTTPS URL 和清理句柄。本次实现只提供协议边界、能力探测和不可用时的安全行为，不绑定后端上传接口或对象存储 SDK；运行时没有具体发布器时，路由器必须跳过云端并回退本地。未来接入任一部署实现都不得返回永久公开地址，也不得把 URL 写入普通日志。

替代方案：现在直接选择后端上传或对象存储会引入未确认的部署依赖；提交本地路径或 `file://` URI 则百炼无法访问且会泄露本地信息，均不采用。

### 4. 百炼任务采用有界轮询和取消传播

提交 `qwen3-asr-flash-filetrans` 后保存仅用于内存控制的 task handle，以固定最小间隔、最大次数和总超时轮询；任务取消时停止客户端轮询并清理本地/远端临时音频。401/403、429 和 5xx 分别进入鉴权、限流和暂时性故障分类，有限重试后回退本地。

替代方案：无限轮询会占用 ASR 全局并发并造成上游压力，因此不采用。

### 5. 结果和状态扩展使用非敏感元数据

统一 ASR 结果增加 provider、模型标识和可选 fallback reason 等非敏感字段；稳定句段 ID、源内时间戳、规范化、复用和导出继续复用本地既有逻辑。临时 AK、Authorization Header、完整音频 URL 和上游原始正文仅存在于受控内存/网络调用范围。

## Risks / Trade-offs

- [云端调用需要上传音频] → 仅上传标准临时 WAV，使用短期 HTTPS URL，任务结束立即清理；无发布器时完全不调用云端。
- [后端签发成功但百炼任务失败] → 保留本地回退，错误仅记录分类、状态码和脱敏 message/request_id。
- [云端识别延迟高于本地短音频] → 限制轮询总时长并保留任务取消；超时后本地处理。
- [回退可能造成重复计算] → 在发布统一产物前不写半成品，provider/fallback 元数据帮助诊断，复用规则继续按完整配置指纹判断。
- [云端模型返回时间戳结构变化] → 在适配器边界做严格 schema 校验，缺少可靠时间戳时按统一契约降级或回退本地，不伪造时间。

## Migration Plan

1. 先发布仅包含路由、配置和本地回退的版本，默认在无临时音频发布器时保持原有本地行为。
2. 后续由部署方实现后端临时上传或对象存储发布器，并通过运行时诊断确认 HTTPS、过期清理和大小限制。
3. 发布器就绪后开启云端优先，观察云端成功率、回退分类和配额提示；不记录任何密钥或完整 URL。
4. 若百炼接口异常，可关闭云端发布器/路由开关，客户端自动回到本地 ASR；无需迁移已有 transcript/artifact。

## Open Questions

- 百炼返回的详细转写 JSON 在实际账号和模型下是否始终提供词级时间戳，需要用集成测试确认；缺失时按统一结果允许的可选字段处理。
