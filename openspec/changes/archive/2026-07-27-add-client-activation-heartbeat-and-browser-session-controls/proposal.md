## Why

当前客户端可以直接进入监控和录制流程，但没有与授权运营服务端建立统一的激活、心跳和启动登记链路，导致未激活时无法阻止后台任务继续运行，也无法及时响应卡密被停用或换绑。浏览器验证完成后虽然已有 WebView 探测线程，却没有把“会话恢复”明确转化为一次访问状态检查；后台解析窗口还可能播放直播声音，影响用户正常使用。

## What Changes

- 新增统一的 Rust 服务端 API 客户端，集中处理 API 地址配置、统一响应体、中文错误、激活、心跳、AppStart 和埋点请求，并预留请求/响应加解密入口；本期保持明文传输，不实现加密协议。
- 新增本地激活状态持久化和启动门禁：没有有效激活信息时显示不可关闭的激活弹窗，不恢复监听、录制和其他主功能；激活成功后恢复后台任务。
- 启动时调用 AppStart 并上报 `app_open`，运行期间按固定周期发送心跳；收到停用、过期或解除绑定状态时清理本地会话、暂停后台任务并提示重新激活。
- 埋点采用 best-effort 队列，服务端不可用不阻塞客户端启动；只上报白名单事件和安全属性，不上传直播内容、媒体路径或页面正文。
- 用户完成验证码后，浏览器会话探测成功时自动触发一次访问状态检查并唤醒等待主播；验证窗口在后台运行时尽力静音，无法设置媒体音量的平台也不得阻塞解析流程。
- 增加激活、心跳、AppStart、埋点和浏览器静音/自动回查的单测及集成验证。

## Capabilities

### New Capabilities

- `client-activation-service`: 客户端 API 配置、激活持久化、启动门禁、心跳、AppStart 和埋点生命周期。

### Modified Capabilities

- `desktop-client-shell`: 增加激活弹窗、未激活门禁、心跳状态提示和启动 API 生命周期要求。
- `browser-session-room-resolution`: 增加验证码完成后的显式访问状态回查，以及后台验证 WebView 静音行为。

## Impact

- Rust：新增 `src-tauri/src/api.rs` 和授权状态服务，修改 SQLite migration、应用初始化、Tauri commands、Supervisor 恢复时机和浏览器 WebView 驱动。
- 前端：扩展 `ClientApi`，新增激活状态订阅和不可关闭的激活弹窗，展示停用/过期/网络错误等脱敏状态。
- 配置：新增 `DY_SCREEN_API_BASE_URL`，优先读取运行时环境变量；开发默认回退 `http://localhost/api/`，生产部署必须显式配置。
- 依赖：复用现有 Tokio、Serde、Reqwest 能力，暂不引入信封加密依赖；加解密接口保留在统一 API 客户端边界内。
- 非目标：本期不实现 API 加密、不绕过验证码、不自动识别验证码、不上传媒体/ASR/直播内容，也不做服务端 API 之外的后台运营功能。
