## Context

剪辑工作台已经持久化工程字幕副本和相邻片段转场边界，并通过本地 Tauri/Rust 层调用现有 DeepSeek Provider。字幕支持单条编辑、隐藏和恢复 ASR 原文；转场匹配则由本地候选召回加一次 LLM 选择完成，并以固定 `0.75` 置信度决定自动应用。前端新增的两个一键入口尚未具备完整后端能力。

本次变更横跨 LLM 契约、SQLite 迁移、工程版本事务、后台运行生命周期、Tauri command、设置页和剪辑工作台。所有模型调用必须经本地 Rust 发起；WebView 不接触 API Key、Provider 响应正文、本地路径或数据库。

## Goals / Non-Goals

**Goals:**

- 让“一键文本纠错”对当前工程的合格字幕执行保守的 ASR 文本纠错，并在全部结果有效时原子保存。
- 让“一键 Agent”按“场景匹配、候选评分、阈值应用”执行可解释、可取消、可审计的两阶段工作流。
- 在设置中增加默认 8 分的独立转场自动应用阈值，并为每次运行冻结设置快照。
- 保留激活、Provider 凭据、工程版本、人工字幕修改和人工转场锁的既有安全边界。

**Non-Goals:**

- 不引入本机离线模型、Ollama 或第二种 Provider。
- 不执行字幕润色、翻译、摘要、句段合并拆分或时间轴重算。
- 不让 Agent 生成素材、修改素材目录或返回任意 URL、路径和渲染参数。
- 不绕过未激活客户端、未配置 DeepSeek Key 或空素材目录的门禁。

## Decisions

### 1. WebView 只触发工作流，本地 Rust 拥有 LLM 和数据提交

前端只提交工程 ID、期望工程版本和用户授权标志。Rust 从 SQLite 读取字幕、边界、模板目录与 Provider 设置，构造受限请求并校验响应。这样 API Key、完整素材目录和工程内部状态不会进入 WebView 可构造的载荷，也能复用现有 Tauri 错误分类与取消机制。

替代方案是由 React 直接调用 DeepSeek。该方案会暴露凭据、绕过工程版本事务并扩大可注入输入面，因此不采用。

### 2. 字幕输入使用当前工程文本，但跳过人工修改与隐藏记录

运行开始时按工程片段顺序、源内时间和稳定字幕 ID 排序，选择 `text == originalText` 且未隐藏的字幕。每个批次发给模型的业务数据是纯文本数组；稳定 ID 与数组索引只保留在 Rust 映射中。已经人工修正的字幕和隐藏字幕不会被模型覆盖，结果摘要会返回处理、修改、未变化和跳过数量。

替代方案是始终使用 `originalText` 或覆盖所有当前文本。前者忽略当前工程快照，后者可能破坏用户明确编辑，因此不采用。

### 3. 文本纠错按预算分批，结构化返回后统一提交

Rust 按字符预算在完整字幕边界分批，请求模型返回 `index + text` 的结构化数组。每批必须与输入严格等长，索引唯一且覆盖 `0..n-1`；文本还必须通过现有字幕规范化、非空和 500 字素限制。所有批次完成后再次校验工程版本，并在一个 SQLite 事务中更新发生变化的记录和工程版本。

Provider 失败、取消、非法响应或版本冲突都不会提交任何字幕修改。远程调用不能包在长 SQLite 事务内，运行开始时冻结版本、提交前做乐观并发校验。

替代方案是每批成功即保存。该方案会让失败和重试产生难以理解的半修正工程，因此不采用。

### 4. 提示词将纠错限制为保守 ASR 修复

系统提示只允许修正错别字、同音错词、明显识别错误和标点，并要求保持含义、语气、专名、数字和数组边界。模型不允许合并、拆分、增删字幕项。Rust 无法证明语义完全未变，但通过低温度、明确契约、长度与结构校验降低风险，并保留单条“恢复 ASR 原文”。

### 5. 转场 Agent 使用两个独立结构化阶段

第一阶段在本地确定性召回的受限模板候选内，为每个未人工锁定边界返回最多三个场景匹配候选或 `none`。第二阶段只接收已验证的边界上下文与候选语义元数据，为每个候选返回 0–10 总分、场景适配、衔接、节奏、素材适配和简短理由。Rust 校验边界、候选键版本、字段范围和集合完整性，再按总分降序选择最佳结果；并列时按第一阶段排名、素材键和版本确定性选择。

两个阶段使用同一已配置模型，但拥有独立 prompt 版本和审计阶段。Agent 没有工具、文件、网络搜索或数据库写权限。

替代方案是继续让单次模型响应同时选择并自报置信度。该分值缺少独立复评，难以解释和设置统一阈值，因此不采用。

### 6. 分数采用 0–10，运行冻结独立阈值

`LlmProviderSettings` 新增 `transitionAutoApplyScore`，SQLite 默认值为 8，后端只接受 0–10 整数。运行创建时把当前阈值、模型和两个 prompt 版本写入运行快照；运行过程中修改设置只影响下一次运行。最佳合法候选 `score >= threshold` 时才自动应用和下载，低分只保存建议；`none` 保存无转场建议。人工锁定边界始终跳过。

现有 0–1 `confidence` 字段保留用于读取历史工程，但新运行写入独立分数和维度，不把新分数伪装成旧置信度。

### 7. 运行状态与取消由 Rust 统一管理

字幕纠错和转场 Agent 都具有稳定运行 ID、阶段、总数、已完成数、脱敏错误和 token 用量。Tauri 发布有界进度事件并提供取消 command；取消标志在批次、匹配、评分和应用阶段之间检查，迟到响应只允许完成本地校验，不再进入后续阶段或提交工程修改。

转场结果按边界持久化；已成功完成评分的边界可在运行失败后用于诊断，但只有最终应用阶段可以改变未锁定边界。字幕纠错则始终保持全有或全无。

### 8. 运行审计只保存结构化必要信息

审计保存工程版本、模型、prompt 版本、素材键版本、总分、维度、理由、阶段耗时、token 用量和稳定错误分类。不保存 API Key、请求头、完整 Prompt、原始 Provider 响应、隐藏推理、本地路径、视频或音频。字幕纠错审计只保存计数和指纹，不复制完整字幕正文。

### 9. 前置条件由前后端共同执行

未激活、未配置 Key、导出中、工程无合格字幕、素材目录为空或没有未锁定有效边界时，工作台禁用对应命令并显示具体原因；Rust command 对相同条件再次校验。浏览器演示模式继续保持未激活，不能借由新按钮进入真实画布或模拟远程调用。

## Risks / Trade-offs

- [模型可能做超出范围的语义改写] -> 使用保守提示词、低温度、严格结构校验、人工字幕跳过和单条原文恢复；界面显示实际修改数量。
- [长工程产生多次请求和费用] -> 按预算分批、展示进度和取消、跳过无变化/人工/隐藏字幕，并记录 token 用量。
- [两阶段转场使延迟和费用增加] -> 本地先有界召回，每边界最多三个候选，评分阶段只发送压缩语义元数据。
- [运行期间工程被编辑] -> 冻结工程版本并在每个提交点执行乐观并发校验，冲突时不覆盖新编辑。
- [旧工程只有 confidence 字段] -> 向前迁移保留旧字段与读取行为，新运行使用可空评分字段，避免破坏历史工程。
- [取消发生在远程请求期间] -> 无法保证立即终止已经发出的 HTTP 请求，但取消后忽略迟到结果且禁止提交后续修改。

## Migration Plan

1. 增加向前 SQLite 迁移，为 Provider 设置补充默认 8 分阈值，并为转场运行与边界补充分数、维度和 prompt 审计字段。
2. 扩展 Rust LLM 契约、repository 事务和 Tauri commands；旧设置读取时自动取得默认值，旧工程继续使用已有转场选择。
3. 接入设置页和剪辑工作台状态，先以后端门禁为准，再提供前端禁用原因、进度和取消操作。
4. 通过 repository、Provider schema、编排、Tauri API 和 React 交互测试后发布。

回滚旧版本时新增列和表由旧代码忽略；已经写入的新评分建议不会删除旧 `confidence` 或人工选择。若功能回滚，不删除审计和字幕原文，用户仍可通过单条恢复能力处理已纠错字幕。

## Open Questions

无。文本范围、批次原子性、人工修改优先级、两阶段候选数、评分维度、阈值与审计边界均已确认。
