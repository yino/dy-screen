## Why

剪辑工作台已经提供“一键 Agent”和“一键文本纠错”入口，但前者仍复用单阶段置信度匹配，后者只打开人工校对面板，无法完成用户期望的一键处理。需要把两个入口接入由本地 Rust 编排和校验的真实 LLM 工作流，在不绕过激活、人工编辑优先级和工程版本控制的前提下减少重复操作。

## What Changes

- 新增工程级一键文本纠错：本地 Rust 将当前工程中未隐藏、未经人工修改的字幕文本按稳定顺序分批发送给现有 DeepSeek Provider，严格校验结构化结果后一次事务更新工程。
- 文本纠错只处理错别字、同音错词、明显 ASR 错误和标点，不润色或改写语义；任何批次失败、响应错位或工程版本冲突均保持工程不变。
- 将一键转场 Agent 改为由 Rust 控制的两阶段编排：先根据现有转场模板库召回并匹配每个边界最多三个候选，再对候选执行独立的 0–10 分评分。
- 将固定 `confidence >= 0.75` 自动应用规则替换为独立可配置阈值；默认值为 8 分，运行开始时冻结，`score >= threshold` 的合法候选自动应用，低分和 `none` 结果只保存为建议。
- 保存可解释的转场评分维度、理由和脱敏审计信息，并为两个工作流提供前置条件、进度、取消、成功和失败反馈。
- 保留激活门禁、DeepSeek 凭据边界、人工锁定转场、人工字幕修改、隐藏字幕和恢复 ASR 原文能力。

## Capabilities

### New Capabilities

- `ai-clip-text-correction`: 定义工程字幕批量纠错的输入选择、分批 LLM 契约、本地校验、原子提交、冲突处理和隐私边界。

### Modified Capabilities

- `ai-transition-material-matching`: 将单阶段置信度选择改为候选匹配与独立评分的两阶段 Agent 编排，并按冻结的 0–10 分阈值应用结果。
- `llm-provider-configuration`: 增加独立的转场自动应用分数设置，默认 8 分并纳入本地持久化与校验。
- `ai-clip-editor`: 让两个工作台入口执行真实后台工作流，并展示可取消进度、结果和不可用原因。

## Impact

- Rust：扩展 LLM 结构化请求/响应、剪辑字幕事务、转场匹配编排、评分持久化、设置迁移、运行审计和 Tauri commands。
- 前端：扩展 API 与类型，接入两个按钮的执行、取消、进度、错误、结果刷新和设置表单。
- 数据：SQLite 向前迁移新增转场阈值、评分维度和必要的运行状态字段；不覆盖 API Key、原始 ASR 或人工锁定内容。
- 外部调用：继续只使用现有 DeepSeek Provider。发送内容限制为必要字幕文本、边界上下文和候选素材语义元数据，不发送视频、音频、本地路径、激活信息或凭据。
- 非目标：不引入离线模型或新的 Provider，不让浏览器前端直连 LLM，不绕过客户端激活，不实现字幕润色、翻译或时间轴重切分，也不让 Agent 生成素材或任意渲染参数。
