## ADDED Requirements

### Requirement: 在设置页管理 DeepSeek
系统 SHALL 在设置页提供 DeepSeek API Key、模型 ID、凭据状态、测试连接、替换和清除入口，并 MUST NOT 在读取设置或重新打开页面时回填 Key 明文。

#### Scenario: 保存并重新打开设置
- **WHEN** 用户保存有效 Key 和模型后再次打开设置页
- **THEN** 界面显示模型和“已配置密钥”，Key 输入保持空白且 DOM、浏览器演示数据和日志均不包含旧 Key

#### Scenario: 测试连接
- **WHEN** 用户点击测试连接
- **THEN** 界面展示加载状态及后端返回的成功或脱敏错误，并防止重复提交

### Requirement: 在 AI 工作区控制全局队列
系统 SHALL 在每个合法待处理视频上提供“下一个处理”，并 SHALL 提供带进度损失说明和二次确认的“立即切换”；界面 SHALL 展示当前输入和稳定全局队列位置。

#### Scenario: 提升第三个视频
- **WHEN** 用户把第三个待处理视频设为下一个
- **THEN** 界面立即刷新后端队列快照，并明确当前视频仍会继续运行

#### Scenario: 确认立即切换
- **WHEN** 用户确认立即切换且后端完成抢占
- **THEN** 选中视频显示运行中，被中断视频显示重新排队，其他项目继续保持可执行

### Requirement: 展示高光 Agent 工作流
系统 SHALL 在 ASR 结果旁提供独立高光步骤，显示发送预估、模型、Skills、运行阶段、取消/重试操作和高光候选；ASR 完成 MUST NOT 自动开始该步骤。

#### Scenario: 用户尚未授权
- **WHEN** 项目已经有转写但没有高光运行
- **THEN** 界面展示将发送的文本类型、句段数、批次和模型，并提供显式“开始高光分析”按钮

#### Scenario: 高光运行恢复
- **WHEN** 用户离开页面后重新打开正在执行或已完成的项目
- **THEN** 界面通过主动查询恢复当前阶段、进度、token 用量和已发布候选

### Requirement: 展示和保存高光候选选择
系统 SHALL 以可扫描列表展示候选总分、维度、理由、标签、来源视频和时间范围，并 SHALL 支持排序、播放器跳转、勾选和保存选择。

#### Scenario: 预览候选
- **WHEN** 用户点击可定位候选
- **THEN** 界面切换到来源视频并跳转至开始时间，同时保留候选列表和选择状态

#### Scenario: 保存候选
- **WHEN** 用户保存勾选结果
- **THEN** 界面显示已保存状态和候选数量，不展示或触发成品切片、拼接或导出入口

### Requirement: 浏览器演示不处理真实凭据或云端调用
系统 SHALL 在浏览器演示模式中提供稳定的本地队列和高光候选示例，但 MUST NOT 保存 DeepSeek Key、发起真实 Provider 请求或伪造真实连接测试成功。

#### Scenario: 浏览器演示填写 Key
- **WHEN** 用户在非 Tauri 浏览器演示中打开 DeepSeek 设置
- **THEN** 界面明确真实凭据仅桌面端可用，并拒绝保存或测试 Key
