## Context

剪辑工程当前不保存字幕记录。`AiRepository::get_clip_project` 每次从项目输入当前已发布的 `transcript_segments` 计算 `AiClipSubtitle`，前端以整句叠层预览，导出端则在临时目录生成带半透明黑底的透明 PNG 序列并交给受控 FFmpeg 滤镜烧录。这个模型保证了 ASR 产物不可变，但也使用户无法修正错字，且 ASR 重新发布后已有工程的字幕可能随之变化。

本变更横跨 SQLite、Rust repository/DTO/command、React 剪辑工作台和字幕渲染器。约束包括：原始 ASR 和录像不可修改；前端不能提交时间戳、字体路径、滤镜或 FFmpeg 参数；现有工程必须无损升级；预览与导出必须使用同一工程文本、分页和逐字时间计划；第一版没有真实字级时间戳。

## Goals / Non-Goals

**Goals:**

- 为每个剪辑工程持久化独立、可恢复且可审计来源的字幕副本。
- 支持在剪辑工作台修正文案、隐藏或恢复字幕、恢复 ASR 原文，并提供冲突保护和保存反馈。
- 以句段时间生成确定性的 Unicode 字素级逐字显示计划，并让长句稳定分页而不截断。
- 让播放器、字幕轨和 MP4 导出使用相同的文本、时间计划、换行与固定样式。
- 通过 additive migration 兼容现有数据库和工程，不影响原始 ASR、高光候选、录像及既有成品文件。

**Non-Goals:**

- 不修改 Whisper 调用协议，不采集或保存 token/word 真实时间戳。
- 不支持字幕拆分、合并、拖动、手动调时或跨句自动纠错。
- 不提供字体、字号、颜色、位置、模板和动画的用户配置。
- 不修改 AI 工作区的原始 ASR 浏览结果，也不把工程修正反向传播到其他工程。
- 不删除或覆盖已经导出的 MP4；字幕修改只让工程状态要求重新导出。

## Decisions

### 1. 将 ASR 投影固化为工程级字幕副本

新增 `ai_clip_subtitles` 表，以 `clip_project_id` 和 `clip_segment_id` 归属字幕，并保存 `stable_segment_id`、裁剪后的源时间、`original_text`、当前 `text`、`hidden`、创建和更新时间。`UNIQUE(clip_segment_id, stable_segment_id)` 防止同一片段重复回填，外键使用 `ON DELETE CASCADE`，移除剪辑片段时只删除其工程字幕副本。

首次创建工程、追加候选或打开尚未回填的旧工程时，在同一事务内从当前已发布稳定句段生成副本。此后重排只重新计算工程时间，ASR 重跑不会覆盖副本；不同工程即使引用同一稳定句段，也分别保存修正。

选择工程副本而不是修改 `transcript_segments`，是为了保持 ASR 缓存指纹和高光证据稳定，并避免一次成片修正意外改变其他项目。只保存差异覆盖虽然更省空间，但会继续依赖可变的当前 ASR 投影，也难以处理 ASR 重新发布，因此不采用。

### 2. 使用工程版本执行乐观并发和导出门禁

字幕更新 DTO 只接受 `subtitleId`、规范化后的文本、隐藏状态和 `expectedProjectVersion`。事务先验证字幕属于工程、工程版本一致且未处于 `exporting`，再更新字幕、递增工程版本、清除上次错误并把已完成导出状态恢复为 `idle`；保留磁盘上的旧 MP4，不把它继续标记为当前版本成品。

文本在后端去除控制字符、合并空白并限制为 500 个 Unicode 字素簇；空文本被拒绝，用户需要通过“隐藏字幕”表达不输出。恢复原文把 `text` 重置为不可变的 `original_text` 并取消隐藏。相比最后写入获胜，工程版本可明确阻止两个窗口或迟到请求覆盖彼此。

### 3. 由 Rust 生成唯一的字幕显示计划

新增纯函数字幕计划器，输入工程字幕、输出尺寸和工程总时长，输出按时间排序的显示帧。计划器使用 `unicode-segmentation` 切分字素簇，并通过固定标点表把标点和空白附着到前一个可发音字素；前导标点附着到后一个字素。

每个句段的显示单元在前 85% 时长内依次出现：首个单元在句段开始显示，最后一个单元在 85% 边界显示，完整末页保持到句段结束。单字句从开始保持到结束。句段结束后不生成延长帧，空白区不残留上一句。重叠句段继续确定性选择工程开始时间最晚、稳定 ID 最大的记录。

长句根据受控中文字体、输出尺寸、安全宽度和最小字号预先换行为最多两行的页面；各页按显示单元数分配句段时间。每一帧同时包含完整页面、可见前缀和隐藏后缀，前端预留完整布局后只显示前缀，因此逐字出现不会触发重新换行。分页和显示帧由后端随工程详情返回，导出端直接复用同一计划，不在 TypeScript 中重写算法。

采用句段内均匀分布是因为当前数据没有真实字级时间。按固定“每秒字符数”会在语速变化时越过句段边界；重新运行 ASR 获取 token 时间则扩大识别协议和资源兼容范围，留待独立变更。

### 4. 在现有工作台加入字幕轨和右侧字幕模式

时间轴保留单一视频轨，并在其下增加非拖动的字幕轨。字幕块按工程时间和片段边界定位，隐藏字幕使用弱化样式；点击字幕块会选择所属视频片段、定位播放头并打开右侧字幕编辑模式。

右侧属性区增加“片段 / 字幕”分段控件。字幕模式提供工程内搜索、当前片段过滤、可滚动列表、当前播放字幕高亮、文本框、隐藏/恢复和恢复 ASR 原文操作。文本只在失焦或 `Cmd/Ctrl + Enter` 时提交，`Escape` 放弃未保存草稿；界面明确显示“未保存、保存中、已保存、保存失败、版本冲突”。搜索只影响列表，不改变时间轴和导出内容。

不在画面上直接编辑文字，是为了避免播放器控制、缩放和中文输入法组合事件互相干扰；右侧固定编辑区在长工程中也更容易检索和校对。

### 5. 使用无背景固定样式并保持预览与导出语义一致

固定样式为底部居中、白色半粗体、黑色描边、轻微阴影、画面左右安全边距和最多两行。Rust 渲染器移除矩形背景填充，改为先绘制阴影和扩张后的黑色字形遮罩，再绘制白色字形。透明画布及 FFmpeg 参数白名单保持不变。

前端根据后端返回的页面、换行和可见前缀使用同一组样式常量。WebView 与 `fontdue` 的光栅化结果可能存在亚像素差异，但文本、页码、换行、出现时间、描边颜色、相对字号和安全位置必须一致；自动化契约测试以这些可观察属性为准，而不要求跨平台逐像素相同。

### 6. 区分“缺少字幕来源”和“用户主动隐藏”

字幕完整性仍要求每个剪辑片段至少存在一条从有效 ASR 句段建立的工程字幕记录。用户主动隐藏部分或全部已有记录不代表数据缺失，因此不阻止导出；从未取得有效句段的片段继续阻止导出。这样既保留原有的数据门禁，也允许用户有意制作短暂无字幕的片段。

### 7. 保持 Tauri 和 FFmpeg 安全边界

前端不能提交 `original_text`、源时间、工程时间、分页、字体、图片路径、滤镜或参数。所有归属、时间、版本、文本长度和导出状态在 Rust command/repository 中再次校验。字幕临时资源继续位于应用缓存或系统临时目录，并在成功、失败、取消和异常路径清理。

## Risks / Trade-offs

- [均匀逐字时间不等同真实发音时间] → 在界面和文档中说明其来自句段时间估算；未来以独立 migration 接入真实 token 时间戳。
- [长句逐字帧可能增加工程详情和 PNG 数量] → 限制单条字幕字素数、合并相同帧、按当前工程生成，并在导出结束后清理临时资源。
- [平台字体和 WebView 字形略有差异] → 由后端固定分页和换行，使用一致的相对尺寸、描边和位置契约测试，避免依赖浏览器自行换行。
- [旧工程首次打开需要写入回填数据] → 使用短事务、唯一约束和幂等插入；失败时不修改原工程并返回可重试错误。
- [字幕修改与导出竞态可能生成旧内容] → 导出期间后端拒绝编辑，并以工程版本绑定导出快照；前端禁用控件只是辅助。
- [回退旧版本时旧客户端看不到工程字幕副本] → migration 只新增表且不删除原数据；回退前保留新版本数据库备份，并避免用旧客户端重新导出已修正工程。

## Migration Plan

1. 增加下一顺序 SQLite migration，创建 `ai_clip_subtitles`、唯一约束和查询索引，不改动既有表和记录。
2. 扩展 repository，在新工程创建和片段追加事务中写入字幕副本；旧工程打开时仅为尚无副本的片段执行幂等回填。
3. 发布扩展后的 DTO 和 Tauri command，再切换前端读取工程字幕与显示计划；迁移期间不存在前端直接访问新表的路径。
4. 切换导出端复用工程字幕计划并移除背景矩形，完成旧工程、编辑工程和隐藏字幕工程的回归测试。
5. 如需回滚应用版本，保留新增表和数据，不执行降级删除；重新升级后修正文案仍可恢复。

## Open Questions

无。字幕作用域、编辑能力、逐字算法、长句分页、固定样式、空白行为和导出门禁均已确认采用推荐方案。
