## ADDED Requirements

### Requirement: 允许已授权智能任务自动启动精彩运行
系统 SHALL 允许 Rust 编排器为已完成 ASR 且输入指纹一致的智能成片子项目自动创建精彩运行，但 MUST 在创建前验证当前任务授权、客户端激活、Provider、模型、文本发送范围和批次代次。该例外 MUST 只作用于关联智能任务；普通 AI 项目继续要求用户显式授权，并且 Agent 的工具权限、结构校验、冻结 Skills 和评分阈值 MUST 与手动运行一致。

#### Scenario: 自动启动本地任务精彩
- **WHEN** 已授权本地智能任务完成 ASR，激活和 Provider 门禁有效且不存在相同运行指纹的完整结果
- **THEN** Rust 编排器创建精彩运行、冻结 Skills 与阈值并进入既有分块流程

#### Scenario: 复用相同精彩结果
- **WHEN** 智能任务对应的转写、输入、标签、Skills、模型、Prompt 版本和参数指纹已有完整精彩结果
- **THEN** 系统复用该结果并将阶段标记为缓存命中，不再次调用 Provider

#### Scenario: 普通项目完成 ASR
- **WHEN** 一个未关联智能任务的普通 AI 项目完成 ASR
- **THEN** 系统不得自动创建精彩运行，继续展示发送预估并等待用户显式授权

### Requirement: 为直播分片携带有限相邻上下文
系统 SHALL 允许智能直播批次在候选发现阶段携带前一完整批次末尾的有界稳定句段作为只读上下文，并 MUST 以来源视频、稳定句段和规范化会话时间标记上下文边界。全局评分和候选发布仍 MUST 只引用本地可验证的真实句段；系统 MUST NOT 读取活动分片、把上下文复制成新 ASR 产物或让单个物理候选跨越未登记媒体。

#### Scenario: 分析相邻完整分片
- **WHEN** 新直播批次存在已完成的直接前序批次
- **THEN** 系统按冻结预算附带前序末尾句段、明确来源边界并将当前完整分片作为主要分析输入

#### Scenario: 没有前序完整批次
- **WHEN** 当前批次是首个批次或前序批次不可用
- **THEN** 系统只分析当前冻结转写且不等待或读取正在写入的媒体

#### Scenario: 候选引用上下文和当前句段
- **WHEN** Agent 返回一个跨相邻完整分片边界的候选建议
- **THEN** Rust 只在所有引用句段和真实源内区间均可验证时，将其交给智能任务候选账本形成多来源逻辑候选

### Requirement: 向智能任务发布可合并的候选结果
系统 SHALL 在每个智能直播批次完成本地去重和全局评分后，将全部合法候选连同批次 ID、视频库 ID、稳定句段、真实源内时间、规范化会话时间、评分和阈值快照发布给智能任务候选账本。精彩运行自身 MUST 保持不可变；跨批次合并、自动入选和草稿更新 MUST 由父工作流完成，不得回写或删除原运行候选。

#### Scenario: 批次发布评分候选
- **WHEN** 一个直播子项目完成精彩全局评分
- **THEN** 系统原子发布该运行结果，并向父任务提交具有真实来源映射的候选集合

#### Scenario: 父任务合并重复候选
- **WHEN** 父任务判定新候选与历史候选属于同一逻辑精彩
- **THEN** 原精彩运行和两个候选记录保持不变，父任务只更新合并账本及其草稿选择

#### Scenario: 单个批次精彩失败
- **WHEN** 某直播批次的分块、校验或评分失败
- **THEN** 系统保留其他批次的已发布候选和父任务草稿，并允许只重试该批次的失败阶段
