## Context

当前客户端已经把公开抖音直播保存为有音频信息、可恢复且按时间登记的 MKV 分片，并通过视频库维护录像会话和完成分片。AI 剪辑页面仍是占位页，现有规格明确禁止该页面创建任务或读取媒体；预览 MP4 又是可清理缓存，不能作为 ASR 输入。因此本变更需要跨越 React 页面、Tauri command、SQLite、后台任务、FFmpeg/FFprobe 和新的本地模型进程，同时保持录制核心不依赖 Tauri 且不降低录制可靠性。

讨论已经确认以下产品约束：视频流没有可提取字幕；ASR 不随录像自动运行；用户在 AI 剪辑页面导入多个本地视频，或选择一场直播并将其展开为多个视频；第一版以 8 GB 内存设备为最低基线，使用本地 `whisper.cpp` 和多语言 small 量化模型；macOS arm64 与 Windows x64 均须可分发；本次不调用云端服务，只为后续剪辑建立可靠的文本时间轴。若真实中文直播效果不达标，后续通过新的 OpenSpec 变更增加用户明确选择的云端 `AsrEngine` Adapter，而不是在本版自动回退。

## Goals / Non-Goals

**Goals:**

- 提供由用户主动创建、整理、开始、取消、恢复和删除的多视频 AI 分析项目。
- 将本地导入视频和已结束直播会话统一解析成有序、可验证的视频输入列表。
- 以原始视频为输入，通过 FFprobe、FFmpeg、VAD 和本地 `whisper.cpp` 生成中文句段转写。
- 定义不包含 Whisper 专属字段的统一 `AsrEngine` 请求、结果、能力和错误契约，让后续引擎通过新 Adapter 接入。
- 同时保留单视频时间轴和项目累计时间轴，为后续搜索、精彩识别和切片定位提供稳定数据。
- 在 AI 工作区提供按视频组织的播放器与时间戳文本联动，允许点击句段跳转、播放时高亮、可选跟随滚动和仅在 WebView 中显示的临时字幕覆盖。
- 支持复制与导出 TXT/JSON 文本产物，并让每个句段拥有可供未来 LLM 标注和剪辑计划引用的稳定 ID。
- 让识别引擎、VAD 和媒体准备能力通过 Rust 接口隔离；第一版只实现 Rust `WhisperCppEngine` Adapter 调用原生 sidecar。
- 持久化可恢复状态并复用相同源版本、相同识别配置的转写结果，且不修改或复制原始视频。
- 通过单并发调度、录制优先门控和临时文件治理，避免 ASR 破坏现有录制可靠性。
- 为 macOS arm64 和 Windows x64 提供平台匹配的原生 sidecar、随包 small 多语言量化模型与 VAD 模型、完整性校验和任务前环境检查。

**Non-Goals:**

- 不实现录制完成后的自动识别、直播中实时字幕或流式 ASR。
- 不实现通用 Provider 进程协议、插件扫描、动态 Provider 安装或 Provider 独立升级。
- 不实现 Python、Go 或 Node.js Provider，不随第一版安装包携带这些语言运行时。
- 不实现云端 ASR、自动云端回退、音视频上传、云端凭据或远程模型调用；云端能力只通过中立接口预留未来适配空间。
- 不实现在线模型下载、离线模型导入、多模型切换或用户自定义模型路径。
- 不实现说话人身份、多人分离、情绪、掌声、笑声等声音事件识别。
- 不实现人工编辑转写、SRT/ASS 字幕导出、字幕样式编辑、可缩放/拖动/切割的图形化剪辑时间轴。
- 不实现 NLP/LLM 精彩评分、自动切片、视频拼接、字幕烧录、转码导出或成品管理。
- 不识别仍在写入的录像分片，也不把进行中的直播会话动态追加到已开始的项目。
- 不在第一版支持 Intel Mac、Windows ARM64、Windows CUDA/Vulkan 可选加速或第三方模型市场。

## Decisions

### 1. 以用户触发的项目作为业务边界

AI 剪辑页面使用“项目”组织一次多视频分析。项目先处于 `draft`，只有用户确认有序输入并点击开始分析后才进入 `queued`。录像完成事件不会创建项目、输入或 ASR 任务。

项目状态使用 `draft`、`queued`、`running`、`completed`、`completed_with_errors`、`cancelled` 和 `failed`；每个输入独立维护 `pending`、`validating`、`preparing_audio`、`detecting_speech`、`transcribing`、`completed`、`skipped`、`cancelled` 和 `failed`。单个输入失败时项目可以继续，全部输入均不可处理时项目才进入 `failed`。

选择项目而不是“完成分片即任务”，是因为用户明确要求主动分析，而且项目天然承载输入顺序、热词、模型配置和跨视频时间轴。自动识别会浪费大量本地资源，也会在用户不需要 AI 剪辑时产生数据，因此不采用。

### 2. 两种入口统一为不可变的有序输入快照

本地“上传”在桌面客户端中表示通过文件选择器导入本机文件，不发生网络上传。外部视频只保存经过后端规范化和授权验证的路径、大小、修改时间及媒体元数据，不复制大文件。选择直播会话时仅接受已结束会话，并按录制时间把全部已登记的完成分片展开为输入。

草稿阶段允许重排和移除输入；开始分析时冻结输入顺序和源指纹。外部文件被移动、删除或修改时，对应输入独立失败或失效。采用引用而不是复制可避免成倍占用磁盘，但代价是外部源可能丢失；界面必须在开始前和执行时都重新校验。

### 3. Rust 核心定义中立 `AsrEngine` 契约，Tauri 只负责适配

新增的核心边界包括 `AiProjectRepository`、`AiInputResolver`、`MediaAudioPreparer`、`VadEngine`、`AsrEngine`、`TranscriptAssembler` 和 `AiJobPublisher`。Tauri 层负责 command、文件选择授权、SQLite 实现、事件发布和进程生命周期，核心状态机与时间轴合并逻辑可在无 WebView 环境下测试。

`AsrEngine` 接受经过媒体层准备的音频资产、语言提示、热词和时间戳策略，返回引擎/模型身份、语言、时长、句段时间边界、原始文本、可选置信信息和统一警告。接口同时暴露引擎能力与环境校验，并使用统一错误分类。请求和结果不得包含 `whisper.cpp` 命令行参数、sidecar 路径或其他供应商专属字段。

```text
React AI 工作区
       │ Tauri command / event
       ▼
AiProjectService ───────▶ SQLite
       │
       ▼
TranscriptionScheduler（全局单并发）
       │
       ├─▶ InputResolver / FFprobe
       ├─▶ FFmpeg AudioPreparer
       ├─▶ VAD
       ├─▶ AsrEngine
       │       └─▶ WhisperCppEngine ─▶ whisper.cpp sidecar
       └─▶ TranscriptAssembler / ArtifactStore
```

第一版不实现通用进程 Provider 协议。业务层依赖 `AsrEngine`，`WhisperCppEngine` 作为 Rust Adapter 直接管理官方 `whisper.cpp` CLI sidecar。等第二个引擎真正进入范围后，再根据实际差异评估是否抽取 `ProcessAsrEngine` 和跨语言 Provider 协议，避免在只有一个实现时提前承担插件扫描、协议版本和动态安装复杂度。

不把模型调用直接写进页面 command，也不复用预览服务生成的 MP4，因为长任务需要在窗口隐藏或页面重建后继续，且现有规格要求原始媒体独立于预览缓存。

### 4. 使用 FFmpeg 准备短期音频，使用 VAD 约束识别范围

每个输入先由 FFprobe 获取音轨、时长和格式。FFmpeg 从原始文件解码为 16 kHz、单声道、16-bit PCM。执行器优先使用进程管道；若首个 `whisper.cpp` 适配器需要文件输入，则在 Tauri 缓存目录创建项目隔离的临时 WAV，并在成功、失败、取消和下次启动恢复时清理。

VAD 只判断人声区间，不负责识别文本。检测区间前后默认保留约 500 毫秒保护边界，避免切掉首尾音节；完全没有有效人声的输入进入 `skipped`，不伪造空白转写。VAD 参数和模型版本属于识别配置的一部分。

替代方案是把完整音轨直接交给 Whisper，但直播中的静音、纯音乐和挂机内容会增加耗时并提高无中生有文本的风险，因此不采用。

### 5. 首个引擎采用 Rust Adapter 调用原生 `whisper.cpp` sidecar

`WhisperCppEngine` 通过受控子进程调用随安装包提供的平台匹配 `whisper.cpp` CLI。macOS arm64 包提供启用 Metal 的 arm64 sidecar；Windows x64 包提供不依赖独立显卡的 CPU sidecar。模型文件与操作系统无关，可以在两个平台共享相同版本和哈希。第一版不支持 Intel Mac、Windows ARM64 或 Windows CUDA/Vulkan 构建。

Rust Adapter 负责从应用资源目录解析 sidecar，使用参数数组而不是 shell 字符串启动进程，解析结构化输出，发布进度，响应取消并脱敏 stderr。生产环境不允许用户把任意可执行路径写入普通设置；开发环境可以提供显式覆盖。每个输入启动一次 CLI，输入完成后进程退出并释放模型内存。重复加载模型会带来固定开销，但第一版以简单、隔离和可取消为优先，不实现常驻模型进程。

引擎返回源文件内的句段开始时间、结束时间、原始文本以及模型能够提供的置信信息。置信信息不可用时保存为空，不根据经验值伪造。模型标识、文件指纹、引擎版本、语言、VAD 配置和热词配置共同组成 `recognition_profile`。

第一版以 8 GB 内存设备为最低基线，默认推荐多语言 small 量化模型；用户可以在后续版本选择更高质量模型，但任务开始前必须检查模型预计内存、当前可用内存和磁盘空间。若 small 模型在真实中文直播样本上的商品名、金额或整体可读性不达标，本变更不自动上传或切换云端，而是记录基准结果并为后续云端 API Adapter 变更提供依据。

备选的 faster-whisper 需要附带 Python/CTranslate2 运行环境，FunASR 需要额外 Python/模型分发，Go 或 Node.js Adapter 也只有在出现具体 Provider 时才有价值，因此均不进入第一版安装包。

### 6. 默认模型随安装包分发并在任务前严格检查

macOS arm64 与 Windows x64 安装包均携带主程序、平台匹配的 FFmpeg/FFprobe、`whisper.cpp` sidecar、一个面向 8 GB 设备的 small 多语言量化模型、兼容 VAD 模型和资源 manifest。模型文件与平台无关，两个安装包使用相同模型版本和 SHA-256；第一版不包含在线下载器、离线导入、多模型管理或用户自定义模型路径。

模型和 VAD 文件作为只读应用资源使用。macOS 从签名 `.app` 的 Resources 解析，Windows 从受安装器保护的资源目录解析；业务项目和数据库只保存逻辑模型 ID、模型版本及识别配置指纹，不保存可由前端修改的任意模型路径。模型升级跟随新的应用版本发布。

每次任务开始前必须检查平台 sidecar 是否存在且可执行、sidecar 版本、资源 manifest、ASR/VAD 模型文件存在性、大小、SHA-256、磁盘空间和可用内存。任一关键检查失败时项目保持草稿或环境不可用状态，不启动 FFmpeg、VAD 或 ASR，也不创建自动重试。界面提供重新检测和安装修复说明；模型缺失或损坏时提示用户重新安装当前应用版本。

正式发行需要固定模型来源、许可证、版本清单和哈希，对 macOS 主程序及全部 sidecar 完成签名与 notarization，并对 Windows 安装包和 sidecar 完成代码签名、VC++ 运行库及 SmartScreen 验证。第一版识别和资源准备均不需要联网。

### 7. 分层保存项目、输入、可复用产物和转写片段

SQLite 新增以下逻辑实体：

- `ai_projects`：名称、状态、识别配置、累计进度、错误和生命周期时间。
- `ai_project_inputs`：项目、顺序、来源类型、可选视频库 ID、本地路径快照、源指纹、时长、项目偏移和输入状态。
- `asr_artifacts`：源指纹、识别配置指纹、引擎/模型版本、状态、创建时间和最后使用时间。
- `transcript_segments`：稳定句段 ID、产物、源内开始/结束毫秒、原始文本、规范化文本和可选置信信息。

项目输入引用可复用产物，而不是复制转写。删除项目只删除项目及关联输入；没有任何项目引用的 ASR 产物按缓存清理策略回收。删除原始录像时必须使相关产物失效并清理；删除 ASR 数据不得修改录像或外部视频。

### 8. 不拼接视频，只合并逻辑时间轴

每个视频独立探测和识别。项目累计时间偏移等于前面输入的可靠媒体时长之和，转写同时保存 `source_start_ms/source_end_ms` 与计算得到的 `project_start_ms/project_end_ms`。选择同一直播会话产生的连续分片时，下一分片可以使用上一分片末尾的有限文本作为识别提示，并通过有界的后缀/前缀匹配消除模型重复；普通外部视频之间不共享上下文。

物理拼接视频或长期生成合并音频会增加磁盘、失败恢复和时间轴漂移风险，因此不采用。若某个输入失败，后续输入仍根据已探测时长保留稳定项目偏移，并在项目时间轴中明确标记空洞。

### 9. 复用由源指纹和识别配置共同决定

源指纹至少包含规范路径、文件大小和修改时间；录制库视频还包含稳定视频 ID。识别配置指纹包含引擎、模型、语言、VAD 参数、时间戳策略、文本规范化版本和热词。两类指纹完全相同时复用已完成产物；任何一项改变均创建新产物，失败或未完整发布的产物不得复用。

产物先写入临时记录，全部片段通过事务发布后才进入可复用状态，从而避免崩溃后读取半成品。

### 10. ASR 全局单并发并服从录制优先策略

ASR 使用独立队列和一个全局执行许可，不占用录制并发许可。默认只在没有活动录制时派发新的 ASR 工作；录制开始后不再派发新的人声片段，当前有界片段结束后让出资源。调度器限制 `whisper.cpp` 线程数并在每个输入完成后退出 sidecar、释放统一内存。窗口隐藏不停止任务，显式退出、用户取消或源失效会取消子进程并持久化可恢复状态。

这一策略牺牲识别即时性，但符合当前“可靠录制优先”的产品阶段。未来可在性能数据充分后增加用户可配置并发和电源策略，本次不开放。

### 11. 后端掌握路径、进程和本地数据边界

前端只提交文件选择器返回的授权项或视频库/会话 ID，不得构造任意路径启动 FFmpeg 或模型。后端规范化路径、验证普通文件、限制临时目录和子进程参数，并对界面事件及日志中的本地路径和模型错误进行脱敏。第一版识别流水线和模型准备不得发起网络请求或上传业务数据。

### 12. 第一版 UI 使用播放器与时间戳文本联动

AI 工作区左侧显示有序视频输入及识别状态，右侧显示当前视频播放器和该视频的时间戳文本列表。宽屏时播放器与文本左右排列，较窄窗口时播放器在上、文本在下；第一版不使用多轨道、缩放、拖动或裁剪工具组成的专业时间轴。

播放器复用现有预览服务准备的可播放媒体，但该预览结果只服务 UI 播放，ASR 仍读取原始视频。前端根据播放器 `currentTime` 在已加载句段中定位当前 `start_ms <= currentTime < end_ms` 的文本：点击文本行时播放器跳转，播放时高亮当前行；用户可以开启“跟随播放”让列表自动滚动，也可以关闭跟随后自由阅读。

播放器提供“显示字幕”开关。开启后，前端用普通 WebView 元素把当前规范化文本覆盖在视频画面底部；关闭播放器或切换视频后立即清理。该覆盖不生成字幕文件、不修改视频、不进入预览缓存，也不使用 FFmpeg 渲染。

转写列表是第一版的逻辑时间轴：每行展示源内开始/结束时间、规范化文本和可选低置信提示。第一版允许复制单段、当前视频全文和整个项目全文，并导出人类可读 TXT 与包含项目、输入、稳定句段 ID、视频 ID、源内/项目时间范围、原始/规范化文本及可选置信信息的 JSON。第一版不允许编辑、拆分、合并或拖动句段。

后续 LLM 能力必须返回稳定句段 ID 或明确时间范围，而不是只返回复制文本。UI 可以在现有列表上增加分类、评分、理由和颜色标记；只有进入真正裁剪阶段时才另行设计图形化时间轴和剪辑计划编辑器。

## Risks / Trade-offs

- [8 GB 基线使用的多语言 small 量化模型可能无法满足中文直播商品名、金额和背景音乐场景] → 建立真实直播评测集，支持每项目热词和文本规范化；若关键指标不达标，保留本地结果并通过后续独立变更评估用户授权的云端 API Adapter，不在本版自动上传。
- [VAD 过于激进会切掉首尾语音，过于宽松又会增加耗时] → 使用保守阈值与 500 毫秒边界保护，把配置写入产物指纹并用真实样本校准。
- [外部视频仅保存引用，文件可能被移动或修改] → 开始前与执行时双重校验源指纹，逐项报告失效且不阻塞其他输入。
- [本地模型可能抢占 CPU、统一内存和电量] → 以 8 GB 设备和 small 量化模型为基线，全局单并发、录制优先门控、限制线程、分段执行并在每个输入后退出 sidecar；首版不承诺后台实时完成。
- [安装包中的模型缺失、损坏或与 manifest 不一致会让任务不可用] → 任务前校验文件大小与 SHA-256，阻止任务并提示重新安装；安装器、应用和模型资源使用同一版本清单。
- [`whisper.cpp`、FFmpeg、模型和 VAD 文件增加跨平台发行与许可复杂度] → 固定 macOS arm64 与 Windows x64 CPU 构建矩阵，完成来源和许可证清单、macOS 签名/notarization、Windows 代码签名、VC++ 运行库和 SmartScreen 验证。
- [Windows 中文路径、空格路径或 CPU 指令集差异导致 sidecar 启动失败] → 使用参数数组和 Unicode 路径 API，明确最低 CPU 指令要求，并在目标 Windows 设备上覆盖安装与任务前诊断。
- [多文件时长不准确会造成项目时间轴漂移] → 使用 FFprobe 的可靠时长，以整数毫秒保存，并在缺少可靠时长时禁止合并而不是猜测。
- [应用崩溃可能遗留临时音频或半成品转写] → 使用项目隔离临时目录、事务发布和启动清理，运行中状态恢复为可重试队列状态。
- [有限文本去重可能误删真实重复话术] → 只对同一录制会话的相邻分片启用，限制匹配窗口并同时保留不可变原始分片转写。
- [长直播产生大量句段会让文本列表渲染和自动跟随变慢] → 按当前视频分页或虚拟化渲染句段，只在播放位置变化到新句段时更新高亮，并允许用户关闭跟随播放。
- [播放器预览时间与原始媒体时间戳存在偏移] → 使用源视频内毫秒时间作为唯一定位基准，在预览准备后验证时长一致性；无法可靠定位时仍展示文本但禁用跳转和字幕覆盖。

## Migration Plan

1. 增加向前迁移，创建 AI 项目、输入、ASR 产物和转写片段表；不修改现有录像表和文件。
2. 定义中立 `AsrEngine` 契约、能力与错误分类，使用假引擎验证业务层不依赖 Whisper 专属字段。
3. 增加 macOS arm64 与 Windows x64 sidecar 及随包模型资源解析、版本诊断、manifest 和完整性校验。
4. 实现 Rust `WhisperCppEngine` Adapter，接入 FFprobe、FFmpeg、VAD 与平台 `whisper.cpp` CLI，并用固定测试媒体验证时间戳、取消、恢复、中文路径和临时文件清理。
5. 引入持久化状态机、全局单并发调度器、录制优先门控、8 GB 内存检查和输入完成后的 sidecar 释放。
6. 用 AI 项目工作区替换占位页，分阶段开放本地导入、会话选择、环境检测、任务运行、播放器联动文本、临时字幕覆盖和 TXT/JSON 导出。
7. 在 macOS arm64 与 Windows x64 目标机使用真实中文直播样本完成 small 量化模型和 VAD 基线验收；若效果不达标，记录指标并另立云端 API Adapter 变更。

回滚时可以恢复 AI 占位页并停用调度器；新增表和本地缓存可保留以避免丢失用户转写，也可由明确的数据清理操作删除。录制、视频库和原始文件不需要回滚。

## Open Questions

- 默认 small 多语言量化模型的具体量化格式、可信来源、许可证和随应用版本更新周期，需要在打包前通过 macOS arm64 与 Windows x64 基准确定。
- 8 GB 目标设备上允许 `whisper.cpp` 使用的默认线程数、最低空闲内存和可接受实时因子，需要通过目标机测量确定。
- macOS 正式启用 App Sandbox 后，外部视频的持久访问是否采用 security-scoped bookmark，需要与最终签名和商店分发方式一起决定。
- 若 small 模型中文效果不达标，后续云端 API Adapter 的供应商、费用、用户授权和数据保留策略由独立变更决定，本变更不预选供应商。
