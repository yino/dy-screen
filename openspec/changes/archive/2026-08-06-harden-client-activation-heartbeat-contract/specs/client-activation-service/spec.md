## ADDED Requirements

### Requirement: 在系统安全存储中保存授权秘密
系统 SHALL 通过可测试的安全凭据存储边界保存完整设备 ID、激活码和离线 token，并 MUST 在 macOS 和 Windows 生产构建中使用操作系统安全凭据存储；SQLite MUST NOT 在迁移完成后保存完整设备 ID、激活码、token 或其他授权秘密。本期继续使用明文 JSON API，系统 MUST NOT 因此生成、保存或伪装使用尚未实现的设备签名私钥或 `encKey`。

#### Scenario: 新激活保存秘密
- **WHEN** 激活接口与同步心跳均确认授权有效
- **THEN** 系统将完整授权秘密写入操作系统安全凭据存储，并只在 SQLite 保存状态、有效期、心跳时间、策略字段和脱敏设备提示

#### Scenario: 迁移旧版明文记录
- **WHEN** 启动时发现旧 SQLite 授权记录仍包含完整设备 ID、激活码或 token
- **THEN** 系统先写入并回读验证安全凭据，再以事务清除数据库秘密字段；迁移中断时不得删除唯一可用凭据或错误解锁主界面

#### Scenario: 安全凭据存储不可用
- **WHEN** 操作系统安全凭据存储写入、读取或删除失败
- **THEN** 系统保持激活门禁并返回稳定的安全存储错误，不得回退为 SQLite 明文保存

#### Scenario: 清除授权
- **WHEN** 用户重新激活或服务端确认授权失效并要求清理秘密
- **THEN** 系统幂等删除对应安全凭据和不可继续使用的 token，同时保留不含秘密的诊断状态供界面展示

### Requirement: 输出可关联且脱敏的授权 API 诊断
系统 SHALL 在统一 Rust API 客户端边界为激活和心跳输出结构化请求与响应摘要，并 SHALL 捕获响应头 `x-request-id` 和可选 `x-trace-id`；日志 MUST 使用字段白名单，MUST NOT 输出完整设备 ID、激活码、token、原始请求或响应正文、Cookie、签名、完整查询参数或本地敏感路径。

#### Scenario: 记录激活请求
- **WHEN** 客户端开始并完成一次激活请求
- **THEN** 控制台日志包含方法、固定路径、阶段、耗时、HTTP 状态、业务码、参数字段是否存在、脱敏设备提示和请求关联 ID，不包含任何激活码或 token 值

#### Scenario: 记录心跳响应
- **WHEN** 心跳返回成功、强制下线或业务错误
- **THEN** 控制台日志包含业务码、稳定错误分类、`revoked/state/reason` 的安全摘要及关联 ID，并且不序列化原始响应正文

#### Scenario: 响应正文无效
- **WHEN** 服务端响应无法解析为统一业务信封
- **THEN** 系统仍记录已取得的 HTTP 状态、耗时和请求关联 ID，将正文归类为无效响应但不输出正文内容

#### Scenario: 其他客户端 API 正常返回
- **WHEN** 激活和心跳之外的客户端 API 正常完成
- **THEN** 系统不输出逐请求成功日志；发生失败时只输出相同脱敏结构的错误摘要

## MODIFIED Requirements

### Requirement: 统一封装客户端授权 API
系统 SHALL 在 Rust 中提供单一 API 客户端封装，集中读取 `DY_SCREEN_API_BASE_URL`、规范化 `/api/` 前缀、处理 HTTP 恒 200 的业务 `code`、超时、请求关联头和脱敏错误；激活、心跳、AppStart、埋点及其他需授权 API 的业务代码 MUST NOT 直接创建 HTTP 客户端。客户端 SHALL 在所有需授权请求中同时发送权威 `device_id`、`activate_code` 请求头和兼容 `device-id`、`activate-code` 别名。本期 SHALL 保持明文 JSON 编解码，不实现信封加密、请求签名或 `encKey` 轮换。

#### Scenario: 配置服务端地址
- **WHEN** 启动时设置 `DY_SCREEN_API_BASE_URL=http://localhost/api/`
- **THEN** 所有客户端请求都发送到该地址下的 `/client/...` 路径，并且不在日志中输出完整查询参数

#### Scenario: 发送需授权请求头
- **WHEN** 心跳或其他需授权接口发出请求
- **THEN** 统一客户端同时发送 `device_id`、`activate_code`、`device-id` 和 `activate-code`，且任何业务调用方都不能自行复制或改写凭据

#### Scenario: 代理丢失权威请求头
- **WHEN** 客户端确认已构造授权请求头但服务端返回 `1001` 或 `2001`
- **THEN** API 客户端返回稳定的请求头契约错误分类和关联 ID，提示检查代理下划线请求头配置，不把该结果伪装成普通网络错误

#### Scenario: 服务端返回业务错误
- **WHEN** HTTP 状态为 200但响应 `code` 不是允许的成功或强制下线码
- **THEN** API 客户端返回包含业务码、稳定错误分类、中文安全消息和请求关联 ID 的错误，不把原始响应正文传播到前端

#### Scenario: 保持明文 JSON 编解码
- **WHEN** 激活、心跳或其他客户端接口编码请求并解析响应
- **THEN** 系统使用现有明文 JSON codec，且不得发送未完整实现的信封头、设备签名或伪造的加密正文

### Requirement: 激活前阻止桌面业务
系统 SHALL 在没有经服务端完整确认的有效授权时显示不可关闭的激活入口，并 MUST NOT 恢复监听、录制、视频处理或其他依赖授权的后台任务。激活接口返回成功仅 SHALL 使状态进入 `verifying`；系统 SHALL 在同一次激活 command 内立即执行同步心跳，只有心跳返回 `code=200`、`revoked=false` 且 `state=ACTIVE` 时才发布 `active`、保存有效授权并恢复后台任务。

#### Scenario: 首次启动没有激活凭据
- **WHEN** 安全凭据存储和本地元数据中没有完整有效的激活记录
- **THEN** 客户端显示激活页，激活码为空时不能关闭页面或进入主功能

#### Scenario: 激活接口成功后验证心跳
- **WHEN** 用户提交有效激活码且激活接口返回 token 和有效期
- **THEN** 客户端保持主界面锁定并显示“正在验证”，使用同一设备和激活码立即发送一次心跳

#### Scenario: 激活与心跳均成功
- **WHEN** 紧随激活的同步心跳返回 `code=200`、`revoked=false` 和 `state=ACTIVE`
- **THEN** 客户端原子保存授权状态、关闭激活页、发布 `active` 并且只恢复一次已启用后台任务

#### Scenario: 激活请求确定失败
- **WHEN** 激活接口返回激活码不存在、格式错误、过期、停用或已绑定其他设备
- **THEN** 激活页保持打开并显示对应中文安全原因，既有用户输入不丢失且不启动后台任务

#### Scenario: 激活后心跳返回请求头契约错误
- **WHEN** 激活接口成功但同步心跳返回 `1001` 或 `2001`
- **THEN** 客户端不得短暂显示首页，状态进入 `contract_error` 并提示检查授权请求头及反向代理配置

#### Scenario: 激活后心跳暂时失败
- **WHEN** 激活接口成功但同步心跳发生网络、超时、`1007`、`9000` 或无效响应错误
- **THEN** 客户端保持激活门禁和用户输入，显示可重试状态，不发布 `active` 或恢复后台任务

### Requirement: 维护心跳并处理强制下线
系统 SHALL 在激活成功后按有界周期发送心跳，并 SHALL 处理服务端下发的 `serverTime`、令牌续签和 `revoked/state/reason`。`code=201`、`revoked=true`、非 `ACTIVE` 状态、确定的卡密错误 `1002~1006` 或设备错误 `2003~2004` MUST 停止授权依赖任务、清理不可继续使用的 token 并要求重新激活；`1001/2001` MUST 锁定主功能并进入请求头契约异常；网络、超时、`1007`、`9000` 和无效响应 MUST 进入有界重试而不得直接判定卡密失效。

#### Scenario: 心跳续约成功
- **WHEN** 心跳返回 `code=200`、`revoked=false`、`state=ACTIVE` 和 `reason=ok`
- **THEN** 客户端更新 token、有效期、服务端时间偏移和策略字段，保持监听运行并刷新授权状态

#### Scenario: 服务端强制下线
- **WHEN** 心跳返回 `code=201`、`revoked=true` 或状态为 `DISABLED`、`EXPIRED`、`INACTIVE`
- **THEN** 客户端幂等暂停后台任务、清除不可继续使用的 token、发布前端状态并重新显示激活入口

#### Scenario: 卡密或设备确定失效
- **WHEN** 心跳返回 `1002~1006` 或 `2003~2004`
- **THEN** 客户端按业务码显示卡密或设备原因、锁定全部主功能并要求重新输入激活码

#### Scenario: 请求头契约异常
- **WHEN** 心跳返回缺少 `activate_code` 的 `1001` 或缺少 `device_id` 的 `2001`
- **THEN** 客户端进入 `contract_error`、暂停授权依赖任务并显示代理部署诊断，不把重复输入同一激活码描述为必然可修复该问题

#### Scenario: 暂时网络或服务端失败
- **WHEN** 心跳请求因网络、超时、`1007`、`9000` 或无效响应失败
- **THEN** 客户端保留宽限期内的本地授权秘密和元数据，按有界退避重试并展示“正在重试”，不泄露请求地址或凭据

#### Scenario: 可恢复协议错误
- **WHEN** 心跳返回 `9104` 或 `9105`
- **THEN** 客户端使用已有服务端时间偏移或当前明文会话立即有界重试一次，重复失败后锁定主功能并要求重新激活

#### Scenario: 信封完整性错误出现在明文兼容期
- **WHEN** 心跳返回 `9101~9103`
- **THEN** 客户端记录协议不兼容诊断并有界重试一次，仍失败时锁定主功能并要求重新激活，不伪装已启用信封协议
