## MODIFIED Requirements

### Requirement: 安全配置 DeepSeek Provider
系统 SHALL 使用单一模型调用形态：客户端 Rust 侧持 `GET /api/client/ai/llm-ak` 签发的短期 token 直连阿里云百炼。系统 SHALL 只允许配置非敏感的合格/优秀精彩阈值、独立的转场自动应用阈值，以及白名单内的模型取值，并 MUST NOT 要求用户配置上游 API Key。合格与优秀阈值 MUST 为 0–100 的整数且优秀阈值不得低于合格阈值；转场自动应用阈值 MUST 为 0–10 的整数且默认值为 8。生产构建 MUST NOT 接受任意 Base URL、代理地址、浏览器端 Provider 配置或手输的上游凭据；短期 token 只来自 `ai/llm-ak`。

#### Scenario: 保存 DeepSeek 设置
- **WHEN** 用户提交非敏感参数、阈值与白名单内的模型取值
- **THEN** 系统保存这些字段、不保存任何上游凭据，并只向界面返回阈值、当前模型与解析来源

#### Scenario: 旧设置没有转场阈值
- **WHEN** 升级后的客户端读取尚未包含转场自动应用阈值的既有设置
- **THEN** 系统使用并持久化默认 8 分，且不改变既有精彩阈值与已配置的模型

#### Scenario: 保存无效精彩阈值
- **WHEN** 用户提交超出 0–100 范围的精彩阈值或优秀阈值低于合格阈值
- **THEN** 后端拒绝保存并返回中文校验说明，且保留已有有效设置

#### Scenario: 保存无效转场阈值
- **WHEN** 用户提交非整数或超出 0–10 范围的转场自动应用阈值
- **THEN** 后端拒绝保存并返回中文校验说明，且保留已有有效设置

#### Scenario: 提交任意 Provider 地址
- **WHEN** 生产构建的前端尝试提交自定义 Base URL、非白名单模型或手输的上游凭据
- **THEN** 后端拒绝该字段且不发起网络请求

#### Scenario: 切换模型
- **WHEN** 配置把模型标识改为白名单内的另一个取值
- **THEN** 系统在心跳周期边界产出新的不可变快照，此后新建的运行使用新模型，进行中的运行不受影响，且 MUST NOT 复用由其他模型产出的结果

#### Scenario: 重启后重新解析
- **WHEN** 应用重启后再次解析模型配置
- **THEN** 已发布结果按产出它的运行指纹匹配；指纹不一致时保留为历史建议且不自动应用，MUST NOT 丢弃已付费资产

### Requirement: API Key 不进入应用数据和日志
系统 MUST NOT 把短期 token、上游 API Key 或任何可用于调用上游模型的凭据写入 SQLite、设置 JSON、日志、事件、错误、剪贴板恢复数据或浏览器演示存储。`ai/llm-ak` 的短期 token SHALL 只保存在 Rust 内存中，按 `expireAt` 提前刷新，并在过期、重新激活或进程退出后释放。

#### Scenario: 查询 Provider 设置
- **WHEN** 界面读取当前设置
- **THEN** 系统只返回阈值、非敏感参数、更新时间、当前模型、解析来源与短期 token 是否可用，不返回任何凭据内容或可推断片段

#### Scenario: 清除凭据
- **WHEN** 用户在本机覆盖或设置中清理既有的上游凭据
- **THEN** 系统从操作系统凭据库删除该凭据、保留非敏感设置与阈值，并确保该凭据不再被任何链路使用，也不回显其内容

### Requirement: 提供有界连接诊断
系统 SHALL 针对当前生效的模型执行不包含用户转写的最小连接诊断，并 SHALL 返回脱敏分类、当前模型和可操作中文信息。

#### Scenario: 连接与模型可用
- **WHEN** 用户点击测试连接且短期 token 可获取、当前模型可用
- **THEN** 系统显示连接成功与当前模型，且不创建精彩运行或保存响应正文

#### Scenario: 凭据无效或被限流
- **WHEN** `ai/llm-ak` 签发失败、短期 token 已过期，或上游返回鉴权失败、模型不存在、额度耗尽、限流或暂时网络错误
- **THEN** 系统返回稳定错误码和中文说明，不记录响应正文、请求头或短期 token，并把额度耗尽与网络故障区分为不同分类

### Requirement: 仅在用户授权后发送最小文本
系统 SHALL 只在用户针对项目显式启动分析后，经客户端直连百炼发送必要的规范化转写、稳定句段 ID、相对时间、标签和分析目标，并 MUST NOT 发送视频、音频、本地路径、签名流地址或数据库内容。

#### Scenario: 查看分析预估
- **WHEN** 用户打开已完成 ASR 的精彩分析步骤
- **THEN** 系统显示将发送的数据类型、句段数、文本量、预计批次与当前模型，但不发起任何模型请求

#### Scenario: 用户确认开始分析
- **WHEN** 用户确认文本将发送到百炼并点击开始
- **THEN** 系统冻结本次最小请求上下文、模型快照与短期 token 状态，并创建可取消的精彩运行

### Requirement: 限制 Provider 重试与诊断数据
系统 SHALL 为每次请求设置超时和取消边界，只对限流或暂时网络错误最多自动重试两次，并 SHALL 仅记录脱敏 request ID、阶段、模型、耗时、token 用量（若上游返回）、分类和重试次数。对可能产生付费调用的请求，重试 MUST 复用同一本地幂等请求 ID。

#### Scenario: 请求暂时失败后恢复
- **WHEN** 第一次请求返回可重试错误且第二次成功
- **THEN** 系统以同一请求 ID 重试、保存一次重试计数和最终结构化结果，不重复已经完成的其他工作流阶段，也不产生重复付费

#### Scenario: 用户取消网络分析
- **WHEN** 用户取消精彩运行
- **THEN** 系统停止后续调用、忽略迟到响应并保留此前完整发布的阶段结果

## ADDED Requirements

### Requirement: 使用客户端短期 token 直连百炼
系统 SHALL 只用 `GET /api/client/ai/llm-ak` 返回的短期 token（`{ak, expireAt, provider}`，`provider=ALI`，形如 `st-lt-v1.xxx`）从客户端 Rust 侧直连百炼完成模型调用；系统 MUST NOT 引入服务端模型网关或网关令牌，MUST NOT 为此新增任何服务端接口。短期 token MUST 只在内存中持有；WebView MUST NOT 接触短期 token 或原始响应。

#### Scenario: 获取并刷新短期 token
- **WHEN** 需要在一次模型调用中使用短期 token 且内存中的 token 缺失或临近过期
- **THEN** 系统经已鉴权的 `ai/llm-ak` 重新获取，并在内存中缓存至 `expireAt` 前刷新，不写入任何持久化存储

#### Scenario: 未开通或额度耗尽
- **WHEN** heartbeat 响应表明账号未开通 AI 服务，或对应额度已耗尽
- **THEN** 系统按该结论停止发起模型调用、显示可区分的中文原因，且不把结论描述为网络故障

#### Scenario: WebView 不接触凭据
- **WHEN** 检查 WebView 状态、前端事件与浏览器演示存储
- **THEN** 不存在短期 token、Authorization Header 或上游原始响应

### Requirement: 模型配置在心跳周期边界重新解析并在运行前冻结
系统 SHALL 在每个心跳周期边界重新解析模型标识与受控请求参数，配置切换 SHALL 最长在一个心跳周期（90 秒）内生效。系统 SHALL 在一次运行开始前把解析结果冻结为不可变快照，运行期间 MUST NOT 重新解析。运行指纹与识别、分析、渲染的缓存键 SHALL 包含实际模型标识与模型版本；切换模型后 MUST NOT 复用由其他配置产出的结果。系统 MUST NOT 允许各业务模块直接读取配置文件、环境变量或全局可变状态来决定模型，也 MUST NOT 允许业务模块自行获取短期 token。

#### Scenario: 心跳周期内切换模型
- **WHEN** 配置把模型标识改为白名单内的另一个取值
- **THEN** 新配置最长在一个心跳周期后对此后新建的运行生效，且不需要客户端发版

#### Scenario: 运行中修改配置
- **WHEN** 一次运行进行中，用户下发了新的模型配置
- **THEN** 该运行继续使用其冻结快照，新配置只影响此后新建的运行

#### Scenario: 同一运行内模型一致
- **WHEN** 一次运行包含多个模型调用阶段
- **THEN** 所有阶段使用同一冻结的模型与同一短期 token 提供方

#### Scenario: 重启后按运行指纹匹配
- **WHEN** 应用重启并重新解析模型配置后读取既有的已发布结果
- **THEN** 系统按产出该结果的运行指纹匹配；指纹一致才复用，不一致时保留为历史建议且不自动应用

#### Scenario: 无全局可变状态参与决策
- **WHEN** 两个并发运行在同一进程内使用不同的模型配置
- **THEN** 两者各自按自己的快照执行且互不影响

#### Scenario: 配置来源可观测
- **WHEN** 界面或诊断展示当前模型
- **THEN** 系统同时展示该取值来自构建期默认还是本机覆盖，以及下次解析时间

### Requirement: 按构建类型限定配置输入面
系统 SHALL 按构建类型区分配置输入面：生产构建只接受构建期注入或白名单内的模型取值，MUST NOT 接受手输的 Base URL、代理地址或上游凭据；开发与验证构建 SHALL 允许通过本地配置文件或环境变量覆盖。任一构建类型下，非生产配置 SHALL 在界面与诊断中显著标记。

#### Scenario: 生产构建拒绝自由输入
- **WHEN** 生产构建的界面或前端请求尝试提交任意 Base URL、代理地址或手输凭据
- **THEN** 系统拒绝该输入且不发起网络请求

#### Scenario: 验证构建允许本地覆盖
- **WHEN** 开发或验证构建通过本地配置文件或环境变量指定 Base URL 与模型
- **THEN** 系统采纳该覆盖用于本机验证，且不把它写入随发布分发的默认配置

#### Scenario: 非生产配置被显著标记
- **WHEN** 当前生效配置来自本机覆盖而非构建期默认
- **THEN** 界面与诊断显著标记当前为非生产配置，避免被误认为正式环境行为

#### Scenario: 覆盖值不进入持久化凭据
- **WHEN** 本地覆盖包含凭据
- **THEN** 该凭据 SHALL 只存在于内存或操作系统凭据库，MUST NOT 写入 SQLite、配置文件明文、日志或事件
