## Context

见 `proposal.md` 的 Why。与设计相关的现状约束：

- `src/asr/cloud.rs` 已有 `TemporaryAudioPublisher` 抽象、`CloudFirstAsrEngine` 路由与 `DashScopeAsrClient`（提交、轮询、结果下载）。发布器在 `src-tauri/src/ai/desktop_runtime.rs` 被硬编码为 `UnavailableTemporaryAudioPublisher`，`cloud_asr_available` 在三处诊断分支中恒为 `false`。
- `CloudFirstAsrEngine` 目前对任何云端错误一律回退本地，且 `identity()` 委托本地引擎；`src-tauri/src/ai/processor.rs` 在调用引擎前无条件执行本地 VAD，并要求识别配置身份与本地引擎身份一致。
- 客户端已有 `GET /api/client/ai/llm-ak` 短期 token（`{ak, expireAt, provider}`，`provider=ALI`）。按 v2 口径，ASR 场景改为使用该 token 直连百炼，不再依赖服务端任务接口。
- 百炼的音频上传/提交路径仍在 `validate-dashscope-direct-capabilities` 探针中验证；本 change 只固定契约，具体的上传方式（文件上传接口或等价方式）以探针结论为准。
- 客户端 `asr_artifacts` 已有 `provider` 与 `fallback_reason` 两列（最新迁移版本 25），但缺少模型版本、分块策略与规范化版本作为缓存键组成部分，也缺少本地幂等记录。

## Goals / Non-Goals

**Goals:**

- 让百炼直连转写路径从“资格判定通过但永不执行”变为可实际执行、可诊断、可取消、可恢复。
- 让“云端优先”在缺少本地组件时仍然成立，同时**明确取消自动本地回退**：云端失败即失败。
- 在任何中断路径上都不重复付费转写，且不把授权/额度问题伪装成云端故障。
- 保留 macOS Intel x86_64 的平台承诺。

**Non-Goals:**

- 不引入任何新的服务端接口；不把任务创建、查询或取消交给服务端。
- 不做服务端分项账本；记账以本地 SQLite 的 `requestId` + 输入指纹为准。
- 不改变统一 ASR 产物结构对导出的兼容性：句段 ID、源内时间戳与规范化规则保持不变。
- 不删除客户端已有的百炼协议适配（本轮重新启用并收口它）。
- 不改动录制、预览、封面与转场素材链路。
- 不为分块引入本地重新拼接音频文件的中间步骤。

## Decisions

### 决策一：客户端直连百炼，任务由客户端提交与轮询

**选择**：客户端用 `ai/llm-ak` 的短期 token 直连百炼，自己完成音频上传、异步文件转写任务提交、轮询与结果下载。**本决策修正本 change 前一版的结论**——前一版选择“删除客户端百炼协议、任务由服务端创建与轮询”。

**理由**：v2 已定案 admin-service 本轮不新增任何接口、不做服务端分项账本，因此服务端代理这一权威来源不再存在。客户端本已有可用的百炼适配（`DashScopeAsrClient`），重新启用并收口它是成本最低且与既有代码一致的路径。短期 token 的设计本来就面向“客户端持此直连上游”，与 `ai/llm-ak` 的既有语义一致。

**已考虑的替代方案**：服务端代理并记账（本 change 前一版的选择，对应已搁置的 `add-cloud-ai-job-backend`）。被否决的原因：需要新增 9 个服务端接口与分项账本，与“admin-service 本轮不新增任何接口”的口径直接冲突；在服务端不参与的前提下保留该路径会形成无法验收的空契约。该方案整体保留在搁置的 change 中，若产品后续决定重新引入服务端代理，可按 `v2-delivery-order.md` 的恢复条件重新评估。

**代价**：客户端承担直连与重试责任，服务端不再拥有用量与对账视图；上游凭据路径从“服务端长期密钥”变为“短期 token + 客户端实现”。代价由短期 token 的有效期、本地幂等记录与脱敏日志要求共同约束。

**音频直传的三步流程（已由 `validate-dashscope-direct-capabilities` 实测确认）**：

1. `POST /api/v1/files`（multipart）直传 16 kHz、单声道、16-bit PCM WAV，取得 `file_id`。
2. `GET /api/v1/files/{file_id}` 取回上游签发的签名临时 URL（`data.url`，含 STS `security-token`、`Expires` 与 `Signature`，约 938 字符）。
3. 以该临时 URL 作为 `input.file_url` 调用 `POST /api/v1/services/audio/asr/transcription`；实测终态 `SUCCEEDED`，`usage` 返回 `seconds`。

两条被实测证伪的替代上传路径，MUST NOT 再采用：`GET /api/v1/uploads?action=getPolicy` 加对象存储表单直传（策略把对象访问级别固定为 `private`，转写服务无法读取：`oss://` 引用得 `FILE_DOWNLOAD_FAILED`、HTTPS 直链得 `FILE_403_FORBIDDEN`）；以及跳过第 2 步直接用 `file_id` 提交（得 `FILE_DOWNLOAD_FAILED`）。

**由此产生的一项客户端约束**：上游签发的临时 URL 为 `http` 方案，而 `TemporaryAudioReference::validate()` 现只接受 `https`。该校验 SHALL 放宽为“由上游签发且含签名与有效期参数”，并 SHALL 新增“用户可输入地址被拒绝”的负向测试；放宽 MUST NOT 波及任何用户可输入的地址。

### 决策二：分块采用有重叠的固定区间，不删除静音

**选择**：超过单任务上限时按固定区间切分并保留少量重叠，取得全部子结果后把块内时间加回源偏移，再按文本与时间交叠去重，最后为合并句段分配稳定 ID。

**理由**：删除静音后拼接会破坏“结果时间可定位回源视频”这一前提，而这是高光引用真实来源区间的基础。

**已考虑的替代方案**：按 VAD 人声区间拼接以缩短音频。被否决：同上，且与决策三把 VAD 移出云端路径的方向一致。

**真实长样本验收暴露的缺陷与修正（2026-09-30）**：按上述"文本与时间交叠去重"实现在真实中文 4 分钟样本上验收时，发现**分块边界的截断残句**无法被该规则命中——前一块末尾产生「感慨为。」（159120–159980），后一块开头产生完整句「敢看微霜雪，想赠眉间一道疤。」（159240–162820），两者**时间交叠 740ms 但文本相似度为 0**。这不只是重复显示问题：产物发布要求句段严格按源时间单调且互不重叠，因此该情况会让整次长音频转写以"句段时间无效"失败。

**修正规则**：合并结果在文本去重之后 MUST 再执行一次**时间交叠消解**：同一路音频内两个句段在时间上交叠时，保留覆盖更完整的句段，直接丢弃较短者（裁剪只会留下无独立意义的碎片，例如 120ms 的「感慨为。」）。等长时保留先出现的一段。输出 MUST 保证严格按源时间单调且互不重叠。

**代价**：交叠区可能丢失一个被截断的短片段。这是可接受的：该片段本身就是边界产物，不携带独立语义，而保留它会导致发布失败。

### 决策三：VAD 只服务于本地路径

**选择**：VAD 保留为本地识别路径的前置步骤，但不再是云端路径的门禁；云端路径处理完整来源音频。

**理由**：当前 VAD 无条件先跑，`speech_regions.is_empty()` 会直接把输入标记为 `SkippedNoSpeech`，而 VAD sidecar 与 VAD 模型正是“本地环境失效时最容易缺失”的组件。把它当前置门禁等于让本地组件决定云端能否运行。

### 决策四：引擎身份真实化，识别配置身份校验跟随实际引擎

**选择**：`CloudFirstAsrEngine` 返回云端引擎的真实身份，不再委托本地引擎；识别配置身份校验改为与实际执行引擎比对。

**理由**：当前实现让云端结果带着本地 Whisper 的身份发布，既污染产物身份，也使后续缓存键与诊断无法区分两条路径。这也是 `provider` 列难以被真正使用的原因。

### 决策五：缓存键纳入完整转写身份

**选择**：识别配置指纹包含 `provider`、模型、模型版本、分块策略、VAD 参数、热词与规范化版本。

**理由**：缓存键若不含身份字段，云端结果与本地结果会互相命中；若含但不记录版本，模型升级后无法判断旧产物是否仍适用。

**兼容**：旧产物保持原 `provider` 与模型身份，不通过数据库迁移改写。

### 决策六：失败与取消是显式分类，不做本地回退

**选择**：删除“云端失败自动回退本地”的行为。云端路径的失败分类如下：

| 失败类别 | 处理 |
| --- | --- |
| 用户取消 | 直接终止；若上游支持取消则请求取消；**不回退本地** |
| 授权、未开通、额度耗尽 | 显式报告可区分原因；不描述为云端故障；不回退本地 |
| 网络超时、限流、上游 5xx、上传失败 | 有界重试后**明确失败**并保留可重试状态；不回退本地、不重复付费 |
| 临时音频资源失效、短期 token 过期 | 可重新上传或用新 token 重试一次；仍失败则明确失败并返回可区分原因 |

**理由**：现状“任何 cloud error 一律回退本地”会掩盖真实故障，让用户看到的路径与诊断不一致；在 v2 口径下本地 Whisper 不再是云端路径的兜底，必须让失败可见。保留用户取消直接终止与授权/额度显式报告两条既有语义，是因为它们直接决定用户看到的因果与费用结论。

**与既有决策的冲突记录**：本决策改写了本 change 前一版的“回退分类是显式三分支（云端失败按冻结策略回退本地）”。前一版对应的验收任务（瞬时故障后回退本地、回退验收）同步改写为“明确失败、本地引擎未被调用”的断言。

**本地路径的定位**：本地 `whisper.cpp` 仍作为用户**显式选择**的独立识别路径保留，既有行为不变；云端路径 MUST NOT 自动降级进入它。

### 决策七：清理失败不回滚成功结果

**选择**：云端转写成功但本地临时音频清理失败时，保留成功结果、标记清理待重试，不重新提交转写。

**理由**：清理是资源治理动作，转写是付费动作。为清理失败重跑一次付费转写是不可接受的放大。

### 决策八：本地幂等记录替代服务端任务找回

**选择**：付费提交前在本地事务中持久化稳定 `requestId`、任务类型、输入指纹与（若已取得的）上游 `task_id`；同一 `requestId` 与同一输入指纹复用原任务记录，同键不同输入拒绝。已提交但缺少 `task_id` 时保持待对账，先查询上游是否已创建，不自动再次提交。

**理由**：在没有服务端账本的前提下，本地 SQLite 是唯一可持久化的权威；这同时满足“不重复付费”与“崩溃后可按 `requestId` 找回”。复用了 `add-cloud-ai-job-backend` 中 `(账号, 任务类型, requestId)` 的幂等语义，只是把存储位置从服务端移到客户端本地。

## Risks / Trade-offs

- [客户端直连成为单点] 百炼或本机网络不可用即云端路径整体不可用 → 这是“不做本地回退”的既定代价；诊断必须把“云端路径不可用”与“授权/额度问题”区分为不同状态，并给出可重试指引。
- [短期 token 的暴露面] token 在客户端内存中，泄漏即获得调用能力 → token 只在内存持有、按 `expireAt` 刷新、不写入 SQLite/日志/事件/前端状态；新增脱敏测试断言。
- [分块边界重复文本] 重叠区可能产生重复或截断句段 → 以文本与时间交叠双重条件去重，并在任务中要求用真实中文长样本验证边界处的句段数与文本一致性。
- [合并后稳定 ID 的可重现性] 合并结果在不同分块策略下可能生成不同 ID → 稳定 ID 依据源时间与文本内容派生，并新增任务验证“相同输入与相同分块策略产生相同 ID 序列”。
- [本地幂等记录的正确性] 崩溃点落在“已提交、未落盘”窗口会丢失找回能力 → 任务要求提交前先落盘，并用“提交后立即退出进程”的测试覆盖。
- [迁移不改写旧产物] 新增列必须可空或有默认值，且不得触发对旧行的重写 → 迁移任务要求覆盖旧库快照，并断言升级前后旧产物的 `provider` 与缓存命中行为不变。
- [诊断语义变化] `cloud_asr_available` 从恒 `false` 变为真实反映可用性，可能暴露此前不可见的问题 → 诊断只报告分类与布尔可用性，不报告 URL、凭据、路径或上游任务 ID。
- [平台范围扩大] 保留 macOS Intel x86_64 后，随包 sidecar、渲染浏览器与 Harness 都需要 Intel 构建 → 任务中要求核对发行清单与发布校验，避免 Intel 用户拿到缺组件的包。

## Migration Plan

1. **前置**：`validate-dashscope-direct-capabilities` 给出探针结论（音频上传路径、模型可用性、取消语义、时长上限）。
2. **切换实现**：客户端实现直传发布器并收口百炼提交与轮询，替换 `UnavailableTemporaryAudioPublisher`；`cloud_asr_available` 开始反映真实可用性。
3. **本地幂等**：落盘 `requestId`、任务类型、输入指纹与 `task_id`，实现同键复用与待对账状态。
4. **数据迁移**：新增转写身份、分块策略与本地幂等记录列，版本号为 26；迁移只增列不改写旧行，升级后断言旧产物身份与缓存命中不变。
5. **回滚**：关闭云端路径即回到用户显式选择本地识别的行为；已发布产物保持身份不删改。**不再存在自动回退路径，因此回滚是一次显式配置切换。**
6. **平台核对**：同步 README、验收记录与发行清单中的 Intel 表述与构建产物。

## Open Questions

- 百炼单任务的处理时长上限与分块区间长度、重叠时长。这不改变契约（分块与源时间还原的语义已固定，均由客户端按上限驱动），需要以探针结论与真实中文长样本取值。
- 音频上传到百炼的具体路径（文件上传接口与 `oss://` 资源引用，或等价方式）与资源有效期。契约只要求“任务期间可被百炼读取、且客户端可在终止后清理”，方式以探针结论确定。
- 百炼任务取消的实际支持程度。契约要求“能取消则取消，不能取消则明确告知可能已产生费用”，具体行为随探针结论确定。
- 归一化版本字段是复用现有规范化版本号还是为其单列。这不改变缓存键“必须包含规范化版本”的要求，可在迁移设计时确定。
