## ADDED Requirements

### Requirement: 为入选高光输出互斥的增强方式
系统 SHALL 在一次精彩运行中同时完成表现形式选择，并为每条入选高光输出唯一的增强方式：`effect_caption` 或 `video_animation`。两种方式 MUST 互斥；增强方式与人工修改的关系 MUST 遵循"人工优先、旧代次保留为审计"的既有规则。客户端 MUST 拒绝未知类型，也 MUST 拒绝同一高光同时出现两种方式的结果。

#### Scenario: 字幕为默认分支
- **WHEN** 高光属于金句、数字、观点、反问，或其视觉化收益不明确
- **THEN** 系统为该高光选择 `effect_caption`，且不为其请求媒体生成

#### Scenario: 结果包含互斥冲突
- **WHEN** 同一高光的结果同时包含 `effect_caption` 与 `video_animation`，或包含未知的增强类型
- **THEN** 系统拒绝该结果、记录脱敏原因且不把任何一条分支写入工程

#### Scenario: 事实范围与文字来自工程而非模型
- **WHEN** 模型建议了高光范围、增强方式或强调词
- **THEN** 系统只采用工程已发布的句段与用户修正文案作为实际可用范围与文字，并丢弃模型虚构的引用

#### Scenario: 人工修改后收到旧代次结果
- **WHEN** 用户已修改工程片段或字幕，随后收到先前代次的增强结果
- **THEN** 系统把该结果保存为历史建议，MUST NOT 自动覆盖人工编辑或新的工程代次
