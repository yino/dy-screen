## Context

见 `proposal.md` 的 Why。与设计相关的现状约束：

- 现有第三种媒体来源不存在：`ai-clip-editor` 只认原始片段与目录中的版本化桥接素材（`assetKey + assetVersion`），`renderMode` 是受校验的闭合字段。
- 现有桥接实现已具备大量可复用基础：`ClipExportBridge` 携带 `boundary_id`、`asset_key`、`asset_version`、`duration_ms`、`has_audio`；视频专用桥接通过 `anullsrc` 合成静音输入；`ai_clip_transition_boundaries` 已有 `left/right_clip_segment_id` 与左右稳定 ID；`transition_assets.rs` 已有版本化资产的受控下载、SHA-256 校验与预览。
- 现有桥接语义已规定“完整插入边界、保留原声、桥接区间不显示来源字幕、右侧片段与字幕顺延”，`insert` 可以直接复用这套语义骨架。
- 高光长度范围为 15–90 秒（精彩分析提示词所声明的候选时长区间），而“每条高光只生成一段动画”与“生成时长与目标范围差异不超过 5%”共同要求生成时长接近目标范围。
- 生成调用在客户端 Rust 侧完成：用 `GET /api/client/ai/llm-ak` 的短期 token 直连阿里云百炼，提交万相文生图与图生视频异步任务并轮询终态。**服务端不提供 `image-jobs`/`video-jobs` 任务接口，也没有网关令牌**；探针已实测确认临时 token 可直接提交这两类任务（http=200，返回 `task_id`）。
- 生成能力的模型、参数、时长档位、取消语义与结果下载方式仍由 `validate-dashscope-direct-capabilities` 探针确认。

## Goals / Non-Goals

**Goals:**

- 在不改动目录素材语义与历史工程的前提下，为时间线引入第三种受校验的媒体来源。
- 让生成资产的成本可预算、可门禁、可降级、可复核，且门禁在客户端本地可验证。
- 让两种合成方式都复用既有的导出规范化与字幕时间映射机制。
- 在 macOS arm64、macOS Intel x86_64 与 Windows x64 上完成验收。

**Non-Goals:**

- 不使用生成音轨；不改变相邻片段的音量设置。
- 不把生成资产写入目录素材表或伪装为新的 `renderMode`。
- 不新增任何服务端接口，不依赖 `image-jobs`/`video-jobs` 服务端任务接口与网关令牌。
- 不实现特效字幕路径（见 `add-effect-caption-renderer`）。
- 不为 `insert` 之外引入新的时间线单元类型。

## Decisions

### 决策一：`replace` 的目标范围由生成时长反向确定，而不是先定范围再要求等长

**问题**：方案要求 `replace` “等长替换高光中的原画面”、“每条高光只生成一段动画”，并给出“差异不超过 5%”的容差。而高光长度为 15–90 秒。若把“目标范围”理解为整条高光，等长生成的可行性取决于上游能否一次生成 15–90 秒的视频，这既非常见能力也不经济；方案本身并未定义动画覆盖高光的哪一部分。

**选择**：以“高光内一个目标源时间范围”作为 `replace` 的绑定对象，该范围从生成资产的实际时长与冻结容差反向确定：先取得生成时长，再在高光内选取一个与它匹配的目标源范围，并把该范围写入工程。

**理由**：生成模型只能产出有限档位的时长，把选择权交给“先声明范围”会产生大量不可满足的请求并因此降级，浪费已付费用。反向确定使容差成为真正的匹配条件而不是事后校验。

**约束**：
- 目标源范围 MUST 落在该高光的一个来源区间内，不得跨来源片段。
- 未被目标范围覆盖的高光其余部分保持原画面与原声。
- 该范围与生成时长的差异 MUST 在冻结的 5% 容差内，且适配后的最终偏差不超过一个输出帧。
- 目标范围 SHALL 由 Rust 依据工程已发布句段与来源区间计算，MUST NOT 采用模型给出的时间戳。

### 决策二：插入单元丢弃生成音轨，改用静音补齐与边界淡化

**选择**：`insert` 区间的音频为 48 kHz 双声道静音，前后边界各作受控短淡出与淡入。

**理由**：生成音轨的内容不可控、与来源音频的连续性与音量不匹配，直接用会明显破坏听感；而“无音轨 + 静音补齐”与现有视频专用桥接的实现路径一致，可直接复用。

**代价**：插入区间成为一段无音频的视觉桥接。这是可接受的取舍，因为 `insert` 的定位本来就是视觉转场而非内容延续。

### 决策三：邻接绑定使用稳定 ID 三元组并显式失效

**选择**：`insert` 资产绑定 `leftClipSegmentId`、`rightClipSegmentId` 与 `boundaryId`，并归属左侧高光；任一改变即失效并需要重新审阅。

**理由**：现有边界表已按“左稳定 ID + 右稳定 ID”唯一定位边界并对人工锁定与失效有既定处理，复用它可以避免为生成动画另建一套邻接模型。

**注意**：失效后 MUST NOT 自动重新生成。重新生成会产生新的付费调用，必须由用户显式触发。

### 决策四：5% 容差 + 一个输出帧的界

**选择**：差异不超过 5% 时裁剪多余帧或施加受限变速；超过 5% 即判定失败并降级。适配后的最终偏差不超过一个输出帧。

**理由**：5% 是一个可解释的观感界限；一个输出帧是把“适配后仍需对齐”这一要求变成可断言的量。受限变速的范围需冻结，超出该范围即按超容差处理，避免用大幅变速掩盖时长不匹配。

### 决策五：降级是有序的、有额度上限的、只留一个终态

**选择**：生成或校验失败 → 额度允许时改为字幕分支 → 字幕分支也失败 → 保留普通原视频与基础字幕。每一步记录原因与已产生成本，最终记录唯一的 `enhancement.kind`。

**理由**：用户必须能知道“这条高光最后到底是什么形态、为什么、花了多少”；两条分支同时产出可导出内容是必须排除的状态。

**约束**：降级到字幕分支受字幕分支的额度约束（依据 heartbeat 的开通/额度结论与本地冻结上限）；已经失败的生成资产不重试，除用户显式重新发起。

### 决策六：生成资产复用键独立于目录素材版本

**选择**：复用键由分镜内容、提示词、目标时长与生成规格构成；生成资产不进入目录素材表。

**理由**：目录素材是服务端统一供给、按 `catalogVersion` 同步的共享资源；生成资产是单工程单高光的产物。混入目录模型会污染目录同步语义与匹配召回。

### 决策七：生成调用由客户端直连万相，凭据只有短期 token，能力以探针结论为准

**选择**：客户端 Rust 侧用 `GET /api/client/ai/llm-ak` 的短期 token 直接调用万相文生图与图生视频接口并轮询 `task_id`；不经过我们的服务端，不使用任何服务端生成任务接口或网关令牌。付费提交前在本地事务持久化稳定 `requestId`、任务类型与输入指纹，同键同输入复用、同键不同输入拒绝。

**理由**：v2 口径已定案 admin-service 本轮不新增任何接口、不做服务端记账；直连是唯一可交付的路径，且与 `ai/llm-ak` 的既有语义一致。**本决策修正本 change 前一版**：前一版依赖服务端 `image-jobs`、`video-jobs`、`jobs/{jobId}` 与按 `requestId` 找回接口，这些接口整体保留在已搁置的 `add-cloud-ai-job-backend` 中。

**门禁位置**：任务级动画数量、累计秒数与金额上限在客户端本地冻结并校验，超限 MUST NOT 提交；未开通与额度耗尽由上游业务错误码 3001 / 3003 / 3004 判定（heartbeat 响应不含额度字段），客户端不得以本地设置替代该结论。

**代价**：服务端不再拥有生成用量视图；上游 401/429/5xx、任务取消能力与资产下载方式需要客户端自行处理并做脱敏分类。**生成能力与参数取值以 `validate-dashscope-direct-capabilities` 的探针结论为准**。

**已考虑的替代方案**：服务端生成任务接口（前一版的选择）。被否决：与“admin-service 本轮不新增任何接口”直接冲突，且没有服务端账本时该路径无法验收。

**已实测确认的调用形态与记账依据（`validate-dashscope-direct-capabilities`）**：

- 文生图：`POST /api/v1/services/aigc/text2image/image-synthesis`，实测模型 `wanx2.1-t2i-turbo`，请求头 `X-DashScope-Async: enable`，终态 `SUCCEEDED`，`usage` 返回 `{"image_count":1}`。
- 图生视频：`POST /api/v1/services/aigc/video-generation/video-synthesis`，实测模型 `wanx2.1-i2v-turbo`，终态 `SUCCEEDED`，`usage` 返回 `{"video_duration":5,"video_ratio":"standard","video_count":1}`。
- 轮询：`GET /api/v1/tasks/{task_id}`，成功终态的结果必须经客户端哈希、尺寸、帧率与实际时长校验后才可应用。
- **记账依据只取上游响应中的用量字段**（图片张数、视频条数与实际秒数），MUST NOT 采用请求体中的任何价格或额度字段。
- **上游不具备调用方幂等能力**：实测以相同输入与相同自定义幂等键连续提交两次会得到两个不同 `task_id`，响应头无幂等字段。因此本地 `requestId` + 输入指纹是去重的唯一承担者；在未能确认上游是否已受理时 MUST NOT 自动重复提交付费请求。

**本地帧到上游可读引用的可达性（已实测，详见 `validate-dashscope-direct-capabilities/local-frame-accessibility.md`）**：

参考帧必须走与音频上传同构的**三步直传**：`POST /api/v1/files` 直传本地帧 → `GET /api/v1/files/{file_id}` 取回签名临时 URL → 作为 `input.img_url` 提交。以仓库内真实录制抽帧（720×1280 JPEG）实测：

- `oss://<key>` 引用 → 被拒：`InvalidParameter.DataInspection`（`The media format is not supported or incorrect for the data inspection.`）。
- `/files` 直传后取回的签名临时 URL → 被接受并进入 `PENDING`。

因此：`getPolicy` 表单路径 MUST NOT 用于参考帧；客户端 SHOULD 抽出共用的"上游文件上传"原语供转写音频与参考帧共用；签名临时 URL MUST 在提交前取回，其有效期必须覆盖生成任务的完整耗时（实测图生视频在 107–200 秒区间）。参考帧属于用户内容，MUST NOT 为它新增公网可读的持久对象。

**上游存在偶发生成失败，必须按此设计（新增风险项）**：以真实录制抽帧做 5 组对照时，两个同为 `720x1280` 的真竖屏帧**一败一成**（失例 190 秒后 `AlgoError`），横屏 2 例均成功。失例堆栈为上游内部插帧阶段空文件（`TypeError: expected str, bytes or os.PathLike object, not NoneType`），既不是内容审查也不是引用不可读（引用已被接受并进入 `PENDING`）。据此：

- 失败的判定 MUST 与"用户内容违规"区分开，归类为上游内部缺陷型的可重试失败。
- **重试必须受门禁约束**：上游无幂等键，每次重试都是一次新的付费提交，因此重试次数 MUST 计入任务级动画数量与金额上限，MUST NOT 无限重试。
- 一次失败要等约 190 秒才得到结论，成功也需 107–200 秒：编排 MUST 给出与该量级匹配的超时与进度预期，并允许用户先审阅已就绪的其他高光。
- 该失败模式无法由输入预检规避（同规格帧结果不一致），因此降级路径 MUST 在首次失败时即可用。

**一批实测暴露的生成规格特征（对结果校验与降级有直接影响）**：

- **实际时长不等于请求时长**：请求 `duration=5` 得到 `5.367` 秒，偏差 +7.3%，**超过本 change 冻结的 5% 容差**。这直接印证决策一的必要性：若先声明目标范围再要求等长，此类请求会不可满足并浪费已付费用；必须由实际时长反向确定目标源范围。
- **上游会改写提示词**：文生图与图生视频都返回 `actual_prompt`，且与 `orig_prompt` 明显不同（例：`a red circle on white background` → `Minimalist graphic design, perfectly centered vibrant crimson circle...`）。结果校验 SHOULD 记录 `actual_prompt` 以便复核风格偏离；分镜 Skill 的提示词设计 MUST NOT 假定上游会原样使用输入。
- **延迟量级差异**：文生图约 12 秒、图生视频约 107 秒。任务级门禁之外，界面与编排需要按此量级给出真实进度预期，且轮询超时必须覆盖该量级。
- **输出规格**：请求 `480P` 得到 768×512；文生图 `1024*1024` 得到 1024×1024 PNG。

## Risks / Trade-offs

- [成本不可预判] 生成式动画按次付费且效果不可预判 → 客户端冻结的任务级数量、累计秒数、金额三重上限，参考图与视频各有独立提交上限；降级记录成本以便复核；上限取值随探针结论与服务端版本化配置确定。
- [直连可用性] 万相接口不可用即动画分支整体不可用 → 明确失败并降级到字幕分支；诊断区分“上游不可用”与“开通/额度问题”。
- [短期 token 的暴露面] token 只在 Rust 内存中持有 → 不写入 SQLite、日志、事件与前端状态；Harness 只能经受控工具提交结构化请求，拿不到 token。
- [容差导致的降级率] 生成时长与高光内可用范围可能频繁不匹配 → 决策一的反向确定显著降低该风险；任务中要求以真实样本统计降级率，并在降级率过高时评估是否放宽容差或调整目标时长档位。
- [视觉风格跳变] 生成画面与原视频画面差异明显，可能造成突兀感 → 要求分镜参考图提示词以高光内的真实画面为参考来源；对同一高光只生成一段动画，避免多次切换；`replace` 保留原声与普通字幕以维持连续性。
- [音频空洞感] `insert` 区间无音频 → 边界淡化降低爆音；插入时长由门禁约束，避免长时间静音段。
- [邻接失效后的重复成本] 用户重排片段会使已付费的 `insert` 资产失效 → 失效后不自动重生成，保留为历史建议供用户显式复用；这一点在任务中要求可验证。
- [磁盘与导出耗时] 生成资产需下载、校验、解码并参与导出 → 复用 `transition_assets.rs` 的体积上限与校验路径；任务中要求在 8 GB 目标设备上测量峰值磁盘与导出耗时。
- [探针结论未定] 万相的模型、参数、时长档位、取消语义与资产下载方式仍在验证 → 任务按“资产契约 → 下载校验 → replace → insert → 降级”分层，使前两层可在探针结论前用固定样本资产推进；所有与生成能力相关的验收以探针结论为准。
- [跨变更依赖] 本 change 依赖增强方式契约（`add-effect-caption-renderer`）与 sidecar 的媒体生成受控工具（`add-model-gateway-and-harness-sidecar`）→ 任务按层推进，避免与前置 change 的交付顺序冲突。

## Migration Plan

1. **前置**：`validate-dashscope-direct-capabilities` 的探针结论（万相模型、参数、时长档位、取消语义与资产下载方式）；`add-effect-caption-renderer` 的增强方式契约可用。
2. **资产契约与下载校验**：定义生成资产的数据模型、哈希与媒体属性校验、复用键，先以固定样本资产打通下载与校验，不接入真实生成。
3. **`replace` 先行**：先交付 `replace`，它不改变工程总时长，风险最低且可独立验收。
4. **`insert` 随后**：在 `replace` 验收通过后交付 `insert`，复用既有桥接单元与字幕顺延机制。
5. **门禁与降级**：接入客户端冻结的额度上限与降级顺序，验证成本记录与最终唯一增强方式。
6. **历史兼容校验**：以既有含目录桥接素材的工程作为回归样本，验证边界选择、阈值、预览与导出结果均不变。
7. **回滚**：关闭动画门禁即让全部高光回到字幕分支；`replace` 与 `insert` 都是工程级可选增强，回滚不改变原始片段、字幕与目录素材的任何既有行为。

## Open Questions

- 万相文生图与图生视频的具体模型标识、参数与单次生成时长档位。这不改变本 change 已固定的契约（反向确定目标范围、5% 容差、受控上限与降级顺序），以探针结论为准。
- 万相任务是否支持取消，以及取消后是否仍计费。契约要求“能取消则取消，不能取消则明确告知可能已产生费用”，具体行为随探针结论确定。
- 生成资产的受控下载方式（直接下载地址 vs 需要额外换取）。契约要求“客户端 MUST 校验下载文件与媒体属性后才应用”，方式以探针结论确定；签名地址不得写入数据库、日志与前端状态。
- 受限变速的具体范围（例如允许的百分比区间）。契约要求“超出即按超容差处理”，具体区间可在实现时结合真实样本确定。
- 默认动画条数上限的取值。契约要求该上限在客户端本地冻结，具体数值随探针结论与产品配置确定。
