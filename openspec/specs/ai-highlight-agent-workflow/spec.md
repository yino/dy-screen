# AI 精彩 Agent 工作流规格

## Purpose

定义本地转写结果经过用户授权后，由 Rust 控制精彩候选发现、评分、持久化、恢复、排序、播放器定位和用户选择的完整工作流边界。
## Requirements
### Requirement: 通过两个受限 Agent 角色分析精彩
系统 SHALL 使用同一个用户配置模型构建候选发现 Agent 和全局评分 Agent，并 SHALL 由 Rust 工作流决定调用阶段、顺序、重试、停止和持久化；Agent MUST NOT 获得写文件、执行命令、数据库 mutation、网络搜索或切片工具。

#### Scenario: 分析单个转写块
- **WHEN** Rust 工作流向候选发现 Agent 提交一个有界转写块和已选 Skills
- **THEN** Agent 只返回绑定稳定句段 ID 的结构化候选，不决定下一工作流阶段

#### Scenario: 全局复评候选
- **WHEN** 所有分块候选已经通过本地校验和去重
- **THEN** 全局评分 Agent 只接收压缩候选摘要并返回结构化评分和排序

### Requirement: 组合版本化精彩分析 Skills
系统 SHALL 始终使用通用爆点 Skill，并 SHALL 根据主播标签快照和项目级标签确定性选择最多三个内置专项 Skill；第一版内置带货转化、搞笑包袱、知识密度和故事情绪 Skill。

#### Scenario: 带货主播开始分析
- **WHEN** 项目标签快照包含“带货”或等价的已支持标签
- **THEN** 系统组合通用爆点与带货转化 Skill，并把 Skill ID、版本和权重纳入运行指纹

#### Scenario: 项目包含未知标签
- **WHEN** 项目标签不匹配任何内置专项 Skill
- **THEN** 系统仍使用通用 Skill，并把未知标签作为明确分隔的用户数据而不是系统指令

### Requirement: 分块并校验 Agent 候选
系统 SHALL 把长转写按稳定句段边界划分为有界、带重叠的块，并 SHALL 在本地校验候选句段存在、时间递增、长度为 15–90 秒且不跨越源视频文件。

#### Scenario: 长直播超过单次上下文预算
- **WHEN** 项目转写超过当前分块字符或 token 预算
- **THEN** 系统生成多个可恢复块并保留有限相邻上下文，不截断句段文本或丢失稳定 ID

#### Scenario: Agent 返回伪造句段或越界时间
- **WHEN** 候选引用不存在的句段、跨视频或时间范围超出真实句段
- **THEN** 系统拒绝该候选并记录结构校验分类，不把模型时间直接用于播放器或后续切片

### Requirement: 生成可解释的精彩评分
系统 SHALL 为每个有效候选保存 0–100 总分、开场吸引力、信息密度、情绪强度、标签相关性、完整性和传播潜力维度分、简短理由及命中标签。系统 SHALL 保存全部通过本地校验和去重后的评分候选，不设推荐数量上限；默认仅发布总分大于等于该运行冻结的合格阈值的候选导航，并在初次最终评分发布时自动选择总分大于等于该运行冻结的优秀阈值的候选。

#### Scenario: 多个分块产生重复候选
- **WHEN** 相邻块返回重叠或引用相同核心句段的候选
- **THEN** 系统先本地合并去重，再让全局评分 Agent 对唯一候选复评

#### Scenario: 候选低于默认阈值
- **WHEN** 全局评分后的候选总分低于该运行冻结的合格阈值
- **THEN** 系统保留候选、计数和可解释完成状态，但不将其列入默认精彩导航或自动选择

#### Scenario: 候选达到优秀阈值
- **WHEN** 全局评分后的候选总分大于等于该运行冻结的优秀阈值，且该运行首次发布最终评分
- **THEN** 系统将该候选持久化为已选择，并在已选择视图中展示

### Requirement: 持久化并恢复精彩工作流
系统 SHALL 持久化运行配置、标签快照、Skill 版本、分块状态、结构化候选、评分、选择和 token 用量，并 SHALL 在应用重启后从最后一个完整阶段恢复。

#### Scenario: 排名阶段前应用退出
- **WHEN** 所有分块已经完成但全局评分尚未发布时应用退出
- **THEN** 重启后系统复用已验证分块候选并继续全局评分，不重新发送全部转写

#### Scenario: 相同分析指纹再次运行
- **WHEN** 转写、输入顺序、标签、Skills、模型、Prompt 版本和参数均未变化且已有完整结果
- **THEN** 系统复用结构化结果并显示缓存命中，不再次调用 DeepSeek

### Requirement: 展示和选择精彩候选
系统 SHALL 按分数或源时间提供不受数量上限限制、按合格阈值筛选且分页的候选导航，并 SHALL 把当前候选标题、时间范围、总分、维度、理由、标签和来源视频与其稳定 ASR 句段共同展示；系统 SHALL 支持跨视频播放器定位、候选时间范围预览以及通过“加入待切片”开关即时持久化选择。系统 MUST NOT 为展示候选而复制转写产物或修改原始媒体。

#### Scenario: 用户点击精彩候选
- **WHEN** 候选对应视频具有可靠预览和时间映射
- **THEN** 播放器切换到来源视频，ASR 视图定位并标记候选引用句段，播放器跳转到候选开始时间且不修改原始媒体

#### Scenario: 用户预览精彩范围
- **WHEN** 用户启动当前候选片段预览
- **THEN** 播放器只在候选开始和结束时间之间播放，结束后暂停且不执行 FFmpeg

#### Scenario: 用户切换待切片选择
- **WHEN** 用户开启或关闭当前候选的“加入待切片”开关
- **THEN** 系统立即持久化完整选择集合供剪辑工程使用，并返回后端确认状态而不自动生成成品视频

#### Scenario: 候选包含大量句段
- **WHEN** 当前运行包含多个长候选、候选跨越大量 ASR 句段或合格候选数量很大
- **THEN** 界面通过分页导航和单一当前候选详情保持选择可操作，不按固定数量截断合格候选

#### Scenario: 候选引用重叠句段
- **WHEN** 多个已发布候选引用同一个稳定句段
- **THEN** 界面复用同一份不可变转写并只强化当前候选，候选选择和评分保持彼此独立

### Requirement: 允许已授权智能任务自动启动精彩运行
系统 SHALL 允许 Rust 编排器为已完成 ASR 且输入指纹一致的智能成片子项目自动创建精彩运行，但 MUST 在创建前验证当前任务授权、客户端激活、Provider、模型、文本发送范围和批次代次。该例外 MUST 只作用于关联智能任务；普通 AI 项目继续要求用户显式授权，并且 Agent 的工具权限、结构校验、冻结 Skills 和评分阈值 MUST 与手动运行一致。

#### Scenario: 自动启动本地任务精彩
- **WHEN** 已授权本地智能任务完成 ASR，激活和 Provider 门禁有效且不存在相同运行指纹的完整结果
- **THEN** Rust 编排器创建精彩运行、冻结 Skills 与阈值并进入既有分块流程

#### Scenario: 复用相同精彩结果
- **WHEN** 智能任务对应的转写、输入、标签、Skills、模型、Prompt 版本和参数指纹已有完整精彩结果
- **THEN** 系统复用该结果并将阶段标记为缓存命中，不再次调用 Provider

#### Scenario: 普通项目完成 ASR
- **WHEN** 一个未关联智能任务的普通 AI 项目完成 ASR
- **THEN** 系统不得自动创建精彩运行，继续展示发送预估并等待用户显式授权

### Requirement: 为直播分片携带有限相邻上下文
系统 SHALL 允许智能直播批次在候选发现阶段携带前一完整批次末尾的有界稳定句段作为只读上下文，并 MUST 以来源视频、稳定句段和规范化会话时间标记上下文边界。全局评分和候选发布仍 MUST 只引用本地可验证的真实句段；系统 MUST NOT 读取活动分片、把上下文复制成新 ASR 产物或让单个物理候选跨越未登记媒体。

#### Scenario: 分析相邻完整分片
- **WHEN** 新直播批次存在已完成的直接前序批次
- **THEN** 系统按冻结预算附带前序末尾句段、明确来源边界并将当前完整分片作为主要分析输入

#### Scenario: 没有前序完整批次
- **WHEN** 当前批次是首个批次或前序批次不可用
- **THEN** 系统只分析当前冻结转写且不等待或读取正在写入的媒体

#### Scenario: 候选引用上下文和当前句段
- **WHEN** Agent 返回一个跨相邻完整分片边界的候选建议
- **THEN** Rust 只在所有引用句段和真实源内区间均可验证时，将其交给智能任务候选账本形成多来源逻辑候选

### Requirement: 向智能任务发布可合并的候选结果
系统 SHALL 在每个智能直播批次完成本地去重和全局评分后，将全部合法候选连同批次 ID、视频库 ID、稳定句段、真实源内时间、规范化会话时间、评分和阈值快照发布给智能任务候选账本。精彩运行自身 MUST 保持不可变；跨批次合并、自动入选和草稿更新 MUST 由父工作流完成，不得回写或删除原运行候选。

#### Scenario: 批次发布评分候选
- **WHEN** 一个直播子项目完成精彩全局评分
- **THEN** 系统原子发布该运行结果，并向父任务提交具有真实来源映射的候选集合

#### Scenario: 父任务合并重复候选
- **WHEN** 父任务判定新候选与历史候选属于同一逻辑精彩
- **THEN** 原精彩运行和两个候选记录保持不变，父任务只更新合并账本及其草稿选择

#### Scenario: 单个批次精彩失败
- **WHEN** 某直播批次的分块、校验或评分失败
- **THEN** 系统保留其他批次的已发布候选和父任务草稿，并允许只重试该批次的失败阶段
