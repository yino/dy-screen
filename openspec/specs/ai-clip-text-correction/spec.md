# AI 剪辑文本纠错规格

## Purpose

定义剪辑工程的一键文本纠错选择范围、本地 Provider 调用、结构化校验、原子提交以及脱敏进度与审计边界。
## Requirements
### Requirement: 从当前工程选择可纠错字幕
系统 SHALL 在用户显式启动一键文本纠错，或当前工程由已授权智能成片任务以自动化所有权创建并到达纠错阶段后，由本地 Rust 按工程片段顺序、源内时间和稳定字幕 ID 读取当前工程字幕。系统 SHALL 只选择当前文本等于不可变 ASR 原文且未隐藏的工程字幕副本，MUST 跳过已经人工修改或隐藏的字幕，MUST NOT 修改原始 ASR、其他工程、字幕时间或片段结构。智能任务自动纠错 MUST 在当前草稿尚未人工编辑、未导出且工程版本与阶段快照一致时才可启动。

#### Scenario: 工程包含未修改字幕
- **WHEN** 用户对包含可见且未经人工修改字幕的工程启动一键文本纠错
- **THEN** 系统按稳定顺序建立文本数组和本地字幕 ID 映射，并显示将处理的记录数量

#### Scenario: 智能任务自动选择工程字幕
- **WHEN** 已授权智能任务创建自动化拥有的合辑工程并进入纠错阶段
- **THEN** 系统只从入选片段复制出的当前工程字幕建立纠错输入，不发送未入选文本或原始 ASR 存储中的其他句段

#### Scenario: 字幕已经人工修改
- **WHEN** 工程字幕的当前文本与其 ASR 原文不同
- **THEN** 系统跳过该字幕、保留人工文案并把它计入跳过数量

#### Scenario: 字幕已隐藏
- **WHEN** 工程字幕被用户隐藏
- **THEN** 系统不把该字幕发送给 LLM，也不改变其文本或隐藏状态

#### Scenario: 自动纠错前工程已被编辑
- **WHEN** 智能任务准备自动纠错但工程版本已变化或草稿已转为用户拥有
- **THEN** 系统不得创建自动纠错运行，保留工程并把该阶段标记为需要审阅或下一代草稿处理

#### Scenario: 没有可纠错字幕
- **WHEN** 当前工程所有字幕均已人工修改、已隐藏或不存在
- **THEN** 系统不调用 LLM、不递增工程版本并提示没有可处理的字幕

### Requirement: 通过本地 Rust 分批调用现有 LLM Provider
系统 SHALL 由本地 Tauri/Rust 层复用已配置的 DeepSeek Provider，将完整字幕边界上的有界文本数组分批发送给受限纠错角色。提示词 MUST 只允许修正错别字、同音错词、明显 ASR 识别错误和标点，MUST 要求保持原意、语气、专名、数字、数组长度和顺序；系统 MUST NOT 发送视频、音频、本地路径、激活信息、API Key 或其他数据库内容。

#### Scenario: 文本超过单次预算
- **WHEN** 可纠错字幕超过当前字符或 token 预算
- **THEN** Rust 在字幕边界生成多个批次、依次调用同一 Provider，并保持全局字幕映射稳定

#### Scenario: 用户启动纠错
- **WHEN** 已激活用户在已配置 DeepSeek Key 后点击一键文本纠错
- **THEN** 本地 Rust 发起受限请求并发布批次进度，WebView 不接触 Provider 凭据或原始响应

#### Scenario: 敏感字段不进入请求
- **WHEN** Rust 构建任一纠错批次
- **THEN** 请求业务数据只包含必要文本数组和受控指令，不包含媒体、路径、凭据或任意前端附加字段

### Requirement: 严格校验结构化纠错结果
系统 SHALL 要求每个批次返回由 `index` 和非空 `text` 组成的结构化纠错数组，并 SHALL 在本地校验结果与输入严格等长、索引唯一且完整覆盖原顺序。每条文本 MUST 通过现有控制字符、空白合并、非空和最多 500 个 Unicode 字素簇校验；任一批次缺项、重复、越界、无法解析或包含非法文本时，本次运行 MUST 失败且不得修改工程。

#### Scenario: 返回合法纠错数组
- **WHEN** LLM 为批次中每个输入索引返回一条合法文本
- **THEN** Rust 按本地索引映射结果并继续处理剩余批次或进入最终提交

#### Scenario: 返回数组长度或顺序错误
- **WHEN** LLM 响应缺少索引、重复索引、包含越界索引或未覆盖全部输入
- **THEN** Rust 拒绝整个运行、返回可重试的结构错误并保持工程不变

#### Scenario: 返回非法字幕文本
- **WHEN** 任一纠错文本为空、只含空白、包含不允许的控制字符或超过 500 个 Unicode 字素簇
- **THEN** Rust 拒绝整个运行且不递增工程版本

### Requirement: 原子提交纠错并处理并发冲突
系统 SHALL 在运行开始时冻结工程版本，并 SHALL 只在所有批次成功且响应通过校验后，在一个 SQLite 事务中重新校验工程归属、版本、导出状态和目标字幕当前值，再更新实际变化的字幕并至多递增一次工程版本。Provider 失败、取消、非法响应、导出竞态或版本冲突 MUST 保持全部工程字幕不变。

#### Scenario: 全部批次成功
- **WHEN** 所有纠错批次合法且工程版本和目标字幕仍与运行快照一致
- **THEN** 系统在一个事务中保存全部变化、递增一次工程版本并返回最新字幕计划和处理统计

#### Scenario: 部分批次失败
- **WHEN** 前序批次成功但后续批次超时、失败或返回非法结构
- **THEN** 系统不保存任何批次结果，工程版本和字幕保持运行前状态

#### Scenario: 运行期间发生人工编辑
- **WHEN** 用户或其他窗口在纠错运行期间修改工程导致版本变化
- **THEN** 最终提交报告版本冲突、重新加载最新工程且不覆盖新编辑

#### Scenario: 用户取消纠错
- **WHEN** 用户在运行完成前取消
- **THEN** 系统停止后续批次、忽略迟到响应并且不保存任何纠错结果

### Requirement: 提供脱敏进度和审计
系统 SHALL 为一键文本纠错展示准备、纠错、校验、保存、完成、取消和失败状态，并 SHALL 返回处理、修改、未变化、跳过人工修改和跳过隐藏字幕数量。系统 SHALL 只保存模型、prompt 版本、输入指纹、计数、token 用量、耗时和脱敏错误分类，MUST NOT 保存完整字幕副本、API Key、完整 Prompt、原始响应正文或隐藏推理。

#### Scenario: 纠错运行成功
- **WHEN** 原子提交完成
- **THEN** 工作台刷新字幕轨和预览计划，并显示实际修改与跳过数量

#### Scenario: 纠错运行失败
- **WHEN** Provider、校验或提交阶段失败
- **THEN** 工作台显示可重试的中文原因，审计只记录脱敏分类且不泄露字幕正文或凭据

### Requirement: 将智能纠错尝试关联到父任务代次
系统 SHALL 为编排器创建的纠错运行保存智能任务 ID、草稿代次、工程版本、阶段尝试代次和输入指纹，并 SHALL 复用既有分批调用、结构化校验和原子提交规则。只有全部结果合法且任务代次、草稿所有权及工程版本仍匹配时，系统才可提交；自动纠错失败、取消或冲突 MUST 保持整个工程不变，并允许智能任务只重试纠错阶段。

#### Scenario: 自动纠错成功提交
- **WHEN** 所有批次通过校验且智能任务、草稿所有权和工程版本仍与运行快照一致
- **THEN** 系统在一个事务中保存实际变化、至多递增一次工程版本，并把纠错统计返回父任务

#### Scenario: 新草稿代次已经产生
- **WHEN** 旧草稿纠错响应在父任务已切换到新草稿代次后到达
- **THEN** 系统拒绝提交旧响应，不改变任一草稿并将旧尝试收敛为过期终态

#### Scenario: 自动纠错 Provider 失败
- **WHEN** 任一批次超时、失败或返回非法结构
- **THEN** 系统不保存部分结果，父任务保留 ASR、精彩和工程并提供纠错阶段重试
